## 1. 方向

- **日記頁是單天頁**（「往回看」：寫和記）；**任務頁是往後看**（排和做）：時間軸、不限時間、1 天／3 天／週都在任務頁的「今天」分頁（`DayPane`）。
  曾試過把三者放在同一頁的「今天」頁，已拿掉（本文最後一節）。
- **時間軸只留「要做／做了的事」＝任務（有時間的，完成的也留）與專注**（業主 2026-10-31）。修改、建立、快速記錄、AI 執行不上時間軸，到「歷史」看。
  篩選只寫一份：`@onden/markdown` 的 `onTimeline`／`TIMELINE_KINDS`，`DayPane`、`WeekBoard` 在畫面層套用；
  `useDayItems`、後端 lens 照舊交出全部來源（日記頁「這天發生的」用）。
- **範圍**：電腦可切 1 天／3 天／週；手機只有 1 天（3 天／週太擠，2026-11-09）。
- **專注**：任務可以「專注」（番茄鐘）。結束時問「做了什麼」，那句話可以寫進日記，也可以記在任務底下。
- 「收工」與「規劃今天」已移除（業主 2026-11-06）：沒做完的留在任務頁「今天」，「這天發生的」列出那天的事。

這份文件管的是上面每一項背後的資料：任務要住在哪裡、時間要寫在哪裡、完成與專注要記什麼，以及各畫面怎麼分工。

## 2. 資料模型

### 2.1 任務住進筆記

任務仍然是一個隱藏的內容節點（模組標籤 `#task`＋`_task_*` 屬性），但**從現在起每個任務都是某篇筆記裡的一行**：

```
- [ ] 15:00–16:00 跟組員討論 {task} ^t-1a2b3c4d5e6f
```

- **快速新增**（`+` 與記一筆）寫一行到**今天的日記**；日記模組關著時寫進空間裡的「任務」筆記；
  輸入裡有 `@筆記名稱` 就寫進那一篇（找不到那篇就不新增，保留輸入並說明）。
- **每個空間各一篇「任務」筆記**（2026-10-31 業主決定；日記與 RSS 仍只在個人空間）：id 由「空間＋任務」推導（`tasksNoteId`，
  與 migration 147 同一條規則），**用到才建**（第一件任務放進去時，`dayNotes.openTasksNote(spaceId)`），共享空間的建在該空間最上層。
  快速新增的 App 內表單（`QuickAddSheet`）在有兩個以上可寫空間時多一列「放在」（建立選單的 `PlacePicker`）：預設空間依序是
  目前打開的筆記所在空間、上次選的空間（帳號偏好）、個人空間；只選空間沒選筆記時，個人空間照上面的規則，**共享空間寫進它自己的「任務」筆記**。
  `@筆記名稱` 仍以 @ 指定的為準。「記一筆」（`QuickCapture`）這次沒加「放在」，維持寫個人空間。
  側欄不列任何空間的「任務」筆記（`sidebarTidy`，以推導 id 判斷）；任務頁照常列出所有看得到的任務，有兩個以上空間時多一個「依空間篩選」。
- 做法是 `POST /api/tasks` 多一個 `into: { note_id }`：伺服器先建任務，再在**同一個交易**裡用既有的 `placeTask`
  把它寫成那篇的一行；筆記不存在或不能寫，整個回滾，不會留下沒人要的獨立任務。重試沿用原來的 `id`，離線佇列照舊。
- **今天的日記不存在**：前端用既有的 `dayNotes.openToday()` 建（id 由「個人空間＋日期」推導，兩台裝置同一天離線建也只留一篇）。
  伺服器端只有一處需要建日記（專注結束時寫進日記，見 2.5），用**同一條規則**（`services/dayNotes.ts`，
  命名空間與 id 的組法在 `@onden/markdown` 的 `sharedContract.ts`：`DAY_NOTE_NAMESPACE`、`dayNoteIdName`）。
- 沒有筆記的任務（`parent_id` 為空）**仍然是合法的資料**——匯入、備份還原與舊版離線佇列還會產生它——但不再有任何畫面建立它。
  （「整篇筆記當任務」已於 2026-11-12 整個移除，見 [任務模組](tasks-module.md)。）

### 2.2 時間寫在那一行

行首的 `15:00–16:00`（也接受 `15:00-16:00`、只有開始 `15:00`）是任務的時間：

| 屬性 | 值 | 說明 |
| --- | --- | --- |
| `_task_time` | `HH:MM` | 開始時間 |
| `_task_until` | `HH:MM`，晚於開始 | 結束時間；沒有開始就沒有結束 |

- **文字是依據**：存筆記時 `syncBlockTasks` 讀行首的時間更新屬性（標題是時間後面的字）；
  在任務頁改時間，則走既有的 `syncTaskLine` 路徑改寫那一行（和打勾同一條路，同一次儲存）。
  結束不晚於開始時，結束被丟掉；清掉開始時間也清掉結束。
- 解析只有一份：`@onden/markdown` 的 `taskTime.ts`（`parseLineTime`／`withLineTime`／`formatLineTime`），
  它用的時鐘樣式（`CLOCK_24H_SOURCE`）就是 `taskParse` 讀「15:00」用的那一個。
- 任務 API 的 `TaskRow` 多了 `time`、`until`（以及下面的 `done_at`、`block_ref`）；任務頁每一列顯示時間。
- **取代**：快速新增打的時間，以前變成 `_task_remind_at`（卻從來沒有被觸發）；現在變成這一行的時間。
  `_task_remind_at` 只在明確說「提醒我」或在任務頁設定時才有。

### 2.3 完成時間


`_task_done_at`（ISO 時間）：狀態**變成** done 時寫入，離開 done 時清掉；已經是 done 再設 done 不改它。
不論從筆記打勾、任務頁、匯入或 AI 寫的任務，都走 `updateTask`／`createTaskNode`，所以都有。

- 匯出的 ✅ 日期改用它；做完的時間沒記下的舊任務才退回最後修改日（`exportTasks.ts`）。
  匯入 Obsidian 清單時 ✅ 的日子讀回成當天正午（UTC）的 `_task_done_at`，沒有 ✅ 的完成任務記為匯入當下。
- 還原備份時，整篇獨立任務保留備份裡的 `_task_done_at`；筆記裡的任務行由筆記內文重建，完成時間記為重建當下（已知限制）。

### 2.4 打開筆記捲到那一行

`TaskRow.block_ref` 是任務那一行的 `^id`（沒有行則為空）。任務頁的「打開筆記」把它交給 `lib/noteReveal.ts`，
筆記一打開、內文到了就捲到那一行（編輯與預覽都行）；十秒內沒有對上就作廢，不會在之後手動打開時突然跳。

### 2.5 專注紀錄

**選擇：一張表（`focus_sessions`，migration 148）加上同交易的領域事件**，而不是只用 `domain_events`。

| 欄位 | 說明 |
| --- | --- |
| `id` | 前端產生，重送同一個 id 回同一筆 |
| `actor_id` | 紀錄是這個人的 |
| `task_id` | 可空；任務被刪紀錄還在 |
| `started_at`／`ended_at` | `ended_at` 空代表還在跑；本機寫入每人同時最多一筆在跑（migration 236 起是觸發器 `focus_sessions_one_running`，以前是唯一索引）；兩台各開一筆、交換之後兩筆都留（同步規則 4.4），讀取把較晚的那筆當成在跑的 |
| `note` | 結束時的一句話（≤500 字） |

理由：「列出某天」「忘了停可以事後改時間」是依時間範圍查、再修改的資料；只用事件就得每次重播並找「某筆的最新狀態」，
而事件在實驗性的修剪下可能被清掉。所以**狀態是表，事實是事件**：`FOCUS_STARTED`／`FOCUS_ENDED`／`FOCUS_EDITED`，
與表的寫入同一個交易（`mutate`）。事件只帶任務與時間，**不帶那句話**——事件的非筆記目標只有擁有者與本人看得到，
但一句話屬於日記的範圍，不該出現在事件紀錄。**沒有復原**：改錯了就是再改一次（這是紀錄不是內容）。

API（都在 tasks 模組的 `/api/tasks/focus` 之下，模組關閉時寫入回 409）：

| | |
| --- | --- |
| `POST /api/tasks/focus` | 開始。`{ id?, task_id?, started_at? }`；已有在跑的回 409 `focus_running`；`started_at` 不可在未來 |
| `POST /api/tasks/focus/:id/end` | 結束。`{ ended_at?, note?, to_diary?, to_task? }`；結束已結束的紀錄回原樣（重送） |
| `PATCH /api/tasks/focus/:id` | 修改開始／結束／一句話／任務；結束不早於開始、不超過 24 小時、不在未來 |
| `GET /api/tasks/focus?day=` | 那天（工作區時區）**開始**的紀錄，加上還在跑的那一筆。臨時工作階段讀開啟它的人的紀錄，但綁在它讀不到的任務上的紀錄不給（任務 id 與那句話都不給），沒綁任務的紀錄只給時間與長度、那句話不給；它不能寫（`requirePerson`） |

- `to_diary`：把 `> 09:30–10:25 專注〈任務〉：一句話` 寫成**開始那天**個人空間日記的一行引文（日記不存在而日記模組開著時才建）。
  `to_task`：把同一行加在任務本文底下。兩者各自嘗試，結果在回應的 `written: { diary, task }`；
  寫不進去（沒有權限、沒有日記）**不會**讓結束失敗。
- 只做資料與 API；計時器畫面下一批。


## 3. Migration 147：獨立任務搬進筆記

- **搬哪裡**：有（有效的）`_task_when` 的，進**那一天的日記**；沒有日期的，進同一空間的「任務」筆記。
  「那天的日記」是該空間裡標題（或 slug）等於日期的現有筆記；沒有就建，id 用 `uuid v5(命名空間, "<空間>/<日期>")`，
  和 App 推導的一樣，之後 App 在那天開日記會找到它（「任務」筆記同理，名稱是「任務」）。
- **空間**：日記建在**任務原本的空間**。個人空間的任務進本人的日記（Today 按鈕找得到）；
  共享空間的任務進那個共享空間裡的日記——它是一篇普通筆記，Today 按鈕（只看個人空間）不會開它。
  不跨空間，所以不會有人突然看到不該看的任務，也不會有人突然看不到。
- **保留**：任務節點的 id 與所有屬性都不變，只有 `parent_id` 改；該行附帶的 block node 已連到任務
  （`block_nodes.task_id`）並帶任務標籤，所以下次存那篇筆記不會多生一個任務。
  有時間的（`_task_time`）寫成行首時間；完成的寫成 `[x]`；其他狀態（進行中、等待、取消）維持 `[ ]`，狀態屬性不動。
- **留在原地（仍是獨立任務，仍列在任務頁）**：垃圾桶裡的任務；標題含 `{ } # ^`、換行，或以 `15:00` 之類時間開頭的任務
  （寫成一行會在下次存檔時被改名或貼上標籤）。數量在 migration 的 NOTICE 裡。
- **事件**：每篇被改的筆記與每個被搬的任務都有一筆 `migration:147` 的事件，讓開著的裝置下次同步看到；事件沒有 inverse（不提供復原）。
- **可重跑**：只選「現在還是獨立的活任務」，第二次只會再略過留下的那些。
  整合測試 `tasksIntoNotesMigration.integration.test.ts` 檢查前後任務筆數一致、屬性逐一相同、
  新舊日記各自對、再存一次筆記沒有第二個任務、重跑沒有變化。還原演練聲明 `notes_live`（新建日記）與 `note-bodies`（被附加的內文）。

## 4. 「這一天」項目的規則

時間軸、「這天發生的」與週檢視讀同一種 `DayItem`（`@onden/markdown` 的 `dayItems.ts`；各模組經註冊表的 `dayItems` 交出自己的來源，`modules/index` 合併排序）。

1. **連續修改合成一段**：同一篇筆記在 30 分鐘內（`EDIT_RUN_GAP_MINUTES`）的連續編輯合成一個項目（`mergeEditRuns`，後端 `services/dayLens.ts` 用它），不是每次存檔一列。
2. **不做忙碌罪惡感的數字**：不顯示「今天只做了 N 件」「專注 N 分鐘低於平均」「連續 N 天」這類數字、排名或進度條；空的一天就是空的一天。
   專注的總長度可以在紀錄本身看到，但不拿來評分。（這是設計決定，不是程式強制的。）
3. **來源**：完成（`_task_done_at`）、專注（`focus_sessions`）、筆記建立／編輯（事件）。未來的部分來自有時間的任務（`_task_time`／`_task_until`），
   沒有結束時間的顯示預設長度（`POINT_ITEM_MINUTES`，30 分鐘）。
4. **時間軸只顯示任務與專注**（`onTimeline`）；修改／建立／AI 執行只在「這天發生的」與歷史。

## 5. 提醒與它的限制

提醒的時刻（規則只有一份，`@onden/markdown` 的 `taskReminder`，App 與伺服器都用它）：任務的 `_task_remind_at`，沒有就用**開始時間**
（`_task_when` ＋ `_task_time`，以工作區時區的牆上時間算）。未完成（待辦／進行中，不含等待中）、未刪除、任務模組開著才提醒。
時刻到了就響一次；錯過的**只補 12 小時內**的，更早的只在「逾期」裡看得到。同一任務同一個時刻只響一次。

兩條路送同一個提醒：

1. **App 開著**（`useDueSoonNotifications`）：每 15 秒用手上的待辦清單核對，到了就用服務工作者顯示通知。已響的記在這台裝置。需要先在任務頁開啟通知。
2. **App 沒開、手機鎖屏、分頁被凍結**：伺服器每分鐘（`modules/tasks/pushReminders.ts`）找「時刻已到、還沒送過」的任務，用 Web Push 送到
   有權讀這個任務的人、所有已開啟鎖屏提醒的裝置。Onden 的任務沒有「擁有者」或「指派對象」，所以對象就是**能讀到這個任務的成員**（與待辦清單給誰看相同，
   逐人用 `readableAmong` 判斷，撤權後就不再收到）。
   - 去重：`push_reminder_sent(task_id, moment)` 以 insert 當認領，重啟、多個 backend 行程都不會重送；該任務沒人可通知時**不認領**，之後才加入的裝置仍收得到。
     送出前先認領（最多一次）；若所有裝置都遇到可能恢復的失敗（網路、5xx），把認領還回去，下一分鐘重試，直到 12 小時視窗結束。
   - 多行程：這個週期任務只在拿到 advisory lock 的那個行程跑（`backgroundJobs` 的 `exclusive`），認領的 insert 是第二道保險。
   - 推播服務回 404／410＝裝置已不在，刪掉該訂閱。伺服器停機後恢復，只補 12 小時內的。
   - 內容只有任務標題與提醒時間，不含筆記內文；點通知開任務所在的筆記（沒有筆記就開任務頁）。
   - 需要部署時設 `VAPID_PUBLIC_KEY`／`VAPID_PRIVATE_KEY`／`VAPID_SUBJECT`（見 [deploy.md](../agents/deploy.md)）；沒設，整個功能不出現。

**前景與背景不重複**：App 內通知與推播的 `tag` 是同一個字串 `remind:<任務 id>:<提醒時刻>`，瀏覽器對同 tag 的通知是「取代」而不是「再加一則」，
所以不論哪一邊先響，螢幕上只會有一則。選 tag 而不是「App 開著就叫伺服器別送」，是因為伺服器無從得知哪台裝置的 App 正開著，
而且 tag 在兩邊各自運作也不必互相通訊。

**開啟與關閉**：任務頁的「到期時提醒我」同一次點擊要到通知權限，並在伺服器有提供時一併訂閱 Web Push；設定 › 日期與時間有
「鎖屏提醒」一列，顯示**這台裝置**是否會收到，並可關閉（每台裝置各自一列）。登出時這台裝置會先取消訂閱。畫面不顯示裝置位址或金鑰。

**限制**：
- iPhone／iPad 要先把 Onden **加到主畫面**，從主畫面的 App 開啟提醒才收得到推播（Safari 分頁沒有推播功能）。
- Android 的 **Brave 預設關閉 Google 推播服務**：到 Brave 設定開「使用 Google 服務進行推播通知」；訂閱失敗且偵測到 Brave 時，畫面會這樣提示。
- 推播服務、手機省電模式與勿擾設定都可能延遲或吞掉通知；伺服器每分鐘核對一次，最多晚約一分鐘。
- 通知的標題是任務標題、內文是時間；App 內通知則是「提醒：標題」「在『筆記』裡」，同 tag 時後到的取代先到的。
- 範圍略有不同：App 開著時只看待辦清單裡「逾期」「今天」兩區的任務；伺服器看所有未完成且設了提醒（或開始時間）的任務，所以提前一天設的提醒也會在鎖屏響。
- 提醒不是保證：不要把會出事的事只靠它。


## 6. 日記頁（`?view=daily`，`modules/daily/JournalScreen` ＋ `day/DayPage`）

資料模型、API、任務寫入路徑、快速捕捉、日記筆記建立規則都不受畫面分工影響。日記往回看：

- 一次只看一天。那天的日記內文用 `NotePreview` **整篇渲染**（唯讀，`day/DayNoteBody`）；點內文（空白處或文字）跳到那天的日記筆記（`onOpenNode`）；
  內文裡的連結、按鈕照常，只去連結目標，不觸發開日記。右上角的「開啟」按鈕是同一件事的鍵盤入口。
- 沒有日記（或內容空白）的日子顯示「寫點什麼…」：沒有筆記時走 `dayNotes.openDay(date)` 建立並打開（同一個入口，連點不會重複建）；已有空白筆記就直接打開它。
- 日期導覽：標題是按鈕，點了展開月曆；今天標題旁小字「今天」，其他天有「回到今天」；上方週列（週一開頭，有東西的日子打點）＋可展開月曆（`DayStrip`）；有東西時顯示「去年今天」卡（`LastYearCard`）。
- **選中的日子記在 `daily/pickedDay.ts`**（只在本次使用中、只對「那一個今天」有效）：開筆記會離開這一頁，返回時回到同一天，不跳回今天；過了午夜就從新的今天開始。
- 內文下面（`day/DaySections`）沒有內容的區不顯示，全空時一行「這天沒有任務、記錄，也還沒有筆記提到它。」：
  1. **到任務頁的一行**（任務模組開著才有）：今天是「還有 N 件要做」，之後的日子是「排了 N 件」，過去的日子不顯示；整列是按鈕，去任務頁（`ModuleScreenProps.onOpenView("tasks")`）。日記頁不列待辦、不打勾。
  2. **這天發生的**：那天日記的快速記錄（`dayChildren`）、那天完成的任務（「完成了 …」，由完成時間，`finishedTasks.ts`；已寫在日記本文裡的不重複列）、
     當天「建立」「修改」的筆記（`GET /api/day/:date/lens` 的 `created`／`edited`，`useDayLens`；不列日記本身、不重複列快速記錄；先 5 篇，其餘「還有 N 篇」可展開）。離線或沒權限時沒有最後那一項。
  3. **提到這天的**：連到那天日記筆記的反向連結（`noteNeighborhood` 的 backlinks，和筆記頁「被 N 篇筆記提到」同一份），顯示標題與提到那句的片段（`BacklinkSnippetView`）。不做內文日期辨識。
- 日記頁沒有時間軸（業主 2026-11-09：任務往後看、日記往回看）。

## 7. 在時間軸上排時間

時間軸只是任務行的另一種看法：排時間＝改寫那一行行首的時間（2.2），沒有另一份資料。
入口都落到同一個 `TimelinePlanner`（`modules/daily/day/`），它只決定「哪一段」與「放什麼」：

| 入口 | 位置怎麼來 | 放什麼 |
| --- | --- | --- |
| 點時間軸的空白處（電腦、手機） | 點的位置，對齊 15 分鐘，長 30 分鐘 | 任務模組的快速新增（見下），或點列出的現有任務 |
| 時間軸上方「＋ 新增」（鍵盤） | 現在之後的下一個 15 分鐘；看別天則 09:00 | 同上 |
| 電腦：把還沒排時間的任務拖進時間軸（任務頁「今天」的列） | 放開的位置，對齊 15 分鐘，長 30 分鐘；拖曳時顯示預覽與時間 | 那一件 |
| 手機：長按（`longPressDraw.ts` 的 `DRAW_HOLD_MS` 450 ms）再上下拖 | 按下與放開的位置各對齊 15 分鐘（拉不到一格視同點一下） | 放開後開同一個輸入（手機是底部面板） |

- **位置換算**在 `timelineSlots.ts`（純函式）：從 `dayWindow` 的起點算分鐘，所以一天從 04:00 開始或遇日光節約時間（23／25 小時）都對得上。
  行首時間不能跨午夜：結束若在時鐘上不晚於開始（含 24:00），就只寫開始。
- **長按**：`longPressDraw.ts` 是狀態機（按住未滿＝一般點按或捲動；移動超過 `HOLD_SLOP`＝捲動，不再畫；滿 `DRAW_HOLD_MS`＝進入畫時段），
  `useLongPressDraw.ts` 接 pointer events（觸控與手寫筆；滑鼠照常點）。進入畫時段後用非 passive 的 `touchmove` 擋捲動、
  擋 `contextmenu`，並用 `touchHold` 的 `vibrate()` 震動一下、`swallowNextClick()` 吃掉放手後的那一下 click。
- **新增**：時段裡放的是任務模組的 `QuickAddPanel`（與中間＋的「任務」、命令面板的「新增任務」同一個輸入，不再有時間軸自己的表單）：
  帶入時段的日期、開始與結束，加「多長」（15 分／30 分／1 小時／2 小時）與開始、結束時間欄，畫錯的長時段按一下就改回。
  輸入框裡寫的日期或時間（「3點到5點」）取代預填，只寫長度（「30分鐘」）則從預填的開始算結束（`quickAddTask.ts` 的 `slotWithReading`）。
  寫入仍是 `createQuickTask`（多收 `until`），任務住進今天的日記或「任務」筆記（2.1）；一次新增就關掉時段。
- **長按門檻**：450 ms（比列表長按的 300 ms 長）。時間軸平常是在捲的，手指停一下再捲動，300 ms 就會畫出一段沒人要的時段（例如 04:00–08:15）；
  移動容差仍是 `HOLD_SLOP`（10 px），捲動在門檻前就取消。
- **排既有任務**：輸入框打字時列出名稱相符的未完成任務（逾期、今天、接下來、隨時、某天，來自 store 的任務，不另開 API），沒打字時列還沒排時間的幾筆；點一下走 `dayTaskWrites.scheduleTaskAt` → `taskWriter.patch({ time, until })`，後端 `updateTask` 經 `syncTaskLine` 改寫那一行；
  任務原本在別天或在「之後」，就一併設那天並清掉「之後」。每次排完顯示「復原」，復原把 `time`、`until`、`when_date`、`someday` 改回原值。
- 已完成的任務不能拖也不能被排；專注紀錄與其他非任務項目不是拖曳來源。任務模組關閉時沒有「＋ 新增」、點空白與拖曳都不作用。
- **拖動已排好的區塊、拉下緣**（`timelineDrag.ts` 純計算、`useBlockDrag.ts` 手勢、`lib/pointerDragSession.ts` 的 `trackPointerDrag` 接指標）：
  - 只有「未完成、有時間、讀者可寫（`taskRefs` 的 `writable`）」的任務區塊能拖；已完成（時間是紀錄）、專注紀錄、外部行事曆、唯讀的沒有 `is-movable`、拉把與抓取游標。
  - 電腦：按住區塊拖（`DRAG_SLOP_PX` 後才算拖，否則仍是點開）；滑過區塊下緣出現拉把。手機：長按（`trackPointerDrag` 的 `hold`，走 `touchHold` 的同一個長按手勢）後拖；
    未滿長按就移動＝捲動，不拖；長按後原地放開＝選取，下緣的拉把變成手指夠大的目標（拉把 `touch-action: none`，可直接拉）。
  - 拖動中只預覽（區塊畫在新位置、顯示新時間，對齊 15 分鐘、不出當天、結束不跨午夜：會跨就往前滑，不削掉結束），靠近上下邊自動捲動（`createEdgeAutoScroll`）；Esc 取消（`useEscapeKey`）。放開才寫一次（`scheduleTaskAt`，同一個「復原」），被拒絕就回原位並照 `writeErrors` 白話告知。
  - 拉下緣最短一格（15 分鐘）、最長到當天結束前一格；沒有結束時間的拉了就補上。起點不動。
  - 鍵盤：Alt＋↑↓ 移動 15 分鐘、Alt＋Shift＋↑↓ 改長度（`lib/shortcuts.ts` 沒有這組）；連按合成一次寫入（最後一鍵後 `KEY_COMMIT_MS`），每一步用 `role="status"` 朗讀新時間。
  - 重疊：照既有並排，不推開別人。
  - 3 天／週（`WeekBoard`）沒有小時格，卡片拖到別天的欄只改日期（時間留著，任務行留在原來的筆記；`moveTaskToDay`，有「復原」）；手機長按卡片後拖到別欄，用 `closestAtPoint` 找欄。
- 瀏覽器版實測（`packages/frontend/e2e/browser-app/timelineDrag.mjs`，桌面 Chromium；手機是 Pixel 5 的 viewport 與觸控模擬，不是真機）：截圖在 `docs/research/screenshots/timeline-drag/`。


## 8. 任務頁「今天與接下來」

任務往後看（排和做）；「⋯ 不直覺，能直接放的就直接放」（業主 2026-11-09）。


- **可以排進今天的**（`UnscheduledStrip` ＋ `lib/tasks/todayCandidates`）：今天分頁最上面一張卡片，取代「前幾天留下的」與
  「都留在今天」。內容是**過期的**（`when_date` 已過、還沒做）加**截止在明天以前（含今天、明天、已過）而今天時間軸上還沒有位置的**；
  過期的在前（越久越前），再按截止日。最多 3 列，超過時標題右邊「看全部 ›」在同一張卡片內展開；一件也沒有就不畫這張卡。
  每列的第二行沿用 `TaskRow` 的標記（`leftOverLabel` 的「昨天留下的」、`deadlineLabel`）與 `hostNoteLabel`。
  過期列右邊兩顆看得到的按鈕：「排到今天」（`planTodayChanges`：`when_date` 今天，並清掉今晚／某天旗標；有「復原」）與「某天」
  （和任務表單的「某天」同一個寫入：放進某天清單）。截止近的列只有「排到今天」（已經排在今天的沒有，沒東西可寫）。列照舊可拖到時間軸的某個小時。
  今天有日期、沒時間、不是候選的任務，照舊一行一件列在卡片下方的「還沒排時間」（不能收合）。
  今天什麼都沒有時，改成一句話，底下列前幾件「隨時」的任務（同樣的列、同樣的「排到今天」，也能拖），「看全部」去「隨時」分頁；「隨時」也空就給一顆新增按鈕。
- **空的時段收成一行**（`day/foldEmptyHours.ts`，純函式；只有 1 天時間軸，3 天／週不收）：連續 ≥ 2 個整點小時沒有任何方塊（任務、專注、行事曆事件、
  正在排的時段）就收成「12:00–16:00 空著 · 展開」，點了展開那一段（只在這次瀏覽有效）。「現在」所在的小時、前 1 小時與後 8 小時（`AFTER_NOW_HOURS`）永遠展開。
  位置全經 `foldLayout`（分鐘 ↔ px，收起的段是一列 36px，內部平均分配），所以方塊、現在線、草稿、指標與自動捲動對得上。
  **收起的段不是死區**：（1）拖任務經過時間軸、或拖動／拉長一個方塊時，全部展開（方塊在螢幕上的位置以捲動補償維持不動），放下後再收；
  （2）排時間的草稿自己的小時保持展開；（3）收起列本身是按鈕，點了展開。手機長按畫時段不在收起列上開始（那是按鈕）；畫到收起列上時，
  收起列內的指標位置平均讀成那一段的時間（粗略，需要精準就先展開）。
- **手機不給 3 天／週**：`DayPane` 在 `MOBILE_QUERY` 下不顯示切換，範圍視為 1 天（之前在電腦選過週，到手機仍是 1 天）。
- **接下來是一天一列的清單**（`UpcomingAgenda` ＋ `lib/tasks/upcomingAgenda`，手機與電腦同一份）：最上面一排接下來七天（有排的日子下面一個小點，點了捲到那天），
  下面依日期分段：「今天 11/9 週一」「明天 11/10 週二」，之後「週三 11/11」…；連續沒有安排的日子收成一行灰字；兩週（`AGENDA_DAYS`）後的放在「之後」一段，日期在左邊。
  清單從今天算起，所以也列今天排的任務（今天分頁也有）。
## 已知限制

- 快速新增有日期的任務（例如「明天」）仍寫進**今天**的日記（依業主指示；`createQuickTask.ts` 的 `defaultNote`）；時間軸以 `_task_when` 為準，不受影響。
- 3 天／週（`WeekBoard`）沒有小時格，不能在欄內改時間；時間軸上重疊的方塊並排，不自動推開。
