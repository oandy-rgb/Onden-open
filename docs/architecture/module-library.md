## 一句話

標籤的能力來自「模組」。內建模組像標準函式庫一樣預設就在（2026-10-24 起不必引入，見下節）；第一次需要時得到一個**模組標籤**
（例如 `#複習`）；自己的標籤**延伸**它（`#課程 延伸自 #複習`），就獲得那個能力。

## 模型：分層的圖（2026-10-24）

Onden 的資料是三層有向圖：

```
功能層   複習   看板   圖庫        ← 內建功能（每個匯入的模組有一個模組標籤）
          ↑ 加功能（可以很多）
標籤層   #英文 ── #單字            ← 你自己的標籤（上層只有一個，組成標籤樹）
          ↑ 套用標籤（可以很多）
筆記層   一篇筆記                  ← 筆記（有自己的筆記樹）
```

- **層與層之間的邊可以很多**：一篇筆記可以套用很多標籤；一個標籤可以加很多功能
  （「＋加功能」，存在 `tag_schema.extends`；**入口已於 2026-11-12 取代**，見〈標籤頁拿掉「＋ 加功能」〉）。
- **同一層裡面的邊只有一條 `parent_id`，組成一棵樹**：標籤樹、筆記樹各自一棵
  （標籤與筆記不互相當上層，見 `services/parentKind.ts`）。
- **新規則：功能層不參與標籤樹。** 模組標籤沒有上層標籤，也沒有任何標籤放在模組標籤底下。
  要讓標籤有某個功能，是「加功能」，不是搬到它底下。

比喻是函式庫：功能像函式庫提供的 trait／interface，你的標籤是你自己的型別，筆記是實例。
**加功能 ＝ implements**（可以很多個）；**上層 ＝ extends**（只有一個）；
函式庫永遠不依賴你的程式碼，你用它是靠組合，不是坐在它底下。

後端在寫入新上層的同一批地方檢查（建立標籤、搬標籤、合併、復原、輸入 `#a/b` 建路徑），
違反時回 409 `module_tag_parent`。輸入 `#複習/英文`（複習是模組標籤）會被拒絕並顯示提示，
不會默默建出功能連結。舊資料由 migration 129 修正：模組標籤的上層清掉；放在模組標籤底下的標籤
改成頂層，並把該模組加進它的 `extends`（保留功能與欄位）。標籤清單（手機「標籤」分頁、桌面側欄）
（2026-10-30）只列使用者自己的標籤；功能不在這裡出現（入口在「更多」與導覽列，標籤頁曾用「＋ 加功能」，2026-11-12 已取代）。
功能在任何地方都不寫成 `#`：用 `components/FunctionChip.tsx`（圖示＋翻譯後的名稱）或 `TagName`（功能是 chip、自己的標籤是 `#名稱`）。
成員只看到「有看得到的筆記用到」的標籤這一項沒做：標籤目錄是全工作區共用（`spaces.md`）、`content_nodes` 沒有建立者欄位，
要另開一批設計。

## 內建功能預設全開（2026-10-24，取代下文的「引入」）

內建功能像標準函式庫：**一直都在，不用引入**。下文凡是「引入／取消引入／未引入」，現在的意思是「開啟／關閉」，
介面已改用「開」「關」，程式與事件名稱（`MODULE_IMPORTED`、`module_not_imported`、`PATCH /api/workspace/modules`）為了相容沒改。

- **預設開**：每個內建模組在每個工作區都能用，擁有者不必先引入。只有擁有者明確關掉的才是關的；以後新增的模組也直接是開的。
- **第一次用先確認，三個**：語意搜尋（用 AI，花運算費用）、RSS（伺服器會連到外面的網站）、網站（發布到公開網路）。
  第一次要用時（「＋加功能」〔2026-11-12 起沒有這個入口〕、設定 › 模組的開關或「打開」、編輯器 `{` 選單）跳出一句白話確認，同意後永遠不再問，
  即使之後關掉再開。同意記在工作區（伺服器端），所以這三個在同意前是關的，背景工作（嵌入、抓 RSS、重建網站）也不會跑。
- **用到才出現**：**預設**的導覽列（沒編輯過導覽列時的桌面頂欄、手機底部列）只放核心頁與在用的功能；
  「更多」（手機的「更多」sheet、桌面頂欄的「更多 ▾」）列出所有開著、沒釘在導覽列的功能，用過沒用過都列，
  內容就是「編輯導覽列」裡「在「更多」裡」那一組（同一份 `arrangeNavigation` 的 `unpinned`，同樣的項目、順序與名字）。
  只有模組標籤、沒有自己頁面的功能（引用、技能）列在手機「更多」的「功能」，點了開標籤頁，不能釘。
  擁有者釘過的功能留在導覽列，不論有沒有在用。「在用」的定義只在 `lib/moduleUse.ts` 一處：

  | 功能 | 在用 = |
  |---|---|
  | 白板 | 有白板 |
  | RSS | 開著就算在用。訂閱存在伺服器的資料表（migration 145），不是筆記，前端的筆記清單看不出有沒有訂閱；閱讀頁同時是新增第一個訂閱的地方 |
  | 網站 | 有筆記標了發布 |
  | 日記 | 有日期標題的日記筆記 |
  | 文獻引用 | 有論文（引用鍵）或用到 #論文 |
  | 其餘（複習、技能、簡報、表格、月曆、看板、卡片） | 它的模組標籤被用到：有標籤加了這個功能，或有筆記直接貼了它 |

  舊的標籤開關（`behaviour.modules.<id>.enabled`）也算在用。標籤清單的「功能」區塊同樣只列在用的（`usedFunctions`）。
- **設定 › 模組**：每個功能一張卡，有開關（關掉要確認，說明資料全部保留、再開就回來）、「設定」與「打開」。
- **儲存**：`workspaces.modules_off`（擁有者關掉的 id）與 `workspaces.modules_confirmed`（三個需確認的同意了哪些）；
  舊的 `modules`（引入清單）不再讀。傳給前端的 `modules` 是算好的「開著的」清單，另有 `modules_to_confirm`（還在等第一次同意的）。
  migration 133：以前沒選過的一律變開；被關掉的以事件紀錄為準（某模組最後一個 `MODULE_IMPORTED`／`MODULE_REMOVED` 是移除 → 關），
  曾經引入過這三個的算已同意；模組庫之前的舊工作區（`modules` 為 NULL）由開機的 `backfillModuleImports` 補，
  在用的 RSS／網站／語意搜尋算已同意。不刪任何資料。模組標籤仍是第一次需要時才建立。

## 設定 › 功能的版面（2026-11-12）

這一頁只做一件事：決定哪些可選功能開著。四條規則：一頁一件事；附屬的排在主人底下；關不掉的不放這裡；一件事一個入口。

- **分組由模組自己宣告**：`library.group`（`{ id, order }`；組別是 搜尋、時間、閱讀與學習、AI、呈現與發布，順序在 `lib/libraryLayout.ts` 的 `LIBRARY_GROUPS`）、
  `library.blurb`（名稱下一句話）、`library.blurbOff`（關著時換成的一句，目前只有 AI）。頁面只照註冊表畫，不寫死模組 id。
  列在清單上的模組沒宣告組別或說明，`test/moduleLibraryLayout.test.ts` 失敗；可選功能之間圖示不可重複，同一個測試擋。
- **從屬**：沿用 `library.requires`（全部要開，後端也讀，關著時伺服器把它列為關）；`library.requiresAny` 是「任一個開著就行」（外部行事曆：日記或任務），
  只有前端讀，只決定這一頁的開關能不能按與說明文字。附屬在同組、排在主人之後、縮排；主人關著時暗掉、開關鎖住、說明換成「要先打開…」。
  附屬自己的開關狀態不動：技能存在 `modules_off` 的狀態不變，AI 再開就回到原狀（後端 `moduleOn` 的衍生規則）。
- **關著的留在自己的組裡**（較淡），不再另成一塊。
- **點一列**進功能自己的頁（說明＋設定）；`library.settingsTab` 讓一個功能的設定在設定的某一頁本身（AI → 設定 › AI），那一列直接去那裡，這裡沒有第二套 AI 設定。
- **記一筆、手寫不是功能**（關不掉）：它們是設定首頁（外觀、筆記之後）的兩列，舊的 `module:capture`／`module:handwriting`／`module:ai` 連結由 `resolveSettingsTab` 轉過去。
- **已關閉功能的標籤**（`RemovedModuleTags`）只在那個功能自己的頁顯示（有東西才顯示），不再常駐在清單底部。

## 為什麼是函式庫，不是 Tana 的範本

| | 函式庫（本設計） | Tana 範本 |
|---|---|---|
| 能力從哪來 | 模組程式碼（排程、抓 RSS、DOI 匯入、發布網站） | 使用者用欄位與指令組出來，或安裝範本 |
| 裝進來之後 | 一直連著，模組改進後全部受惠 | 複製一份，與原版斷開、無法更新 |
| 使用者要做的事 | 引入、延伸、調幾個設定 | 設計 supertag、欄位、指令、檢視 |
| 不夠用時 | Onden 開源：任何人都能寫新模組貢獻回來 | 自己組更複雜的指令 |

借用 Tana 已被證明好用的部分：**集中的標籤頁**、**延伸（繼承欄位、一起被查詢）**、**現成起點**。
刻意不借：讓使用者自組指令與流程（Tana 最常被批評「九成使用者設定不起來」）。

## 概念

- **模組**：一個能力包，例如複習、RSS 訂閱、文獻引用、網站。程式在 `modules/<id>/`，
  前後端各在註冊表登記一行（已存在）。
- **模組庫**：這個 Onden 版本內建的所有模組。開源社群寫的模組合併進來後，也出現在這裡。
- **引入**：工作區層級的開關。沒引入的模組不出現任何入口（導覽分頁、「更多」選單項目、
  首頁區塊、指令面板項目、設定區）。
- **模組標籤**：引入時建立的一個標籤（例如 `#複習`），本身就具備該模組的能力與預設欄位。
  可以直接貼在筆記上使用。
- **延伸**：標籤 A 延伸標籤 B，A 就繼承 B 的能力與欄位；查 B 時也會列出 A 的筆記。
  一個標籤可以延伸多個標籤（`#專題` 同時延伸 `#複習`、`#課程`）。
  「功能」改版後介面不再直接談延伸模組標籤：標籤頁按「＋ 加入功能」（背後是延伸該模組標籤），
  標籤之間的延伸放在「進階 › 從其他標籤繼承」，介面用詞是「繼承」；資料與 API 仍叫 `extends`。

例子：研究生在 `#課程`、`#專題` 的標籤頁各按「＋ 加入功能 › 複習」（第一次會順便引入複習、建立 `#複習`）。
之後貼 `#課程` 的筆記會出現在複習排程裡；打開 `#複習` 能看到兩個標籤的所有卡片，
每天新卡數由 `#複習` 的設定決定、兩個標籤共用一份額度。

## 畫面草圖（已實作的樣子）

### 標籤頁（上方導覽列）

```
標籤
┌ 模組庫 ────────────────────────────────────────────────────────┐
│ 複習     已引入  模組標籤 #複習  用在 #課程 #專題  [＋ 加到標籤…]       │
│                  [▸ 設定]（每天新卡數、記憶率、最長間隔）  [取消引入…]  │
│ RSS 閱讀 已引入  [▸ 設定]（OPML 匯入／匯出）               [取消引入…]  │
│ 文獻引用 未引入  引入後會建立 #論文                           [引入]   │
└────────────────────────────────────────────────────────────────┘
我的標籤                                              [＋ 新增標籤]
┌ #課程  複習  繼承 #學期    12 則直接標記的筆記 ┐ ┌ #gt  還沒有功能 [＋ 加入功能] ┐
```

「＋ 新增標籤」：名稱＋可選範本（空白、書籍、人物、會議、專案；範本只給欄位）。

### 單一標籤頁

```
#課程
功能                                             [＋ 加入功能]
┌ 複習：依複習排程回顧這些筆記。 [開始複習] [設定] [移除] ┐
欄位   作者 · 學分                                  [編輯欄位]
已標記的筆記 12 …（含繼承它的標籤的筆記）
▸ 進階：從其他標籤繼承（#學期 ×、＋ 繼承標籤…）· 存取權限 · 舊的自動化（只有提示與「移除自動化」）
```

- 「＋ 加入功能」列出所有功能與一句說明；模組沒引入時註明「加入時會一併引入模組」。
- 「移除」只拿掉這個標籤自己加的功能；從別的標籤繼承來的功能註明「經由 #x」，到「進階」改。
- 取消繼承或移除功能只影響這個標籤；筆記的標籤不變，複習狀態保留（沿用「停用保留 `_review_state`」）。

### 引入流程

1. 標籤頁 → 模組卡片 → 「引入」，或在任何標籤頁「＋ 加入功能」時順便引入。
2. 建立模組標籤（名稱可改，身分用模組 id 綁定，不靠名字），出現模組入口。
3. 模組卡片「＋ 加到標籤…」，或到單一標籤頁「＋ 加入功能」。

取消引入：入口全部消失、模組標籤保留但失去能力（標示「模組未引入」），資料不刪。
重新引入就恢復。

## 規則

1. **能力**：筆記直接貼的標籤 T，只要 T 本身或 T 延伸（可多層）到的任一標籤是**已引入**模組的模組標籤，
   該筆記就有那個能力。祖先路徑（`a/b` 的 `a`）仍不提供能力，與現行一致。
2. **欄位**：標籤顯示的欄位 = 自己的欄位 + 延伸鏈上所有標籤的欄位（同名以最近的為準）。
3. **查詢**：查 `#複習` 的成員 = 直接貼 `#複習` 的筆記 + 貼了任何延伸它的標籤的筆記。
4. **環**：不允許 A 延伸 B、B 又延伸 A；設定時拒絕並說明。
5. **權限**：延伸與引入都是 admin 操作（與現行「設定標籤功能需 admin」一致）；
   延伸不改變任何人的讀取範圍，標籤的讀取政策不沿延伸傳遞。
6. **模組設定**屬於模組，從「設定」搬到模組卡片（第 3 階段，已實作）；「設定」只留工作區層級的東西。

## 資料怎麼存

- **已引入的模組**（第 1 階段，2026-10-24 起由 `modules_off`／`modules_confirmed` 取代，見「內建功能預設全開」）：`workspaces.modules jsonb`，存已引入的模組 id 陣列，例如 `["rss", "website"]`
  （migration 085）。`NULL` 表示模組庫上線前的工作區，視為全部已引入；開機時 `backfillModuleImports`
  依各模組的 `library.inUse` 寫入實際在用的模組（只動 `NULL` 的列，可重複執行）。新工作區從空的清單開始。
  `PATCH /api/workspace/modules`（`{ module, imported }`，principal admin），寫事件 `MODULE_IMPORTED` / `MODULE_REMOVED`；
  重複同一個動作不寫事件。同步時這兩個事件與 `WORKSPACE_UPDATED` 一樣帶回工作區列。
  未引入 RSS 時背景抓取暫停（`enqueueDueRssFetches` 只排已引入 RSS 的工作區）。
- **模組標籤**：一般的 class_tag 節點，`tag_schema.module = "<模組 id>"` 標記身分（改名不影響）。
  模組的預設欄位寫在 schema。
- **延伸**：`tag_schema.extends = [tagId, …]`。後端提供 `effectiveModules(tagId)`（沿延伸鏈收集模組），
  供各模組判斷成員；必要時把結果快取在 `tag_schema.effective_modules`，延伸變動時重算。
- **沿用現有**：`behaviour.modules.<id>.enabled`（標籤功能中心第一版）。遷移時，每個已啟用某模組的標籤
  改成延伸該模組的模組標籤；舊旗標保留讀取相容一段時間，之後移除。
- **首次升級自動判斷已引入**：有標籤啟用複習、有 RSS 訂閱、有文獻、網站已發布 → 標記為已引入，
  現有使用者看到的東西不消失。

## 第 2 階段實作（2026-10-12）

已實作：模組標籤、延伸給能力、查詢包含延伸它的標籤、標籤頁的延伸介面。**尚未**：欄位繼承（2b）。

- **模組標籤**：`tag_schema.module = "<模組 id>"`。`PATCH /api/workspace/modules` 引入有標籤能力的模組（複習、文獻引用）時，
  在同一交易內確保模組標籤存在：已有標記的標籤 → 沿用；否則同名（不分大小寫）的頂層標籤 → 標記成模組標籤，筆記不動；
  否則建立新標籤（私有 schema，`publish_collection: false`）。名稱由前端依介面語言送（`tag_name`，中文介面是「複習」），
  沒送就用模組預設名（`review`、`paper`）。重複引入是 no-op 但仍確保標籤存在，所以舊工作區可在模組卡上按「建立 #複習」。
  取消引入保留模組標籤，它只是失去能力。
- **延伸**：`tag_schema.extends = [tagId, …]`，`PUT /api/tags/:id/extends { extends }` 一次設定整份清單
  （`services/tagModules.ts setTagExtends`）：principal admin、在事件鎖內重讀操作者、標籤與每個目標都要可見且存在、
  拒絕延伸自己與形成環（A→B→A，任意深度）、清單不變就不寫事件；label 標籤第一次延伸時建立私有 schema。
  事件是 `TAG_SCHEMA_UPDATED`（`changed: ["extends"]`），可在歷史中還原；還原若會形成環就以 `state_conflict` 拒絕。
- **有效能力**：`effectiveTagModules(rows)` 對每個標籤以廣度優先走延伸鏈，收集模組與「來源標籤」（最近的、本身提供該模組的標籤：
  模組標籤或舊開關）。缺失的標籤與環不提供任何能力。伺服器在 `/api/tags`、sync 的標籤目錄與 bootstrap 為每個標籤附上
  `schema_module`、`schema_extends`（只含此操作者看得到的 id）與 `effective_modules`（用全部標籤計算，看不到的模組標籤也照樣給能力）。
  是否已引入由使用端判斷（前端 `useModuleFilter`；複習路由檢查 `workspaces.modules`）。
- **複習**：延伸 #複習 的標籤（任意深度）其筆記都是複習卡；每天新卡數等設定跟著來源標籤（通常是 #複習）。
  額度原本每個直接標籤各一份，第 3 階段已改成每個來源標籤一份（見下）。`?tag_id=` 的範圍包含延伸它的標籤（研讀 #複習 會包含 #課程 的卡）。
  沒引入複習的工作區不排入任何卡，資料保留。
- **舊開關**（`behaviour.modules.<id>.enabled`）照樣是能力來源，不做資料遷移；「功能」改版後它就是這個標籤自己的功能卡，可按「移除」關閉，
  不再提供開啟它的介面。
- **前端**（第 2 階段的樣子，已由「功能」改版取代）：標籤頁的「能力」區塊列出延伸自、「＋ 延伸標籤…」選單與能力卡。
  寫入走 `tagExtendsWriter`（只在連線時、伺服器接受前不改畫面、不明回應以同一 Idempotency-Key 重試），改版後沿用。

### 設計比較（AGENTS.md：新公共介面先比較兩種）

| 決定 | 方案 A | 方案 B（採用） | 理由 |
|---|---|---|---|
| 延伸的 API | `PATCH` 加／移一個目標 | `PUT` 整份清單 | 畫面就是一排清單；冪等，不明回應可同鍵重試；代價是兩個分頁同時改同一標籤時後寫者勝（只有管理員會改） |
| 有效能力誰算 | 前端從目錄自己沿延伸鏈算 | 伺服器算好附在目錄上 | 讀取政策可能讓前端看不到某個模組標籤；複習排程與畫面用同一份結果；前端只在舊伺服器時退回看自己的模組／開關 |
| 模組標籤名稱 | 伺服器固定英文名 | 前端依介面語言送 | 中文介面直接得到 #複習；身分靠 `tag_schema.module`，之後改名不影響 |
| 舊開關 | 遷移成「延伸模組標籤」 | 保留為能力來源 | 不需要先有模組標籤、不改既有資料；畫面可關閉 |

### 尚未處理

- 欄位繼承（標籤顯示的欄位 = 自己的 + 延伸鏈上的，同名以近者為準）、`fieldForKey` 驗證、預設值。
- RSS 更新頻率還不是設定（草圖裡的「每 60 分鐘更新」）；目前 RSS 模組卡的設定只有 OPML。
- 收藏檢視（`collectionViewQuery`）、`#tag` 搜尋、`/api/query` 尚未包含延伸它的標籤；目前只有標籤頁成員清單與複習範圍包含。

## 第 3 階段與標籤頁「功能」改版（2026-10-12）

起因：使用者回報「標籤點進去很難第一時間發現怎麼引用，也不太會知道怎麼改功能」。第 2 階段的標籤頁先講「延伸自」

改版提案（使用者同意「都做」）：

- **標籤頁順序**：功能 → 欄位 → 已標記的筆記 → 進階。
  - **功能**：每個功能一張卡（面板按鈕、「設定」、「移除」）；「＋ 加入功能」列出所有功能與說明，
    選了就讓標籤延伸該模組標籤，模組沒引入就先引入（`lib/data/tagFunctionActions.ts`，模組庫卡片也用同一個）。
    繼承來的功能註明「經由 #x」，不在這裡移除；模組未引入的功能顯示「模組未引入」與「引入模組」。
  - **欄位**：直接顯示欄位名稱，「編輯欄位／新增欄位」才展開編輯器。
  - **進階**：從其他標籤繼承（只列一般標籤，模組標籤改由「加入功能」）、存取權限。
- **標籤自動化已移除（2026-11-15，業主決定）**：「加上標籤時做…」這類觸發／動作已由功能取代，AI 技能是手動按鈕、不由事件觸發。
  後端不再執行存在 `tag_schema.behaviour` 的 `on_apply`／`on_remove`／`on_attribute_change`；舊資料原樣留在資料庫、不動作，
  標籤頁沒有任何相關提示或按鈕；新的寫入（標籤 PATCH、標籤包匯入、AI 提案、備份還原）一律忽略這三個鍵，備份還原會在報告裡計數。
  套用／移除標籤仍照常記 `TAG_APPLIED`／`TAG_REMOVED`、補欄位預設值、展開範本。
- **誰能改**：功能、欄位、繼承、存取權限的變更介面只給管理員（伺服器原本就要求 principal admin）；其他人看得到內容與說明。
- **用詞**：介面說「功能」（原「能力」），標籤之間的關係說「繼承」；資料仍是 `extends`。
- **標籤頁（總覽）**：「＋ 新增標籤」（名稱＋可選範本：書籍、人物、會議、專案，範本只給欄位）；沒有功能的標籤卡片有「＋ 加入功能」；
  卡片只寫「繼承 #x」（一般標籤），模組標籤以功能名稱呈現。複習範本移除（由複習模組與 #複習 取代）。
- **論文**：文獻引用模組的模組標籤（中文介面 `#論文`）。引入時先沿用已有的模組標籤，再認領名為 `paper`／`paper-review`
  的頂層標籤（`legacyNames`），都沒有才用論文欄位範本建立；匯入論文的 `ensurePaperTag` 也先找模組標籤。
  已在用 `#paper-review` 的工作區引入文獻引用後，`#paper-review` 就成為模組標籤，筆記與欄位不動。

第 3 階段（模組設定搬到模組卡）：

- 模組卡「▸ 設定」顯示該模組的 `settings`（RSS：OPML 匯入／匯出，原在「設定 › 你的資料」），
  以及功能自己的設定表單（複習：每天新卡數、目標記憶率、最長間隔，存在模組標籤的 `behaviour.review`）。
  標籤頁功能卡的「設定」打開同一張表單，存在功能的來源標籤；不是來源時註明「這些設定屬於 #複習，從它得到複習的標籤都共用」。
- 模組卡也列出「用在」哪些標籤，並可「＋ 加到標籤…」。
- **每天新卡額度改成每個來源標籤一份**（`modules/review/service.ts reviewBudgets`）：`Budget = { tag_id: 來源, tag_ids: 共用它的標籤 }`，
  一張新卡在每個涵蓋它的額度各扣一次（同一額度的多個標籤只扣一次），任何額度用完或為 0 就不出新卡。
  `/api/review/stats` 的 `budgets` 以來源標籤命名（只列看得到的），`?tag_id=` 時列出涵蓋該範圍的額度。

| 決定 | 方案 A | 方案 B（採用） | 理由 |
|---|---|---|---|
| 每天新卡額度 | 每個直接標籤一份（第 2 階段） | 每個來源標籤一份 | 設定只在來源標籤改一次，表單說「共用」；A 讓三個延伸 #複習 的標籤在 15 張的設定下每天出 45 張新卡 |
| 加入功能的入口 | 標籤頁的延伸選單列模組標籤 | 「加入功能」清單＋說明，必要時先引入模組 | 使用者不必先懂模組標籤與延伸；模組庫卡片與標籤頁共用同一個操作 |
| 自動化 | 保留編輯器 | 只保留提示與移除 | 功能取代它；少一個要學的概念，既有設定照常執行 |

## 白板（2026-10-12）

使用者要求「白板也加進去」：白板成為模組庫的一張卡，可以引入／取消引入。白板原本是核心功能，所以**預設引入**：

  不能關（後端回 400），「＋」照常提供白板。以前把白板關掉的工作區：儲存的 `modules_off` 裡的 `canvas` 不再有作用，

## 欄位繼承 2b（2026-10-18，已實作）

標籤給筆記的欄位 = 自己的欄位 + 它繼承的標籤的欄位，任意深度。使用者確認（2026-10-18，「繼承就是原本的子節點」）繼承來源有三種：
(1) **上層標籤**（`parent_id`：`#書/小說` 得到 `#書` 的欄位）；(2) **功能**的模組標籤（`extends`，例如月曆帶來的日期欄位）；
(3) 舊有的標籤↔標籤 `extends`，在被移除前保留，免得已在用的欄位消失（介面不再提供建立）。同名以最近的為準：自己的最先，
再廣度優先、同一層裡上層先於 `extends`。不複製：上游標籤改了欄位，下游立刻跟著變。

- 一個入口：後端 `services/tagFields.ts`（`effectiveTagFields`、`effectiveFieldsOf`）。值的驗證（`fieldForKey`）、套用標籤時帶入預設值、
  彙總欄位、儲存檢視的欄位型別與看板分欄選項、送給前端的標籤目錄（`effective_fields`，繼承來的帶 `inherited_from`）都經過它。
  集合也是（D89，子標籤一編輯欄位就是集合）：項目的新增／修改（`services/collections.ts` 的 `loadCollectionSchema`，含標題欄位）、
  `GET /api/collections`（`fields` 仍是自己的，另帶 `effective_fields`）；網站 › 集合直接讀前端的標籤目錄
  （`lib/data` 的 `collectionsOf`，D97：bootstrap 不再另送一份集合，存檔只送改過的部分），
  以及發布網站的集合（欄位白名單、wikilink 遮蔽的文字欄位、標題欄位）。
- 前端 `lib/tagFields.ts` 的 `tagFields(tag)`：「這個標籤給筆記哪些欄位」一律讀它（屬性面板、行內屬性、編輯器補全、範本、表格 lens、Bases）；
  舊伺服器沒送 `effective_fields` 時退回自己的欄位。自己的 `schema_fields` 只用在編輯 schema。
- 標籤頁欄位那一行列出繼承來的欄位（虛線、標「#來源」，提示「來自上層 #x」「來自功能 #x」或「繼承自 #x」），在來源標籤上修改；
  成員表格與「＋ 檢視」的欄位選項包含它們。沒有自己 schema 的子標籤也會驗證上層的欄位。
- 「把屬性升格成標籤欄位」遇到已繼承的同名欄位就不再新增。

**同名欄位禁止**（使用者 2026-10-18：「同名欄位要不要禁止」→「要」）：標籤不能宣告上層、功能或舊 `extends`（任意深度）已給的欄位名稱。
規則只有一份（D93）：`@onden/markdown` 的 `fieldNameClashes` / `newFieldNameClashes`，以標籤目錄的列（id、parent_id、extends、fields）判斷，
後端與前端欄位編輯器都呼叫它。**只比欄位名稱**（儲存用的 key）；顯示名稱（label）相同不算衝突，例如 `author` 與 `writer` 都叫「作者」可以並存。
後端 `assertNoNewFieldClash` / `assertFieldChangeAllowed`（`services/tagFields.ts`）比較寫入前後，只拒絕這次寫入**新產生**的衝突，
回 409 `field_name_inherited`，附 `clashes: [{tag, field, from, tag_title, from_title}]`。檢查在兩個 schema 寫入口
（`tagWrites` 的 `insertTagRow`、`writeTagSchema`），所以 schema PATCH、網站 › 集合、模組開關、TagPack 匯入、核准的 proposeTagPack 都經過；
另加移動上層（`nodeUpdate`、`tagMerge`）：

| 情況 | 處理 |
|---|---|
| 編輯欄位：新增或改名成上層已有的名稱（`changeTagSchema` 的 `fields`） | 拒絕；前端欄位編輯器在**該欄位**下標紅「#書 已有『頁數』欄位，請換個名稱」，只有它不送出，其他欄位的修改照常儲存；新欄位自動產生的 key 會避開上下層已有的名稱 |
| 上層標籤新增下層已宣告的欄位 | 拒絕（同一檢查，衝突在下層）；前端標「下層 #小說 已有…」 |
| 加功能／`extends`（`changeTagSchema` 的 `extends`）、把標籤移到別的上層下（`nodeUpdate` 改 `parent_id`）、合併標籤時子標籤移到目標下（`tagMerge`） | 拒絕，訊息列出要先改名的欄位 |
| 新建帶欄位的標籤（`insertTagRow`：TagPack 匯入、proposeTagPack、模組範本、網站 › 集合新增） | 同一檢查；目前這些入口建立的是根標籤、不帶 `extends`，實際不會衝突，但規則在寫入口，不靠入口自律 |

已存在的衝突（舊資料、從垃圾桶或事件還原）照「最近的為準」繼續運作，也不擋該標籤的其他編輯（前後端都只看這次寫入新增的衝突）；還原路徑不檢查（`writeTagSchema(..., { restoring: true })`）。

這是視圖模組 V4（繼承來的檢視）的前提（docs/architecture/views-as-modules.md）。

## 語意搜尋（2026-10-18）

使用者決定「語意搜尋要關」。語意搜尋原本沒有 `library`，被當成永遠開著的基礎設施：每次內容變動都排一個 `embed` 副作用，
但正式站的本機嵌入模型（multilingual-e5-small）從第一次部署起就載入失敗，outbox 累積了幾百筆 dead 的 `embed`。

- 它成為模組庫的一張卡（`library: {}`，不預設引入）。首次引入只看 `inUse`，它沒有，所以新舊工作區都不引入；要用就在設定 › 模組引入。
- 未引入時：內容變動不排 `embed`（`hooksWhenImported`）；`POST /api/nodes/:id/suggested-links` 回 409 `module_not_imported`；
  agent 工具 `semanticSearch`、`suggestLinks`（搬進 `modules/semantic`）在查詢之前就丟 `ModuleNotImportedError`；
  AI 助理的搜尋只用關鍵字（模組的 `retrievalSource`，未引入時回空）；白板不畫「建議連結」（前端 `suggestsLinks` → `useLinkSuggestionsShown`）。
- 安全網：引入前留下的 `embed` 待辦，執行時發現未引入就直接標為 done，不載入模型，不會重試到 dead。
- migration 115 刪掉 `embed` 的 dead 與 pending 列（其他種類不動）；已存的 embedding 保留（取消引入保留資料）。
- 修好模型載入不在這次範圍。

## 標籤頁拿掉「＋ 加功能」（2026-11-12，擁有者決定）

**決定**：標題旁的「＋ 加功能」拿掉。「從一張功能目錄挑一個模組掛到自己的標籤上」不再是使用者的操作。
**理由**：這個操作沒有人敢按、也沒有人在用——正式站沒有任何使用者標籤掛著功能。使用者的標籤之後只有兩樣東西：
**欄位**（「＋ 欄位」）與**檢視**（檢視分頁的「＋」），兩者都已有入口、位置不動。
**原則**：標籤能引用的單位應該小而沒有副作用（欄位、檢視），不是整個模組；整個模組會連帶排程、網路、發布，
讓人不敢按。

**這一批做了什麼（只前端）**
- 拿掉標題的按鈕與 `TagFunctionPicker`（含樣式、字串）、`functionModel` 的選單列、`useTagStructure.addFunction`。
- 「功能」列只顯示標籤**已經掛著**的功能：沒有功能時整列不畫；已有的仍可按 ×、開面板與設定，
  「還沒開」的虛線 chip 與「開啟」（`turnOnFunction`，開模組並確認一次）保留給舊資料與自架的人。
- 不變：任務頁與筆記裡的 `{task}`、段落的「做成複習卡」（`blockAction`）、單則筆記的「當成技能」、文獻引用匯入。
  它們與標籤頁的功能列讀同一份 `TagFunctionSpec` 註冊，由 `tagFunctionCatalog.test.ts` 釘住。

**尚未處理（功能引用第三批）**：後端的 `PUT/DELETE /api/tags/:id/functions/:fn`、標籤持有的功能引用資料、
「標籤讓整則筆記成為任務」的收尾。這個決定不動資料與後端。
