## 流程

1. **選材料**：一塊白板，或一個標籤。白板上卡片的位置就是內容順序（由上到下，同一列由左到右，`harness/scope.ts readingOrder`）；標籤取最近編輯的筆記。
2. **產生大綱**：側欄「+」的「從白板或標籤做成簡報…」（預設選畫面上的白板或標籤），或白板筆記「⋯」／⌘K 的「用這塊白板做成簡報」，等於執行內建技能 `outline`（`POST /api/ai/run`，scope 是 `board` 或 `tag`）。權限與隱私照 harness：只用讀得到、所在空間開了外部 AI 的筆記，最多 20 則。結果串流顯示，**還沒有寫入任何東西**。
3. **存下來**：使用者按「存成簡報」才建立一則普通筆記，標題「簡報：〈白板或標籤名稱〉」，內容就是大綱。
   - 來源是白板：存成白板的子筆記。
   - 來源是標籤：存在根層，並貼上同一個標籤（讓它出現在標籤頁）。
   - 走既有的 note writer（一次結果一個 id，重試不會建兩則）。
4. **調整**：大綱就是筆記，用一般編輯器改；改完照常自動儲存，沒有另一份格式。
5. **播放**：筆記「⋯」或 ⌘K 的「簡報」進入全螢幕播放（模組 `slides`，前後端同名；`presentation` 已是筆記欄位名稱）。

## 大綱放在哪裡

大綱是**一則普通筆記**，投影片之間用單獨一行的 `---` 分隔；沒有 `---` 時以 `##` 標題分頁（規則同 skills-and-presentation.md）。緊接在段落文字下一行的 `---` 是 Markdown 的標題底線（setext），不算分頁；要分頁就在 `---` 前空一行（在清單、標題下面則直接分頁）。程式碼區塊裡的 `---` 不算；區塊要用同一種標記（``` 或 ~~~）結束。

- 不新增資料表、屬性或特殊節點型別，所以同步、離線、版本、復原、匯出、權限全部沿用筆記的。
- 任何筆記都能播放，不只 AI 產生的大綱。
- `[n]` 引用留在文字裡；播放時每頁底部列出引用的筆記標題（見下方「已決定」）。

比較過的另一個做法：把大綱存成來源節點的屬性（`_presentation`）。缺點是看不到、不能用一般編輯器改，還要另做同步與版本；所以不採用。

## 後端

- 只有內建技能 `outline`（scope：`board`、`tag`、`nodes`；effort medium；`output: note`）。它要求模型每頁用 `## ` 開頭、頁與頁之間單獨一行 `---`、每頁最多五點、每頁標上引用的 `[n]`，不加筆記沒有的內容。
- 播放、切頁、鍵盤與觸控都是前端的事，沒有後端 API。

## 「AI 心得」最後一頁（尚未實作）

簡報工具列的「AI 心得」：選一個技能（預設列出 `output: slide` 的 `#技能`），scope 是這份簡報筆記加上同標籤的筆記（`nodes`）。結果先顯示成暫時的最後一頁；使用者按「加到簡報」才用 `editNoteText` 在筆記結尾加上 `---` 與內容，或「另存成子筆記」。

## 已決定（2026-10-14，note-0f）

- **標籤來源的大綱放根層並貼上該標籤**：標籤不是父層，這和其他地方替筆記加標籤的方式一致。
- **播放時顯示來源**：`[n]` 留在文字裡；每頁底部一行小字列出這頁引用的筆記標題（`[1] 標題 · [2] 標題`）。點其中一個，離開簡報模式後打開那則筆記。
- **手機尺寸**：前端實作時在 320／390px 實測字級與換頁手勢，結果記在前端 PR。
  - 實測（2026-10-14，H4 前端 PR）：正文字級隨視窗縮放，390px 約 19px、320px 約 18px，標題約 1.6 倍。兩種寬度都沒有橫向捲動，長句正常換行。
  - 左右滑動超過 48px（而且水平大於垂直）才換頁，←／→、Home／End 也能換頁，Esc 離開。
  - 上一頁、下一頁、關閉按鈕都至少 44px。
