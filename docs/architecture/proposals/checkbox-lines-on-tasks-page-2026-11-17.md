# 提案：任務頁列出「筆記裡還沒變成任務的核取方塊」

> 狀態：提案（只有文件，2026-11-17；業主已同意方向）
> 起因：派工者以全新使用者身分在新筆記寫了兩行 `- [ ]`，任務頁只有範例任務，畫面上沒有任何一處說明原因。業主問過意見、也問過 Obsidian 使用者怎麼說，2026-11-17 回「好」。
> 這份文件**沒有改任何產品程式、測試或 migration**。排在進行中的可靠性修正**之後**。

## 0. 一頁結論

- 核取方塊**不會自動變成任務**。三個理由：核取方塊常常不是任務（解法步驟、行李清單）；變成任務會產生有自己身分的資料（排程、連結），
  若每台裝置都自動做，同一行可能被多台各做一次（第 4 節：#1853 之後，收到對方寫入的情況已修好；各自離線、收到之前的情況仍開著）；產品原則是系統不替人決定（出處：業主 2026-11-17 的方向，經派工者轉述；`docs/decisions/product-principles.md` 沒有寫這一句，那份文件沒有被改）。
- 任務頁多一個區塊，列出**還沒變成任務的核取方塊行**。它是**推導的**：只由筆記文字算出，不建立資料列、不鑄 id、不寫事件，所以各裝置之間不可能衝突。
- 每一項有「排到今天」（桌面與平板也能拖到時間軸）；**那一下才是把這行變成任務**，走既有路徑，是使用者自己的動作。
- 第一次寫核取方塊時在旁邊出現一次安靜的「排進任務」。可以把某則筆記排除在這個區塊之外。不需要任何標記才算候選。

## 1. 今天有什麼（讀碼；沒有在瀏覽器實測）

**一行怎麼變成任務**
- 行尾的 `{task}` 才算：`- [ ] 寫下三個習慣 {task}`。普通 `- [ ]` 不是任務（`modules/tasks/blockTasks.ts` 檔頭；`blockTasks.integration.test.ts` 第一則「a plain box does not」）。
- 筆記每次存檔，`syncBlockNodes` 認出有任務字的核取行，呼叫 `syncBlockTasks`（`blockTasks.ts`）：新行就建立任務、已勾就完成、改字就改名、拿掉 `{task}` 或刪行就把任務丟垃圾桶。
- 整件事受「任務」功能開關約束：關著時存檔不建任務（`modules/tasks/seam.ts` 的 `linesAreTasks`／`syncLines`）。
- 套上 `{task}` 的方式：段落工具的「讓這一塊變成任務」（`modules/tasks/index.ts:63` 的 `paragraphAction`）；筆記資訊面板的「還能用在這則：任務」列的是還沒用在這則的功能（`components/InfoFunctions.tsx`、`functionCatalog/catalogRows.ts`）。
  沒有核取方塊的行被套上時補一個（`packages/markdown/src/taskBox.ts` 的 `taskBoxEdit`）。
- 反方向：在任務頁完成任務，會勾回那一行（`modules/tasks/lines.ts` 的 `syncTaskLine`，經 `updateNode`）。

**任務在資料裡是什麼**（`docs/architecture/tasks-module.md`「兩種任務」「資料合約」）
- 任務是一個**自己的節點**，勾選行任務是筆記底下的隱藏子節點；行與任務由 `block_nodes.task_id` 連起來。排程、完成、重複等屬性寫在任務節點上，不在筆記文字裡。
- 誰鑄 id：由**寫入的那台**鑄一次、跟著寫入走（#1853、migration 215，2026-11-19 合併：錨點、段落列、任務行的 id 隨內文寫入複製，收到的節點採用、不另鑄）。鑄的地方：`blockTasks.ts:72` 用 `randomUUID()` 鑄任務 id，行的 `block_nodes.id` 與段落記號由 `newBlockId()` 鑄。
  快速新增與「放進筆記」不同：用戶端先鑄任務 id（`create.ts` 的 `id`），筆記存檔時用 `adoptTaskForLine` 接上它，不再另鑄。
- 任務頁的列表來自 `taskAgenda`（`modules/tasks/agenda.ts`），不是從文字掃出來的。

**任務頁**（`packages/frontend/src/modules/tasks/TasksMode.tsx`）
- 四個分頁：今天／接下來／隨時／某天。「今天」上方有「可以排進今天的」卡片；今天什麼都沒有時，改顯示一句話加「隨時可以做的 · N」前幾列（`UnscheduledStrip.tsx`）。
- 每列有可見的「排到今天」按鈕；它的寫入是 `lib/tasks/leftOver.ts` 的 `planTodayChanges`（把任務的日子改成今天，附復原）。列也能拖到時間軸。
- 範例筆記（`packages/backend/src/browser/sampleNotes.ts:118-121`）的四行（其中一行已勾）都已帶 `{task}`，所以全新使用者看到的只有範例任務。

**文字在哪台機器上**
- 伺服器有每則筆記的全文（`content_nodes.markdown`）。大工作區（超過 2000 則，`lib/slimMode.ts`）的精簡開機**不帶內文**，裝置的本機副本只有下載過的內文（`localDbPersist.ts` 檔頭、`localDb.ts` 的 `missingBodyIds`／`storeDownloadedBodies`）。
- 已有可重用的零件：程式碼圍欄 `fences.ts`、核取行判斷 `plainText.ts` 的 `checklistLine`；匯入 Obsidian 資料夾時已數「沒有任務記號的 `- [ ]`」（`modules/importers/obsidian/import.ts` 的 `plainCheckboxLines`，有測試涵蓋圍欄與引用裡的圍欄）。那個函式在匯入器裡，不是共用入口。

**其他提案**：[錨點確定性](anchors-deterministic-2026-11-16.md)；[同步設計對照文獻](../../research/sync-design-vs-literature-2026-11-16.md) 第 6 項（衍生的結果必須從已複製的狀態算出，不能是新的有標記寫入）。

## 2. 畫面（使用者看到什麼）

**任務頁的區塊**
- 名稱：建議 **「筆記裡還沒排的」**；備選 「筆記裡的核取方塊」、「還沒變成任務的」。（只有一個名字要業主挑，見第 7 節第 1 題。）
- 位置：「隨時」分頁最下方一個區塊；另外在「今天」空空時，「隨時可以做的」下面多一行「筆記裡還有 N 項沒排」，點了到那個區塊。不進「今天」的時間軸上方，免得與「可以排進今天的」混在一起。
- 以筆記分組，組名＝筆記標題，預設只展開前幾組，每組可收合；一組內項目依它在筆記裡的順序。
- 一項顯示：那一行的字（去掉 `- [ ]`）、所屬筆記名、「打開筆記」（開到那一行）、「排到今天」。電腦與平板：可拖到時間軸。手機：單欄、只有按鈕，沒有拖曳。
- 排進後：那一行多了 `{task}`，從這個區塊消失，出現在任務頁各分頁。
- 在筆記裡把它勾掉：從區塊消失（建議，第 7 節第 2 題）。刪掉那一行：消失。
- 空狀態：一句白話「筆記裡沒有還沒排進任務的核取方塊。在筆記裡寫 `- [ ]` 就會出現在這裡。」同時說明它們不會自動變成任務（這正是今天缺的那句話）。

**筆記裡**
- 第一次寫出核取方塊行時，那一行旁出現一個小的「排進任務」（一次，之後不再出現；用 `useHintOnce`，它本來就是每個帳號一次：`hooks/useHintOnce.ts` 檔頭，換裝置不會再跳）。點了＝這行的「排到今天」同一個動作。
- 排除：筆記資訊面板的「任務」那一列放一個看得見的開關「這則的核取方塊不列進任務頁」，不藏在 ⋯ 選單。排除的是整則筆記；不做逐行排除。
  開關是**使用者的決定**，所以是複製的（會同步、有來源標記），不是推導的。存在哪裡（筆記屬性最可能，`tasks-module.md` 的屬性有標記）我沒有核對它的同步分類。

## 3. 推導的定義：一個純函式

```ts
// @onden/markdown（前後端同一份）
checkboxCandidates(note: { id: string; markdown: string }): { noteId: string; line: number; text: string }[]
```

- 輸入：一則筆記的 id 與全文。**哪些筆記進來**由呼叫者決定，函式不管權限：
  - 只含使用者讀得到**也寫得到**的筆記（排進任務是寫入；唯讀筆記列了也按不了，建議直接不列）。伺服器端走 `readPolicy`（含集合查詢的 SQL 範圍），不先全量取出再過濾。
  - 不含垃圾桶（用現有的活節點條件 `liveNodeSql`）；已被排除的筆記不含；其他空間的筆記照使用者目前可見的空間（與任務頁的空間篩選一致）。
  - 「隱藏」的筆記：我不確定產品裡哪些筆記算隱藏（隱藏的任務子節點是另一回事），**沒有驗證**；先照「讀得到的活筆記」處理。
- 規則（建議；第 7 節第 3 題問巢狀）：
  - 算：行首（可縮排）是 `- [ ]`／`* [ ]`／`+ [ ]` 且**未勾**；編號行（`1. [ ]`）**先不算**：既有的 `checklistLine`（`plainText.ts:25,32`）只認 `-`、`*`、`+`，要算就得新增，列入第 1 步，行上沒有 `{task}`。已勾的不算。
  - 不算：程式碼圍欄裡、YAML 前言裡、引用（`>`）與 callout 裡的行（那是別人的話或範例）。
  - 巢狀子項：建議算，顯示時附上它的上一層文字當脈絡。
  - 範例筆記：是普通筆記，照同一條規則，不特別排除。
- 輸出：行號（供「打開到那一行」）與去掉記號的文字。**不含 id**：沒有任何東西被鑄造。
- 實作要用 `@onden/markdown` 既有的圍欄與核取行判斷，不另寫第二套；把 `plainCheckboxLines` 的圍欄邏輯收到同一處（收斂一處重複，同 PR 加守門測試）。
- **跑在哪**：兩邊都能跑，**答案不能不同**。
  - 伺服器：查詢帶可見範圍與「全文含 `[ ]`」的預篩，再用同一個函式；分頁回傳。線上用它。
  - 裝置：用本機已有的內文跑同一個函式。大工作區（>2000 則）只有下載過的內文，所以離線時結果**可能比伺服器少**；
    介面必須說清楚（「只含這台裝置已下載的 N／M 則」），不能假裝完整（根規則：影響使用決策的保證放進介面）。
  - 保證相同的方法：同一份函式、同一組固定樣本，在兩邊各跑一次比對（第 5 節）。
- **成本（沒有量）**：20,000 則筆記每次打開任務頁都全掃，我沒有量過，不假設可行。選項：(a) 先量；(b) 伺服器維護一個**推導的**每則筆記候選數（存檔時算，不同步，可從全文重算），
  任務頁先顯示總數與前幾組、展開才取內容。(b) 是推導資料，必須遵守「衍生的修正不是新的有標記寫入」。**數字可不可以不掃全部就得出**：只有 (b) 做得到；(b) 要不要做取決於 (a) 的量測，現在不做。

## 4. 排進任務（promotion）

- 就是今天已有的路徑：筆記裡那一行套上 `{task}`（與段落工具「讓這一塊變成任務」相同的筆記存檔，`updateNode`），筆記存檔時伺服器照 `syncBlockTasks` 建任務；
  「排到今天」再用任務的更新（`planTodayChanges`／任務 PATCH）把日子設成今天。
- **誠實說明**：這是**兩次既有寫入**（先筆記、再任務），我沒有找到今天把「這行變任務並排到今天」合成一次的操作。第二次失敗時任務存在但沒有日子，會落在「隨時」，不會遺失（建議這樣接受）；
  若業主要「一個動作、全成或全不成」，需要新增一個領域操作——**這是待決定的依賴，本文不設計**。
- 鑄造的東西：被改的那則筆記一次新的內文版本（`NODE_UPDATED`）；任務節點的 id（`randomUUID`，伺服器鑄）；行的段落列 id 與錨點記號（`newBlockId`，伺服器鑄）。**打開頁面不寫任何東西**。
- **兩台裝置排進同一行，現在怎樣**（2026-11-19 之後，已依 #1853 重寫）：
  - **已修好的情況**：A 排進（行、段落列、任務節點一起寫入）、B 收到之後 B 再編輯同一份文字：B 沿用 A 鑄的錨點、段落列與任務，不會多出第二個任務。
    `packages/backend/src/test/anchorIdsTwoNodes.integration.test.ts` 現在斷言「同一行在兩台是同一則任務」（檔內已沒有 `it.fails`，只剩註解提到舊行為）。
  - **還開著的情況**：兩台**各自**、在收到對方的寫入**之前**，對同一行都加上 `{task}`；每台每次存檔仍各抽一個任務 id（`blockTasks.ts:72`），相會時會有兩個任務。**main 上沒有測試釘住這個情況**，我也沒有補（本次只有文件），列在第 9 節。
  - 這與推導的區塊無關（區塊不寫任何東西），只與「排進」這一下有關；本文不發明修法。
  所以：排進任務的**按鈕**（第 6 節第 4 步）不再等錨點第 3 步（已完成）；它只帶著上面「各自離線排進同一行」這個還開著的風險，要不要先補測試或先處理，由擁有者決定。唯讀區塊本身（第 1–3 步）沒有這個風險。

## 5. 不能弄壞什麼，以及什麼測試證明

- 區塊（任一裝置）＝純函式套在「該使用者可見且可寫的活筆記」上的結果：固定樣本筆記集，在伺服器查詢與本機各算一次，逐項相等。
- 打開任務頁、展開、收合、重新整理：事件數、`node_*` 列數、任務數都不變（寫入計數測試）。
- 排進任務是**唯一的寫入**：一次動作之後只多出第 4 節列的東西，且該行從區塊消失。
- 排除的筆記，同步後在另一台裝置仍然被排除（排除是複製的）；撤權（唯讀、離開空間）後，那些筆記的項目從區塊消失。
- 垃圾桶的筆記、圍欄／引用／前言裡的行、已勾的行、已帶 `{task}` 的行都不在區塊裡；任務功能關著時整個區塊不出現（建議；因為「排進」做不了）。
- 數字：標題上的數量等於區塊實際列出的數量；大工作區離線時，「只含已下載」的說明與實際數量一致。
- 保存與錯誤走既有的 writer／`writeErrors`，失敗保留那一行不動、顯示簡短原因。
- UI 變更要跑桌面與手機寬度檢查與 `layout:audit`；`changes/` 加一則白話說明。

## 6. 做事順序（每步業主可以試；大小是我的估計，沒有量）

前提：排在進行中的可靠性修正之後。

1. **純函式與測試**（小）：`checkboxCandidates` 放 `@onden/markdown`，收斂匯入器的重複邏輯。業主看不到畫面，可以看測試案例表。
2. **伺服器讀取與同步比對**（中）：依可見範圍回傳候選（分頁）；本機同函式；比對測試。先量 20,000 則的成本，再決定要不要做推導計數（3 節 b）。
3. **任務頁的唯讀區塊**（中）：分組、收合、空狀態、打開到那一行。**依賴**任務頁外觀的方向 A 工作（位置與間距在那裡定）。業主可以試：寫兩行 `- [ ]`，看到它們。
   「打開到那一行」今天是否已有現成入口，我沒有確認。
4. **「排到今天」與拖到時間軸**（中）：用第 4 節的兩次寫入。**依賴**：是否合成一次的決定；以及第 4 節「各自離線排進同一行」是否先處理（錨點第 3 步已完成，不再是依賴）。
5. **排除開關**（小到中）：資訊面板那一列；要先確認屬性的同步分類。
6. **第一次核取方塊的提示**（小）。
- 搜尋的單字元修正與這件事**無關**，不在此排序。
