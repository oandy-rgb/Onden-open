## 1. 正式站盤點（決定 6 要求的報告）

上層文件的決定 6：模組標籤節點（#複習、#月曆…）在這一批移除（進垃圾桶，可復原），但要先給業主看「哪些被使用者改過」。
業主 2026-11-12 把規則改為可以讀正式資料庫；當天以唯讀連線跑了一個只看標籤名稱與統計的查詢（沒有讀筆記內文）。

一個工作區、924 個節點、10 個模組標籤：月曆、收件匣、論文（名稱仍是舊的 `paper-review`）、卡片、看板、稍後讀、複習、技能、表格、任務。

- **10 個都沒有被改過**：名稱是預設值、沒有內文、沒有自訂顏色、沒有使用者加的屬性、沒有已存檢視、沒有子標籤。
- **沒有「被收編」的使用者標籤的跡象**（模組建立標籤時若已有同名的使用者標籤會直接沿用，那種標籤上會有使用者自己的筆記與欄位）：只有收件匣上有一則看得到的筆記，是正常的捕捉。
- 論文標籤的欄位與 `PAPER_TAG_TEMPLATE` 相同。幾個標籤在 2026-10-14 同一分鐘內有人為事件，是一次批次處理，不是手動編輯。
- 稍後讀自 2026-10-26 起就在垃圾桶，底下沒有任何筆記。

移除時要帶走的東西：

| 標籤 | 掛在上面的 | 去向 |
|---|---|---|
| 任務 | 11 個進行中的任務節點、11 個在垃圾桶的、24 行 `{task}` | 第 2 節 |
| 複習 | 6 個段落、1 則在垃圾桶的筆記 | 引用（共用；排程本來就分人存，不動） |
| 收件匣 | 1 則筆記（另 5 則在垃圾桶） | 個人引用，歸給捕捉它的人（查不到就歸工作區擁有者） |
| 表格 | 還有 1 個標籤用舊的 `extends` 掛著它 | 第二批處理 |
| 其餘 | 無 | 直接移除 |

**結論：移除模組標籤節點不會丟掉業主的任何東西。** 其他工作區（之後自架的人）沒有這個保證，所以 migration 仍然要照上層文件 §5.3 的做法：遇到被改過或被收編的標籤不移除、留在原地並記下來。

## 2. 任務怎麼搬

### 現況（上層文件寫「筆記直接帶 #task」不精確）

「任務」其實有三種東西：

1. **任務節點**：一則**隱藏的**筆記，掛著任務模組標籤，加上 `_task_status` 屬性（`spine/taskIdentity.ts`、`services/tasksStore.ts` 的 `createTaskNode`）。可能是某則筆記的子節點，也可能獨立。任務頁建的任務都是這種。
2. **筆記裡的一行**：`- [ ] … {task}`，是段落節點，以 `block_nodes.task_id` 連到一個任務節點。
3. **標籤讓整則筆記成為任務**：標籤帶 `tasks_checkable`／`tasks_dates` 功能時，看得到的那則筆記本身就是項目。這種**已經在 `function_refs` 裡**，不靠任務標籤。
   **→ 2026-11-12 決定整個移除（第 7 節）**；正式站沒有任何標籤帶這兩個功能。

判斷「這是不是任務節點」的 SQL 全部經過 `taskIdentity.ts` 的五個函式；其他 35 個產品檔與 19 個測試檔都是呼叫它們。客戶端拿到的是伺服器組好的 `tasks` 列，從不自己判斷。

### 做法：每個任務節點記一筆引用

- 任務節點在 `function_refs` 有一列：`function_id = 'tasks'`，引用者是該任務節點。取代現在的 `node_tags` 列。
- 改的地方集中在兩個檔：`taskIdentity.ts` 的五個函式改成查引用；`tasksStore.ts` 的 `createTaskNode` 改成寫引用。其餘呼叫者不動。
- `functionRefs.ts` 現在只接受標籤當引用者，要開放筆記（上層文件本來就要求）。
- 引用表的唯一索引是 `COALESCE(holder_node_id, holder_space_id)` 的表達式；任務的 `EXISTS` 要寫成用得到它的形狀，或另加一個 `(holder_node_id, function_id)` 的索引。**agenda 的查詢在改前改後要各量一次。**
- **`{task}` 的寫法保留**，改由任務模組自己認得這個保留字，不再靠「解析成標籤」。必須同時擋住一個陷阱：標籤節點不在之後，`resolveTagNames` 會在下一次存檔時幫 `{task}` 新建一個普通的 `task` 標籤（`blockNodes.ts` 的註解已點出）。
- 第 2 種（行內任務）已有的 `block_node_tags` 列跟著移除；段落與任務的連結（`block_nodes.task_id`）不動。
- 同步送給客戶端的 `tasks` 列形狀不變，客戶端不用改。備份格式裡任務的表示法不變（匯出時仍輸出成任務，不輸出引用列的內部細節）；還原舊備份時遇到任務標籤要轉成引用。
- 順便修：`OverviewEditor.tsx` 找任務標籤用的是 `reserved_key === "task"`，那個記號在 migration 135 就清掉了，所以編輯器永遠寫 `task`。改成向任務模組問保留字。

沒選的：
- 用屬性判斷（隱藏＋`_task_status`）：改最少，但「這個東西有什麼功能」就不只一個入口了，違反上層文件的核心規則；而且第 3 種任務也有 `_task_status`，只能靠「是否隱藏」區分。
- 任務標籤當例外保留：零風險，但和決定 6 矛盾，之後每條規則都要寫「任務除外」。

### 使用者看得到的改變

- 標籤清單的「功能」區不再有「任務」這個標籤頁；任務的設定在 設定 › 功能 › 任務（已經是這樣）。
- 不能再幫「任務」改名或改顏色。盤點顯示業主沒有改過。
- 其餘（任務頁、行內任務、重複、提醒、番茄鐘）行為不變。

## 3. 稍後讀整個拿掉（業主 2026-11-12）

上層文件原本要把稍後讀改成個人開關。業主 2026-10 就說過不做只進不出的清單，正式站上它早已在垃圾桶、沒有任何筆記。

既有工作區若有人在用（業主的沒有）：migration 把掛著稍後讀的筆記列進遷移報告，資料表先改名保留一版再刪，不靜默丟棄。

## 7. 標籤不再掛功能（業主 2026-11-12，經另一個工作階段轉述後向業主確認）

業主看過 Tana、Capacities、Heptabase 的做法與自己實際的使用後決定：**標籤頁的「＋加功能」拿掉；使用者的標籤只帶欄位與檢視。**
原話是這幾樣「可能也不太需要，之後設計一個更好用的方式」。標籤層的行為之後從頭設計，不在這一批。

正式站查證（唯讀）：`function_refs` 共 5 列，全部是模組標籤引用自己；沒有任何使用者標籤持有功能；唯一的舊資料是 #書籍 以 `extends` 掛著「表格」（檢視，第二批處理）。

對這一批的影響：

| 項目 | 原本 | 現在 |
|---|---|---|
| 標籤頁的「＋加功能」入口 | 保留 | 前端移除（另一個工作階段的 PR：`feat/tag-page-no-add-function`）；標籤頁分頁列的「＋」是加檢視的入口，保留 |
| 標籤帶 `tasks_checkable`／`tasks_dates`（整則筆記成為任務） | 已在引用表，不動 | **整個移除**：`services/noteTasks.ts`、agenda 裡對它的支援、前端 `lib/tasks/noteTasks.ts`、這兩個功能 id。任務只剩兩種：任務節點與筆記裡的一行 |
| 複習 | 標籤層引用＋段落＋筆記 | **整則筆記與段落都保留**（各自記一筆引用，共用；排程本來就分人存，不動）；標籤層的複習移除 |
| 技能 | 標籤層引用＋筆記上的開關 | 只剩筆記上的「當成技能」（共用） |
| 論文那組欄位（`PAPER_TAG_TEMPLATE`、`ensurePaperTag`） | 模組標籤 | **整個移除**。要記論文的人自己建標籤、加欄位 |
| 稍後讀 | 第 3 節 | 不變：整個移除 |
| 引用表的引用者 | 筆記、標籤、空間、段落 | 這一批之後標籤只因**檢視**而出現在引用表；功能型的引用者只有筆記與段落（空間在第四批） |

**引用文獻模組整個移除（業主 2026-11-12）**：論文欄位移除後，模組其餘部分（以 DOI 匯入、BibTeX、引用連結與選擇器，前後端約 1,300 行：`modules/citations` 兩邊、路由 `/api/citations`、相關的連線類型與文字）失去存放欄位的地方，正式站也沒有任何筆記套過論文標籤。單獨一個 PR；既有工作區若有論文標籤與套用它的筆記，標籤與筆記、欄位的值都保留（標籤變成普通的使用者標籤），只移除模組的行為。

上層文件 [功能引用表](function-references-2026-11-02.md) 第 3 節「四種引用方式」與第 9 節的決定 2（「功能不繼承，空間的引用代表可用」）中凡提到標籤持有功能之處，以本節為準；該文件動工到第四、五批時再整份更新。


### 引用文獻模組移除的實作紀錄（2026-11-12）

移除 `modules/citations`（後端與前端）、`/api/citations`、`@onden/markdown/cite`、模組標籤 #論文與 `PAPER_TAG_TEMPLATE`／`ensurePaperTag`。
migration 193 處理既有資料：標籤去掉模組記號變成普通標籤（內部名 `paper-review` 改成「論文」／`Paper`，被使用者改過名的不動）；
沒改過且沒有筆記的論文標籤進垃圾桶（NODE_DELETED 事件，可復原）；`function_refs` 的 `citations` 列、標籤上的開關、
`origin = 'citation'` 的衍生 `cites` 連線、工作區 `modules_off`／`modules_confirmed` 裡的 `citations` 清掉。
筆記內文裡的 `[@key]` 一字不動，顯示成普通文字。

### 複習與模組標籤節點移除的實作紀錄（2026-11-13，第三批前半）

**migration 195（複習）**：`function_refs` 多一個引用者種類 `holder_block_id`（段落；一個引用列只有一個引用者）。每則曾是卡片的筆記
（`node_tags` 掛在「提供複習」的標籤上：模組標籤、延伸它的標籤、舊開關；垃圾桶與隱藏的也算）與每個曾是卡片的段落各記一筆 `review` 引用；
標籤層的 `review` 引用與舊的 `behaviour.modules.review` 開關刪除。排程（`review_states`）、個人設定（`actor_module_settings`）、
標籤的 `behaviour.review` 都不動。筆記存檔時，段落 `{…}` 裡的複習字（`review`、`複習`，或仍存在的複習標籤現在的名字；工作區有同名的普通標籤時那個字
仍是那個標籤）加一筆引用，不再解析成標籤；拿掉字不會拿掉卡片（排程與引用留著，和被隱藏的段落同一個原則）。整則筆記要當卡片用
「把這篇筆記做成複習卡」（`PUT /api/review/cards/:id`，事件 `FUNCTION_REF_ADDED`／`REMOVED`，可從歷史復原）。標籤頁沒有複習；以標籤為範圍練習
（`/api/review/queue?tag_id=`）改成「筆記或段落掛著這個標籤（含子標籤）」。

**migration 196（模組標籤節點）**：沒被改過的 live 模組標籤（複習、任務、四個檢視）進垃圾桶（`NODE_DELETED`，可復原；`node_tags` 列留著，復原才接得回去）；
被改過的（改名、說明、顏色、欄位、已存檢視、子標籤、延伸、個人設定、非模組自己放的成員）留下並列入 NOTICE，檢視標籤去掉模組記號，複習與任務的標籤保留記號
（複習的每日新卡上限與個人設定還讀它，任務的字還認它的名字，第二批前半之後再依功能 id 重組）。**技能（`skills`）與收件匣（`capture`）的標籤原封不動**：
技能的「當成技能」與收件匣的筆記都還是靠標籤成員找的，改成個人引用／筆記引用屬於下一批；延伸被移除標籤的使用者標籤只去掉那一筆 `extends`。

舊備份還原：複習標籤不還原成標籤，它與延伸它的標籤的筆記還原成卡片；四個檢視標記與其他退役模組一樣由 `withoutRetiredModules` 丟掉。
