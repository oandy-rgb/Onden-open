## 1. 一句話

**每個參與者都是「一個角色，在某些空間有某種權限，透過一個有期限的工作階段連進來」。**
陌生電腦、共編的朋友、會議聽眾、AI、你的第二台裝置，差別只在這三樣東西的值，不各做一套。

業主 2026-11-15 的前提：

- 最常見的情形是**手機配一台陌生電腦**（教室、借來的電腦，不能裝東西），在那台電腦上要能改，改完的東西回到手機。
- 手機、VPS、電腦**都要有一份**資料。
- 這件事和**共編**分不開，要一起設計；**角色與空間**要納進來；要**支援多種連線模式**。
- 兩邊都是瀏覽器也要能用。

## 3. 模型

三個互相獨立的問題，各有一個答案：

| 問題 | 答案 | 值 |
|---|---|---|
| **是誰** | 角色 | 擁有者、成員、AI、**來賓（新）** |
| **在哪裡、能做什麼** | 每個空間的權限 | 不在、只能看、**只能提建議（對人是新的）**、可編輯 |
| **怎麼連進來、連多久** | 工作階段 | 連線模式（第 4 節）＋到期時間＋可以從哪裡結束 |

每種情形填進去：

| 情形 | 角色 | 空間權限 | 工作階段 |
|---|---|---|---|
| 你在陌生電腦上 | 你本人 | 這次選的空間，看或改 | 幾小時；手機上可結束 |
| 共編的朋友 | 成員或來賓 | 你分享的空間，看／提建議／改 | 成員沒有期限；來賓有 |
| 會議聽眾掃 QR | 來賓 | 指定空間，只能提建議 | 會議期間 |
| AI 回答一個問題 | AI | 它被加入的空間，只能提建議 | 一次對話 |
| 你的第二台裝置 | 你本人 | 全部 | 沒有期限；可移除 |

規則：

- **範圍是「哪些空間」，可以選一個或多個**（業主 2026-11-16：「只同步某個空間」改成「同步哪些空間」）。開工作階段、帶到另一台裝置、之後的每一次同步，選的都是一份空間清單：勾幾個就帶幾個，全選就是整個工作區。清單記在工作階段（或長期節點的加入紀錄）上，之後可以加減：加一個空間＝補送那個空間的快照；拿掉一個＝那台裝置上那個空間的資料收回，照到期的同一套做法。快照、修改包、對帳三處用同一份清單過濾，不各寫各的。
- **範圍的單位是空間。** 第一版不做「只分享一則筆記」：比空間小的範圍會被連結、標籤、引用牽連（[傳到手機提案](send-to-phone-2026-11-12.md)已標為難點）。要給別人一則筆記，把它放進一個專門的空間。
- **個人空間（只有我）預設不帶出去**，要明確勾選。
- **工作階段只能縮小、不能放大**本人或該角色原有的權限。
- **撤銷只對之後有效**（2026-11-12 決定）：結束工作階段後，已經複製到對方的內容收不回來；畫面照實說。
- 每個空間的成員清單同時列出人、AI、正在連著的工作階段，各有「結束」。AI「它可以做什麼」的設定（PR #1705 第 8 節）是這張清單的 AI 那一列，不另成一套。

## 4. 連線模式

同一套配對、同一個碰面點，三種模式。使用者不必懂名稱；畫面只問「手機要不要一直開著」。

| | 即時來賓 | 臨時節點 | 長期節點 |
|---|---|---|---|
| 對方存不存資料 | 不存；每個操作送到主持節點 | 存一份（限定空間），在記憶體 | 存全部 |
| 主持節點要不要在線 | 要。主持是網頁時，手機畫面要亮著；是 App 或伺服器時不必 | 傳完就不必；修改包經碰面點暫存，之後取回 | 不必 |
| 合併 | 沒有第二份資料，不需要 | 需要（來源標記、修改包、合併規則） | 需要 |
| 依賴 | 不依賴分散式基礎 | S5（#1684）之後的幾步：收下別台的標記、修改包、限定範圍的對帳 | 同左（PR #1702） |
| 適合 | 共編；陌生電腦（手機放在旁邊亮著） | 陌生電腦（手機收起來）；網路不穩 | 自己的第二台裝置 |
| 斷線時 | 來賓的輸入留在記憶體，接回後補送；太久就結束 | 照常工作 | 照常工作 |

主持節點可以是任何一種：瀏覽器版（受「網頁不在畫面上會被暫停」限制）、桌面版、自架伺服器、之後內嵌後端的手機 App。協定相同，差別只在能不能在背景繼續服務。

配合業主現況的一種主持方式（**要業主同意**，第 10 節）：手機是連到 VPS 的網頁時，手機當轉手的人：陌生電腦 → 碰面點 → 手機 → Tailscale → VPS。VPS 發一把這次專用、有範圍、會過期的鑰匙；VPS 不對外，只有手機連得到它。

通道：兩邊都只能往外連，所以跨網路一定要碰面點（介紹、即時轉送、暫存三件事；STUN 只回答位址，別家的免費中繼各只做一部分）。能直連時走瀏覽器內建的直連當快速通道，是之後的優化，不是條件；校園網路常打不通。

### 4.1 即時共編不是第四種模式，是即時來賓上面的一層

連線模式回答「資料放在哪」；共編演算法回答「好幾個人同時打同一則筆記的字，順序怎麼定」。兩件事各自獨立：

| 情形 | 資料在哪 | 同一則筆記的字怎麼合 | 狀態 |
|---|---|---|---|
| 好幾個畫面同時在線、打同一則 | 只在主持節點（其他是即時來賓） | **主持節點排序**：`@codemirror/collab`，晚到的修改以主持的順序重排；游標另外做 | 2026-11-02 決定先用它；實驗在 PR #1440（未合併）：伺服器上的房間替發起人主持，兩人的字、游標、選取、注音組字、短暫斷線重連都做了，確認過的修改合成一般的內文儲存；本機量到單鍵中位數約 181 ms |
| 各自離線改過、之後才合 | 兩邊各一份（臨時節點、長期節點） | **內文合併**：現在是 `mergeBody`（合併規則第 2 版：以行為單位，同一句兩邊都改就問人）；候選的升級是自己寫的 Eg-walker（字元層級、不需要誰當裁判；仍然在同一句重疊時算衝突） | 現行的已上線；Eg-walker 量過速度（200 KB、每邊 1,000 次修改約 31–34 ms，約 8 KB），計畫先在旁邊影子執行、與現行結果比對，業主同意才切換 |

- 需要裁判的演算法只能用在有主持的即時模式；不需要裁判的才適合離線後再合。所以兩種都要，不是二選一。
- 即時共編的結果由主持節點存成一般的內文修改，再照分散式同步流到其他節點；逐字的打字過程不外傳（除非之後 Eg-walker 需要，那時修改包要多帶編輯紀錄）。
- 2026-11-02 業主另說想直接試 Eg-walker，結論是**一個合併引擎可以替換的即時共編實驗**：先接 `@codemirror/collab`，同一個實驗裡換成 Eg-walker 比較。PR #1440 做了前半（沒有做引擎 B）。它回來審查前業主定的三個條件：共編通道帶裝置編號與協定版本檢查、審查已要求的修正（開關打開時的遺失更新、`@codemirror/state` 升版）、房間的儲存在分散式規則下算誰的寫入。這份提案的回答是第三點：算**主持節點**的寫入，按作者分段。
- **主持離開時**：2026-11-02 想的是「最早加入的人接手」。這只在接手的人**自己也有那份資料**時成立；即時來賓不存資料，所以主持離開＝工作階段暫停，回來再繼續。要換手，接手的一方必須是節點（臨時或長期）。
- 之後可以混用：臨時節點在主持在線時，對正在編輯的那一則改走即時（看得到游標），主持離線就退回各改各的、之後合併。不在前幾批。

## 5. 工作階段怎麼縮小範圍：兩種設計

「你本人，但這次只帶這幾個空間」現在沒有對應的東西：AI 的鑰匙能到哪些空間，是照 AI 自己的成員資格，鑰匙上沒有空間清單。

| | A：鑰匙上帶空間清單 | B：每個工作階段是一個臨時的參與者 |
|---|---|---|
| 做法 | `TokenScope` 多一個 `spaces`（空間 → 看／提建議／改）；讀取與寫入的判斷都與它取交集 | 建一個臨時參與者，把它加進選定的空間；它記著「替誰」（比照鑰匙的 `issuedBy`） |
| 權限判斷 | 每個判斷點都要記得取交集；漏一處就是洩漏 | 完全沿用現有的成員資格判斷，沒有新的判斷點 |
| 同步的範圍 | 要另外教同步「這把鑰匙只讀這些空間」 | 同步本來就照參與者的可讀範圍送，直接適用 |
| 歷史裡寫誰 | 你本人 | 臨時參與者；顯示成「你（臨時）」 |
| 結束 | 撤銷鑰匙 | 撤銷鑰匙並把臨時參與者移出空間 |
| 代價 | 判斷點多、要有守門測試確保每個讀取入口都看清單 | 多一種參與者；個人資料（偏好、複習進度）要決定跟不跟著本人 |

**建議 B。** 它不新增權限的判斷方式，而「只送對方讀得到的」「撤權後重新核對」這些已經為多人做好的機制，對臨時節點直接成立。來賓（別人）本來就要是一個參與者，所以 B 讓「你自己的臨時工作階段」與「別人的來賓」是同一種東西，只差「替誰」。

介面草稿（只寫形狀）：

```ts
// 由一個已登入的人，在自己有權限的空間範圍內，開一個工作階段。回傳配對用的邀請。
openSession(actor: ActorCtx, opts: {
  spaces: { spaceId: Uuid; permission: "view" | "suggest" | "edit" }[];   // 不得超過 actor 自己的權限
  mode: "live" | "temporary-node" | "device";
  expiresAt: Date | null;                                                  // device 才可以是 null
  for: "self" | { guestName: string };                                     // 自己的另一個畫面，或一位來賓
}): Promise<{ sessionId: Uuid; invite: string }>;

// 任何時候由開的人或空間的管理者結束；之後這個工作階段的任何請求都被拒絕。
endSession(actor: ActorCtx, sessionId: Uuid): Promise<void>;
```

呼叫範例（手機掃到陌生電腦的 QR 之後）：

```ts
const { invite } = await openSession(me, {
  spaces: [{ spaceId: classNotes, permission: "edit" }],
  mode: "live", expiresAt: inHours(3), for: "self",
});
await pairing.accept(scanned, invite);   // 既有的配對；六位數確認後才生效
```

## 7. 安全

沿用且不變：配對與加密只經 `@onden/pairing`，**不自己寫密碼學**；六位數由交出資料的一方確認，確認前不送任何資料；碰面點只看得到密文、大小、時間、來源位址。

這份提案新增的要求：

- **陌生電腦不可信。** 你在上面看到與輸入的東西，那台電腦都看得到，技術上擋不住；開工作階段的畫面要直接寫出來。它拿不到沒選的空間。
- **主持節點對每個請求照工作階段的權限重新判斷**，不相信來賓送來的任何身分或範圍。臨時節點送回的修改包只能動它被允許的空間，其餘整包拒收。
- **來賓看不到別的空間存在。** 見第 8 節第 1 點。
- 來賓與陌生電腦的工作階段：有次數與大小上限、到期自動結束、手機上看得到並可結束。
- 版本不同就不連（2026-11-12「升級不考慮新舊並存」）。

兩個既有的關卡不變：碰面點 `onden-relay` 要在**獨立審查通過且業主明確同意**後才重新部署；**真實筆記不得經過通道**直到業主說可以。即時通道是比傳一次檔案更大的用途，要重新審查。VPS 與 Onden 伺服器維持只走 Tailscale。

## 8. 要先查清楚的風險

1. **標籤名稱是全工作區共用的。** 現在任何成員都看得到所有標籤的名字（`spaceScopeSql`：標籤定義不分空間）。對成員沒問題；對來賓等於洩漏其他空間的標籤名稱。要列出所有「不分空間」的資料（標籤定義、成員名單、工作區設定、搜尋、歷史、收件匣、功能清單），逐項決定來賓看不看得到。沒查。
2. **個人資料跟不跟著本人。** 設計 B 下，你在陌生電腦上的偏好、複習進度、已讀，是臨時參與者的還是你的。建議：讀你的、不寫回（陌生電腦上不留個人設定）。
3. **AI 在來賓的工作階段裡。** 來賓能不能叫 AI、AI 讀得到什麼。建議第一版：來賓不能叫 AI。
4. **附件與手寫。** 大檔案經即時通道的速度與碰面點的額度（免費方案每天 10 萬次請求，2026-11-13 實測傳 192 MiB 可行）；即時模式每個操作都是一次往返，額度夠不夠沒量。
5. **主持是網頁時的保持喚醒。** 「保持螢幕不關」在業主的手機瀏覽器上是否正常、醒來後通道能否接回，沒測。
6. **同一個人兩個畫面同時改同一則**（手機與陌生電腦）：即時模式下等同兩個分頁，走現有的內文合併；同時打字要等共編那一層。
