# 提案：標籤不擁有功能，功能把標籤當範圍

> 狀態：歷史紀錄（寫於 2026-11-13；現行規則見 [tag-as-scope-2026-11-13.md](tag-as-scope-2026-11-13.md)）

> 2026-11-13。**設計提案**；只寫文件，不含程式。業主同日確認第 9 節三點（「其他按建議」）。
> 上層文件：[功能引用第三批的補充](function-refs-b3-2026-11-12.md) 第 7 節（標籤不再掛功能；標籤層的行為之後從頭設計）。本文是那個「從頭設計」的出發點。

## 1. 一句話

**一樣東西是不是任務、是不是複習卡，只看它自己；標籤只用來挑出「這個標籤底下的那些」。**

- 所有權：功能型的引用只記在筆記或段落上（第三批之後就是這樣）。
- 範圍：任何功能都可以拿一個標籤（或一棵樹、一個空間）當範圍，列出、統計或操作範圍內已經有這個功能的東西。
- 標籤上不因此記任何東西。標籤仍然只帶欄位與檢視。

## 2. 和被拿掉的做法差在哪

| | 標籤持有功能（已拿掉） | 標籤當範圍（本提案） |
|---|---|---|
| 誰決定「這是卡片／任務」 | 標籤：掛上就變 | 筆記或段落自己 |
| 要不要事先設定 | 要先替標籤加功能 | 不用，任何標籤隨時可用 |
| 拿掉標籤時 | 那些卡片、任務要不要留，說不清楚 | 沒有影響，只是不再被這個範圍挑到 |
| 多出來的資料 | 標籤上的一筆引用，要同步、要處理衝突 | 沒有；範圍是查詢 |

## 3. 為什麼值得定下來

- **所有權只有一處。** 之前的麻煩（整則筆記因為標籤變成任務、複習卡跟著標籤來去）都來自兩處都能決定。
- **對分散式同步友善。** 範圍不產生資料，[來源標記](causal-stamps-2026-11-12.md)要處理的東西不會變多。
- **使用者不用學「加功能」。** 標籤頁上看到的每一塊，都是「某個功能 × 這個標籤當範圍」。
- **和筆記型軟體的主流一致。** Logseq、RemNote、Obsidian 的複習外掛都是卡片屬於內容，標籤或頁面只是挑選範圍（2026-11-13 的調查）。

## 4. 現況：已經有一半

- 複習的後端已經接受範圍：`GET /api/review/queue` 與 `/stats` 有 `root`（一棵樹）與 `tag_id`；個人的複習設定也已經以標籤為鍵存在功能這一邊（`/api/review/settings/:tagId`）。
- 標籤頁已經有「任務」分頁，本來就是這個模式。
- 缺的是：一個看得到的入口、所有功能共用的「範圍」定義，以及把這條規則寫下來。

## 5. 範圍的定義（所有功能共用一份）

要先定、而且只能有一個實作，不能各功能各寫各的：

1. **標籤範圍**含不含子標籤底下的東西。建議：含（和標籤頁現在列筆記的規則相同）。
2. **含不含筆記底下的段落與子筆記。** 建議：筆記掛著標籤，它的段落就算在範圍內；子筆記不算，除非自己也掛著（2026-11-09 已決定段落不繼承標籤，這裡不改那個決定，只是「範圍」往下看到段落）。
3. **樹範圍**＝這則筆記與它底下所有子筆記、段落。
4. 垃圾桶裡的、對這個人不可見的，一律不在範圍內。

動工前要盤點現有的實作（前端 `lib/treeWalk.ts`、`lib/tagTree.ts`，後端 `services/nodeTree.ts`、`services/tagHierarchy.ts`，以及各功能自己的查詢），收成前後端各一個入口。

## 6. 這條規則做不到的事

- **「掛上標籤就自動變成某種東西」沒有了。** 想把 #單字 底下的筆記都變成卡片，用一次性的動作：在標籤頁對範圍內的筆記批次「設成複習卡」。做完之後標籤再怎麼變都不影響它們；之後新掛上的筆記不會自動變。
  若之後真的需要持續的規則，那是「自動化」的題目，另外設計，不回到標籤持有功能。
- **每個標籤的個別設定**（例如這個標籤的卡片每天最多幾張）記在功能那邊、以標籤為鍵，不記在標籤節點上。標籤刪除時由功能清掉自己的那一筆。

## 7. 各功能套用後的樣子

| 功能 | 以標籤為範圍 | 現況 |
|---|---|---|
| 複習 | 「複習這裡的卡片（N 張）」：不看到期日也能整個練一遍 | 後端有，缺入口 |
| 任務 | 這個標籤底下的任務 | 已有分頁 |
| 月曆／時間軸 | 這個標籤底下有日期的東西 | 檢視，已是這個模式 |
| 搜尋 | 只搜這個標籤底下 | 動工前確認 |
| AI | 以這個標籤底下的內容為上下文 | 未做 |
| 發布 | 以空間為單位（2026-11-10 的決定），不因本提案改變 | — |

## 8. 建議的做法

1. **複習當試點**（設計見[複習加強](review-strengthen-2026-11-13.md)）：標籤頁與筆記頁各一個看得到的入口（沒有卡片時不顯示），同時把第 5 節的共用範圍做出來。這一步併在複習加強的工作裡。
3. 任務、AI 等之後逐一對齊，不排期。
4. 定案後更新[功能引用表](function-references-2026-11-02.md)第 3、9 節。

2. 標籤範圍含子標籤，往下看到段落、不看子筆記（第 5 節）。
3. 以「批次設成複習卡」這種一次性動作取代「掛上就自動變」。
