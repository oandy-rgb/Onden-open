## 一句話

月曆、看板、卡片三種版面各是一個**視圖模組**。標籤在「＋ 加入功能」選擇它（背後是繼承 `#月曆` 等模組標籤），
並在加入時給**參數**（例如用哪個日期欄位）。參數存在這個標籤自己的視圖上，同一個標籤可以有好幾個視圖。
清單與表格是內建版面，不用引入。

用函式庫的說法：

```
calendar(#書,  date_field = 讀完日期)
calendar(#會議, date_field = 開會時間)
cards(#書, filter = 評分 = 5)
```

模組是函式，加入功能是呼叫，參數跟著呼叫的地方（`#書`），模組自己的設定（例如一週從哪天開始）存在模組標籤（`#月曆`）。

## 使用者看到的樣子

### 單一標籤頁

```
#書
功能                                              [＋ 加入功能]
┌ 複習：依複習排程回顧這些筆記。 [開始複習] [設定] [移除] ┐
欄位   作者 · 讀完日期 · 評分                          [編輯欄位]

┌ 全部 ┬ 月曆 ┬ 五星好書 ┐                         [＋ 視圖]
（目前分頁的內容：全部 = 成員表格，取代 TagMemberTable）
▸ 進階 …
```

- 分頁列取代「Saved views」按鈕。第一個分頁「全部」固定存在，是內建的表格版面。
- 「＋ 視圖」是捷徑，打開的就是「＋ 加入功能」的「視圖」那一組。
- 分頁的小選單：改名、改參數、刪除。從別的標籤繼承來的分頁標「經由 #書」，只能看，可以「複製成自己的」。

### 「＋ 加入功能」選單分兩組

```
功能   複習 · 稍後讀 · 文獻引用 …
視圖   月曆（依日期欄位排在月曆上） · 看板（依欄位分欄） · 卡片（有封面的格狀卡片）
```

選了視圖後問參數，只問必要的：

| 視圖 | 參數 | 預設 |
|---|---|---|
| 月曆 | 日期欄位 | 第一個 `date` 型別欄位；沒有就提示先新增日期欄位，或用「建立時間／修改時間」 |
| 看板 | 分欄欄位 | 第一個選項（select）欄位 |
| 卡片 | 封面欄位（可不選） | 第一個圖片欄位 |

模組還沒引入時，選單註明「加入時會一併引入」，與現有功能相同。

### 模組標籤頁：總月曆

打開 `#月曆` 看到所有加了月曆的標籤的筆記合在一起，每則筆記依它所屬標籤的日期欄位擺放。
一則筆記同時屬於兩個有月曆的標籤時，各出現一次（Tana 的做法相同）。
`#月曆` 頁另有模組設定（一週開始於週一或週日）。

## 規則

1. **能力**：標籤 T 的某個視圖能顯示，條件是 T 的 `effective_modules` 含該版面的模組，且工作區已引入。
   不符合時視圖資料保留，分頁顯示「月曆模組未引入」或不顯示，與其他模組的「停用保留資料」一致。
2. **內建版面**：list、table 不是模組，任何標籤都能用，不需要引入。
3. **參數存在呼叫的標籤**：每個視圖仍是 `collection_views` 的一筆。月曆的日期欄位存在
   `layout_config.date_field`，看板沿用 `group_by`，卡片存在 `layout_config.cover_field`。
4. **有能力、沒有視圖是合法狀態**：加入月曆功能後若還沒有月曆視圖（建立中斷、被刪除），
   功能卡顯示「選擇日期欄位」來建立，而不是錯誤。這樣「繼承模組標籤」與「建立視圖」兩次寫入不需要包成一個交易。
5. **繼承**：`#小說` 繼承 `#書`，就得到月曆能力，且 `#書` 的視圖出現在 `#小說` 頁，套用在 `#小說` 的成員上，標「經由 #書」。
   要改參數就「複製成自己的」；不做逐欄覆寫，避免「哪個參數是誰的」的隱藏知識。
   這條需要欄位繼承（2b），否則 `#小說` 不一定有 `讀完日期` 欄位。
6. **視圖模組標籤不貼在筆記上**：`#月曆` 只用來被繼承。標籤選擇器不列出它，伺服器拒絕把它直接貼到筆記
   （回應說明「月曆是視圖功能，請在標籤頁加入」）。
7. **權限**：與現在相同。新增、修改、刪除視圖與繼承都是標籤管理者的操作；其他人可以看、切換分頁，
   切換只存在自己的瀏覽器（目前的分頁、月曆的月份）。

## 資料怎麼存

- **不加新表、不改 `collection_views` 的格式**。只多使用 `layout_config` 的 `date_field`、`cover_field` 兩個鍵。
- **模組**：後端 `modules/calendar`、`modules/kanban`、`modules/gallery`，各自只有 `library`（`inUse`）
  與模組標籤；前端各一個 `FrontendModule`，`tagFunction` 多一個 `kind: "view"` 讓選單分組，
  以及加入時要問的參數表單。
  三個模組共用一份程式（`components/collections/`），模組目錄只放登記與參數表單，避免三份重複。
- **舊資料**：開機的 library 回填已會依 `inUse` 引入模組。視圖模組的 `inUse` = 工作區有任何 `collection_views`
  的 layout 是該版面。另外補一次性回填：有該版面視圖的標籤加上 `extends` 到模組標籤，
  使用者原本的月曆、看板不會消失。

## 設計比較（AGENTS.md：新公共介面先比較兩種）

| | A：視圖只是分頁（Notion 式） | B：視圖模組（建議） | C：視圖掛在任何節點（Tana 式） |
|---|---|---|---|
| 呼叫範例 | `POST /api/tags/書/views {layout:"calendar", layout_config:{date_field:"讀完日期"}}` | `PUT /api/tags/書/extends [#月曆]`，再 `POST /api/tags/書/views {…}`（同 A） | `POST /api/nodes/:id/views {…}`，來源可以是子節點、標籤成員或查詢 |
| 使用者要學 | 「功能」與「視圖」兩套入口 | 只有「加入功能」 | 視圖、搜尋節點、來源三個新概念 |
| 隱藏知識 | 少 | 版面能不能用取決於繼承鏈 | 視圖的來源規則 |
| 改動範圍 | 只有前端分頁 | 前端分頁＋三個登記用的模組＋回填 | 後端查詢模型、同步、權限都要改 |
| 相容成本 | 無 | 回填舊視圖的引入與繼承 | 大，現有 `collection_views` 要搬家 |
| 得到的額外東西 | — | 總月曆（`#月曆` 頁）、繼承視圖、未引入時入口全隱藏 | 跨標籤查詢、筆記內嵌視圖 |

選 B：與模組庫一致，使用者只學一個動作；成本只比 A 多登記與回填。C 的好處（跨標籤查詢、內嵌）留待之後，
B 不擋 C：之後若做 C，標籤頁的分頁就是「來源 = 標籤成員」的特例。

## 不在這次範圍

- 個人視圖（每個人自己的篩選、排序並可「存給所有人」）。
- 筆記內的 `onden-base`／`onden-query` 區塊改用同一套視圖（目前在前端自行計算，與後端 `executeView` 規則不同）。
- 網站模組的 `CollectionsManager` 列表。
- 任務議程、Today lens、白板：它們不是「一個標籤的成員列表」，維持獨立。
- 週視圖、拖曳改日期。

## 追加決定（2026-10-17～18）

查過 Obsidian Bases、ClickUp、Notion、Airtable 後（使用者：「按建議」）：

1. **檢視模組不做功能卡，只是分頁。** 「＋ 檢視」列出內建的表格／清單與已引入的檢視模組；加一個月曆分頁＝標籤自動繼承 `#月曆`，
   刪掉最後一個月曆分頁＝自動取消繼承。使用者看不到 `#月曆`。這取代上面「＋ 加入功能」分「功能／檢視」兩組的做法：
   「＋ 加入功能」只放行為類功能。前例：Obsidian 外掛註冊的檢視類型出現在檢視選單，選項存在該檢視；ClickUp 的功能開關（ClickApps）
   與「+ View」是兩套。
2. **月曆、看板、卡片預設引入**（`importedByDefault`，像白板），擁有者可在 設定 › 模組 取消。Notion、Airtable、ClickUp 的月曆與看板都不需要先安裝；
   之後社群寫的新檢視（時間軸、地圖）才需手動引入。
3. **用詞維持「檢視」**（Microsoft 台灣、Notion 繁中皆用「檢視」；「視圖」多為簡中）。版面名稱維持月曆／看板／卡片。
4. 引入與使用分開：模組庫搬到 設定 › 模組（[module-library.md](module-library.md)「引入與使用分開」）。

## V3 月曆修正（2026-10-18，已實作）

- 「+N more」是按鈕：在當天格子裡展開全部，「收合」收回（GAP-157 的「第 4 筆以後無法開啟」）。
- 月份記住：每個檢視記住移到的月份（`PREFS.calendarMonths`，只存在這台裝置）；按「今天」就忘掉，沒動過的月曆一直跟著當月。
  **與上面「分階段」的差異**：原訂「月份記在網址」，但網址由 `locationToSearch` 正規化、每次狀態改變都重寫（只帶 view／node／lens），
  加參數要改整套網址模型；記在裝置與分頁的記法一致，重新載入同樣回到原月份。
- 舊月曆檢視可以改日期欄位：檢視的「⋯」選單多「日期欄位…」（卡片是「封面…」），可選日期欄位、建立／最後編輯日期或「自動」；
  存回 `layout_config`，必要時把欄位加進 `visible_fields`。看板的分欄照舊在工具列。
- 別人改了資料（其他裝置、成員、代理）時，開著的檢視重新查詢（`useLiveRefetch("changed")`，合併自己的回音；分頁回到前景也重查）——GAP-158。
- 390px：月曆格線改 `minmax(0, 1fr)`，長標題不再撐寬某一天（GAP-157）。

## 拿掉列表、表格也是檢視模組（2026-10-18，已實作）

- 使用者：「拿掉列表，只留表格」。表格做得到列表能做的（含分組），兩者重複。migration 111 把已存的列表檢視原地轉成表格
  （順序、篩選、排序、分組都保留；正式站有 2 個）；`services/tagViews.ts` 收到 `list`（舊客戶端、舊事件還原）一律當 `table`，
  前端讀到也當表格顯示。
- 使用者：「表格我想做標籤」。表格改成檢視模組（`modules/table`），跟月曆、看板、卡片一樣預設引入、可在 設定 › 模組 取消；
  migration 111 也把 `table` 加進已記錄清單的工作區。不再有內建版面：「＋ 檢視」只列已引入的檢視模組，都沒引入時說明去哪裡引入。
  標籤頁的「全部」分頁是另一個成員列表（不是表格版面），不受影響。
- 「是標籤」的部分跟其他檢視模組一樣在 V4：加分頁時繼承 `#表格`，`#表格` 頁列出所有用表格的標籤的筆記。
- 模組 id `table` 也是筆記子樹 Table lens 的名稱，所以模組邊界測試把它跟 `canvas` 一樣列為例外。（Table lens 已在「檢視的來源」一節拿掉。）

## V4 檢視模組是標籤、繼承的檢視、總覽頁（2026-10-18，已實作）

前提「欄位繼承 2b」與「禁止同名欄位」已上線（#353，module-library.md）。

- **檢視模組標籤**：表格、看板、月曆、卡片四個模組各有模組標籤 `#表格`、`#看板`、`#月曆`、`#卡片`（`library.moduleTag`）。
  標籤有某種版面的檢視時就延伸（`extends`）該模組標籤：加第一個月曆分頁＝延伸 `#月曆`，刪掉最後一個（或改成別的版面）＝取消。
  由 `services/viewModules.ts` `syncViewModuleExtends` 在建立、修改版面、刪除檢視時維護；其他 `extends` 保留。使用者不必管它：
  標籤頁的「功能」不列出檢視模組標籤（2026-11-01 起沒有「舊的繼承」區塊）。Notion 匯入若由非擁有者執行，延伸留給之後的檢視修改。
- **回填**：migration 113 為舊檢視建立（或收養同名頂層標籤成為）模組標籤並加上延伸；可重複執行。正式站只有 #gt 一個表格檢視。
- **規則 6**：檢視模組標籤不能貼在筆記上。直接加標籤回 409 `view_module_tag`（「這是檢視用的標籤…」）；匯入、訂閱、範本遇到時略過；
  合併標籤的任一端是它也拒絕。標題下的「＋ 標籤」不列出它們。
- **繼承的檢視（規則 5）**：子標籤列出上層（`parent_id`，任意深度）與舊的標籤↔標籤 `extends` 的檢視，排在自己的之後，
  標「經由 #書」，套用在子標籤自己的筆記上。只能看：沒有 ⋯ 選單、版面切換、篩選；經子標籤改或刪回 404。
  「複製成自己的」用同樣設定建立一個自己的檢視（重名時加編號）。模組標籤（功能、檢視）不傳下檢視：功能是組合，不是繼承。
- **總覽頁**：打開 `#月曆` 看到所有延伸它的標籤（看得到的）用各自第一個月曆檢視、各自的日期欄位排在同一個月曆上；
  同一則筆記同一天只出現一次。`#表格`、`#看板`、`#卡片` 每個標籤一段，標題是標籤（點了開該標籤頁）。
  API `GET /api/tags/:id/aggregate`；前端 `components/collections/ViewModuleAggregate.tsx`，標籤頁遇到檢視模組標籤時取代成員列表。

**與上面的差異**：總覽頁不另設模組設定（「一週開始於」未做）；「＋ 視圖 打開加入功能的視圖組」已由 V2 的「＋ 檢視」取代。

## 檢視的來源：標籤成員或子筆記（2026-10-19，已實作）

使用者：「表格鏡頭也跟著「表格」模組」，再來「兩種表格變成同一個東西」。一則筆記的子筆記和一個標籤的成員都是「一組筆記」，
所以兩者用同一套檢視：同樣的分頁、同樣的檢視模組（`VIEW_MODULES`）、同樣的 `CollectionView`／`renderLayout`。
上面設計比較的 C（視圖掛在任何節點）只做「來源 = 子筆記」這一半；跨標籤查詢、筆記內嵌仍不在範圍。

**模型**：檢視存在擁有它的節點的 `content_nodes.collection_views`（欄位本來就在每一列上）。擁有者的種類決定來源：

| 擁有者 | 來源（exec 的列） | API | 誰能新增、改、刪 |
|---|---|---|---|
| 標籤（`class_tag`） | 標籤成員（`memberTagIds`：子標籤、延伸它的標籤） | `/api/tags/:id/views…`（不變） | 標籤管理者（principal admin） |
| 一般筆記 | 它的子筆記（`parent_id` = 這則筆記；不含隱藏列、系統列） | `/api/nodes/:id/views…` | 能編輯這則筆記的人（authority `node`／`write_node`） |

兩種都只回讀得到的列（`readableNodeIdSet`），看不到擁有者時回 404。不需要 migration、不改 `collection_views` 的格式；
筆記檢視的元素用 `node_id`（標籤檢視是 `tag_id`）。

**規則**：
- 版面的模組規則相同：建立或改成未引入的檢視模組回 409 `module_not_imported`；已存的檢視保留，分頁顯示「未匯入」說明。
- 筆記檢視沒有繼承（規則 5 只在標籤之間），也不延伸檢視模組標籤（`#表格` 等總覽頁只收標籤的檢視）。
- 欄位：子筆記帶的標籤的欄位（各標籤的 effective fields，同名取第一個）給型別與看板分欄順序；
  「＋ 檢視」的欄位是子筆記共有的欄位（標籤欄位與屬性，兩則以上都有；只有一則子筆記時就是它的），沒有就只有標題與更新時間。
- 事件：沿用 `COLLECTION_VIEW_CREATED/UPDATED/DELETED`，但 target 是那則筆記（`target_type = node`），
  所以只有讀得到那則筆記的人看得到（標籤檢視的事件是全體成員看得到的標籤定義）。payload 帶 `node_id`、`view_id`。
- 改筆記的檢視不更新筆記的 `updated_at`：檢視是呈現方式，不是內容（不打亂「最近」排序，也不碰內文儲存的版本判斷）。
  這些事件也不算「修改」：列的 `last_modified_at`／`last_actor`／`recent_actors` 與當天回顧的「代理動過」都略過 `COLLECTION_VIEW_*`
  （`nodeRowProjection.ts` `NOT_A_NOTE_CHANGE_SQL`）。標籤檢視的事件 target 是檢視本身，本來就不算。
- 備份（`backupArchive`）的筆記附帶 `views`，與標籤一樣；還原目前不帶回檢視（標籤也是）。

**介面**：
- 筆記的「表格」鏡頭拿掉，鏡頭剩 內容／白板／歷史。有子筆記的筆記在 內容 頁、內文下方有「子筆記」一段：
  第一個分頁「全部」是子筆記清單（從本機資料，離線也能看；有共有欄位時用與標籤頁「全部」相同的成員表格），
  之後是這則筆記的檢視分頁與「＋ 檢視」，和標籤頁一樣。「上層與子筆記」關係區只留上層。
- 只能看的人（不能編輯這則筆記）看得到、切換得到檢視，沒有「＋ 檢視」與 ⋯ 選單。
- 在檢視裡快速新增的列是這則筆記的子筆記（標籤檢視是貼上那個標籤）。
- 設定 › 模組：每個檢視模組的說明加一句「有子筆記的筆記也能用」。

**同步與離線**：檢視（標籤的、筆記的）都不在 bootstrap 與同步裡，打開時向伺服器讀；執行也在伺服器。
離線時「全部」分頁照常（本機資料），已存的檢視顯示讀取失敗、建立與刪除會說需要連線、修改會排隊——與標籤頁相同。
舊的表格鏡頭本來就只是本機子筆記清單，「全部」分頁保有它的離線能力。

## 參考

- Tana：supertag 頁預設是分頁，第一頁是全部成員的表格；視圖設定個人化，可「Save for everyone」；
  月曆讀每個子節點的日期欄位，沒有日期的另列。
  [Views](https://outliner.tana.inc/learn/features/views)、[Supertags](https://outliner.tana.inc/learn/features/supertags)
- Trilium：版面與月曆設定都是筆記上的標籤（`#viewType`、`#calendar:*`），最接近「視圖也是標籤」。
  [Calendar](https://docs.triliumnotes.org/user-guide/collections/calendar)
- Notion、Obsidian Bases：預設一個視圖，在頁面上「＋／Add view」新增，每個視圖各自的篩選與排序。
  [Notion views](https://developers.notion.com/guides/data-apis/working-with-views)、[Bases views](https://obsidian.md/help/bases/views)
- 漸進揭露：預設隱藏進階功能可降低學習負擔，風險是找不到，需在頁面上留明顯入口（本設計的「＋ 視圖」）。
  [UX Tigers](https://uxtigers.com/post/progressive-disclosure)
