# 網站、工作區與筆記歷史的寫入邊界

> 狀態：歷史紀錄（寫於 2026-11-01；現況見程式與 domain-writes.md）

這一批延續 `domain-writes.md`。公開介面表達使用者的意圖，畫面不用組裝
API、離線佇列、本機資料更新和錯誤回復。

| 模組 | 公開操作 | 隱藏的責任 |
| --- | --- | --- |
| `workspaceWriter` | `setHome / saveDesign` | 首頁、設定與共用版型的樂觀更新、逐欄位回復、SQLite 副本、持久化確認 |
| `websiteWriter` | 頁面建立／隱藏／改名、保存設定／版型／內容、發佈 | 組合筆記與工作區領域，為網站提供一致的結果與錯誤契約 |
| `noteHistoryWriter` | `restoreVersion / undelete` | 需要伺服器計算的版本還原、恢復子樹後讀取、避免舊回應覆蓋較新的欄位 |

`websiteWriter` 是組合入口，並不重做 `noteWriter` 的保存邏輯。共用生命週期仍在
`writeLifecycle`；介面需要等操作完成才清除表單或執行下一步。

## 自動保存與發佈

`autosave` 是內部排程器，以設定、共用版型、每個頁面各自作為 debounce key。
同一頁的新草稿取代尚未送出的草稿，不會取消另一頁的保存。關閉／隱藏頁面及卸載時
flush，並沿用 keepalive 與同步恢復副本。永久拒絕保留最新輸入，顯示可手動重試的狀態；
網路失敗由共用持久化佇列負責，不再另外每 5 秒無限重試。

網站設定只 PATCH 使用者改過的 key。晚到的 bootstrap 補齊尚未編輯的設定，
不會把使用者改過的品牌蓋掉，也不會拿預設值覆蓋伺服器上未讀到的其他欄位。

共用版型經既有 `/api/workspace/config` 的 `chrome` 保存，新增 `studio_draft: true`
辨別真正的編輯草稿。舊安裝的 intro chrome 沒有此標記，仍優先載入最後發佈的版型，
避免把已發佈的設計退回初始範本。刻意清空的新版型也是有效草稿。

`onlineWrite` 用於必須取得伺服器計算結果的操作。發佈與版本還原需要連線，且先完成待同步變更；
同一請求的回應遺失後重試沿用 idempotency key。這是執行環境內的重試記錄，並非跨重開的
完整發佈恢復協定。發佈先 flush 草稿，失敗不繼續。發佈成功但後續讀取失敗時，保持已發佈狀態。

## 歷史與部分成功

版本還原按欄位合併並更新本機筆記，不蓋掉等待回應期間的新欄位修改。
編輯器只在仍停留同一筆記且草稿未再改動時採用還原結果。
取消刪除若僅進入佇列，提示「連線後恢復」；伺服器已接受但重新讀取失敗，不能把它當作寫入失敗。

文字擷取成筆記組合 `noteWriter.create` 與 `tagWriter.apply`，兩步都等待確認。
如果筆記已建立但標籤被拒絕，回傳既有筆記並說明未完成的標籤，讓引用能指向已建立的內容。
不會因為標籤失敗而把整次建立當作失敗，誘發重複建立。

`WriteActionError` 表示需要使用者處理的領域前提，例如版本還原需要連線。
它和 HTTP／儲存錯誤共用訊息與去重入口，避免被誤譯成一般網路問題。

## 本機儲存與手機介面

`workspaceMirror` 保存首頁、site_config 和 chrome，同時保留 actor_role。
`localDbSchema` 是冷啟動與匯入舊資料庫共用的 schema 準備流程；先升級候選資料庫再取代現有實例。
Worker 的 RPC 入口會等待同一次初始化，避免同步或 lazy 載入的呼叫者先碰到尚未建立的 SQLite。
初始化失敗會回報給等待者，後續操作可重試，不自行形成無限重試迴圈。

網站手機分頁的 CSS 移回 WebsiteStudio，發布站台的 lazy stylesheet 不再蓋掉它。
手機可切換頁面／設計／編輯／預覽；清單與編輯區不會同時搶高度。網站使用完整工作區，
不再插入與目前網站頁面無關的筆記檢視窗。長標題省略、觸控刪除按鈕保持可見，
高度採用 dynamic viewport，保留底部導覽與安全區。

## 驗證與限制

回歸涵蓋持久化確認等待、儲存失敗保留意圖、連續拒絕、不同欄位保留、發佈重試 key、
版本還原競態、部分成功、表單輸入保留、Enter 重複提交、跨頁 debounce、關閉頁面 flush、
初始化並行／重試，以及真實 sql.js 升級與匯出重開。

最終前端回歸：167 個測試檔、1,173 項測試通過；`tsc --noEmit`、ESLint、
Astro production build 通過。建置仍有既有的大型 chunk 與空 docs collection 提示。

瀏覽器使用既有隔離帳號、隔離 PostgreSQL，桌面 1280 × 900、手機 viewport 390 × 844：

- 桌面修改品牌為「網站領域保存驗證」，共用版型改為 Personal Blog，確認保存提示。
- 網路中斷後保存簡介；手機離線新增「手機離線網站頁面」。
- 離線冷啟動確認簡介、版型與頁面保留，再在手機離線設定首頁與修改簡介。
- 恢復連線後直接查隔離 PostgreSQL，確認頁面與工作區設定、`studio_draft` 和 4 個版型區塊。
- 檢查手機頁面／設計分頁及無水平溢出；保存提示保持在頂欄下方。

手機測試為 viewport，沒有涵蓋 iOS／Android 真機程序回收。未執行對外發佈；發佈成功／失敗
與後續刷新失敗的分支透過測試驗證。自動保存的 debounce 視窗仍依靠 pagehide／visibilitychange
flush，不能保證作業系統無事件強制終止的最後幾百毫秒。

RSS 文章與重點擷取仍是下一個獨立領域：既有分步 save → create → edge 流程涉及部分成功，
另一裝置先保存同一篇文章時也可能回傳不同父節點 ID。應先設計伺服器的原子操作或明確的
ID 對應協定，再遷移依賴它的離線操作。這一批沒有把它包成薄函式後宣稱問題已解決。
標籤 schema／合併、權限、匯入等其他流程也仍需後續整理。
