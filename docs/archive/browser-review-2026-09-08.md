# Onden 瀏覽器與前端檢查 — 2026-09-08

> 狀態：歷史紀錄（最後確認 2026-11-01）

## 判斷

對個人使用的資工學生而言，把課程筆記、任務、連結與複習留在同一份資料裡，是合理而且已有實際用途的方向。這次可以走通「寫課程筆記 → 加標籤 → 建集合 → 排入複習 → 連結另一篇筆記」的流程。

目前主要弱點是介面與資料操作的一致性。功能很多，但共用樣式曾依賴延遲載入的元件；同一種標籤在不同頁面使用不同計數方式；手機仍有桌面工具列擠在一起的情形。這些問題比新增更多視圖更影響日常使用。網站編輯、白板與規則設定也比單纯捕捉、閱讀、任務更需要較大的操作空間。

下一階段應以一週真實課業流程作為驗收：上課記錄、課後整理、作業提醒、考前複習。每個流程都要能在重新整理、斷線與儲存失敗後保住資料。AI 可以負責實作，但產品設計者需要掌握這些流程的資料如何保存、失敗時如何恢復，以及修改如何被驗證；這次發現的 PATCH 預設值與 IndexedDB 錯誤傳遞，就是適合深入理解的兩個案例。

## 測試環境

- 真實 Astro 前端、production 模式後端，另建 PostgreSQL 測試環境，包含 AGE、PGroonga、vector。
- 瀏覽器資料和後端整合測試使用不同資料庫，避免測試清除正在操作的資料。
- 使用合成帳號及測試筆記，未對外發布網站。AI 和 embedding 使用 stub；RSS 是公開 RFC feed 的真實抓取。
- 主要尺寸為 1280×900、390×844，另外檢查 320×740 與 768×1024。這是瀏覽器視窗尺寸測試，不能代替 iOS／Android 實機、觸控筆、虛擬鍵盤和 Capacitor 測試。
- 瀏覽器檔案選擇器有明顯工具延遲。單檔圖片上傳成功；資料夾匯入 UI 的完整路徑未確認，改用同一測試服務的 API 驗證匯入與匯出。

## 待修與未覆蓋

1. **重複匯入會再建立同名資料夾。** 筆記身分能保留，但 folder group 尚未使用穩定路徑去重；已由 API 結果、側欄及 import route 確認，這輪未修改。
2. 手機複雜頁面仍有較高資訊密度，部分提示只有英文。這輪集中修正實際出現的重疊、溢出、對比與字級，不代表已全面完成無障礙與翻譯檢查。
3. 任務原生日期／時間欄位的工具 fill 沒有完成 React 儲存驗證；順延按鈕路徑成功。需以實際點選器或實機再驗證，尚不能直接判定產品錯誤。
4. PDF 註記、手寫筆壓、草圖完整操作、瀏覽器備份還原、原生檔案系統、跨帳號切換、真實 AI、外部發布及所有權限角色組合，未完成瀏覽器逐項驗證。後端自動測試的覆蓋不能替代這些使用流程。

這是一輪涵蓋主要流程的修復與測試，並非「所有功能、所有装置皆無問題」的保證。
