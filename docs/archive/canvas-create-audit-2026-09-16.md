# 白板新建卡片與共用筆記實測（2026-09-16）

> 狀態：歷史紀錄（最後確認 2026-11-01）

對應 CAN-01、CAN-02、UX-01；延續[白板卡片操作](canvas-card-actions-audit-2026-09-16.md)。本批以「建立筆記後加入原白板，保留等待期間的新布局」為主要案例，並補兩張白板共用筆記及冷啟動讀取。不是完整白板功能驗收。

## 重現與修正

- **GAP-35：點空白處會關掉 editor 裡的白板。** 空白點擊原本將 selected ID 清成 null，白板因此卸載；320px 手機退回筆記列表，也可能使雙擊的第一下就中斷建立。現在只取消卡片選取，editor 內保留白板 ID；其他 lens 保持原語意。
- **GAP-36：延遲建立會覆蓋較新的擺放。** 實際將 POST `/api/nodes` 延遲約 8 秒，等待期間透過 picker 加入首頁筆記；建立完成後，晚到 callback 使用開始時的 nodes 快照保存，剛加入的首頁卡片消失。現在 `placeCanvasNode(canvasId, nodeId, position?)` 在追加時使用 writer 最新的本機布局，保留其他卡片、尺寸、顏色和 sections。雙擊、工具列、右鍵新建共用建立 handler，既有筆記 picker 及快速建立的追加也使用同一 writer。
- **GAP-37：未快取白板的冷啟動不補載。** 新白板 B 在本機無布局副本；啟動先讀本機時得到 null，之後上線的核對只看 activeCanvas，因此沒有目標可讀，手機停在「此裝置沒有這張白板的副本」。writer 現在保留選取目標，既有 `refreshOpenCanvas()` 可補讀尚無副本的選取；明確取消或切換後不復活舊目標。

GAP-36 是擺放資料被覆蓋，沒有刪除筆記本體。第一次重現時 sections 曾短暫不顯示，但 API 中仍存在，後續同步重新顯示；不能把這段觀察寫成伺服器分組遺失。

## 方案與責任

追加介面比較兩種方式：

1. 每個 UI 在 `await createNode()` 後讀最新 store、判重、算位置、合併整份布局，再呼叫 `saveCanvasData()`。呼叫者仍須理解快照、切換白板、載入等待及保存確認，各入口容易漏一項。
2. 呼叫 `await placeCanvasNode(originCanvasId, note.id, { x, y })`，或省略位置以追加到右側。writer 擁有最新布局、必要的快取讀取、判重、預設位置及既有寫入生命週期；UI 明確保留開始操作時的白板 ID。

選第二種。重複擺放保留原幾何；相同板／筆記的進行中追加共用 Promise，包括拒絕，不能因樂觀畫面已有卡片就提前宣布成功。讀快取跨越新編輯時再次讀目前布局，讀取期間白板已被移除就拒絕並保留筆記。成功代表伺服器接受或佇列已持久化，並非一律已同步。

快速建立原本取得 identity-stable 的 addToActiveCanvas callback，等待後可能指向新開啟的白板；現在建立流程取得捕捉原白板 ID 的 callback。writer 不負責切換 UI。拖放圖片等仍以整份布局保存的舊路徑未在本批全部遷移，不能宣稱所有新增卡片入口已具備相同行為。

補載亦比較在 Builder 的 online effect 重試，以及 writer 保留讀取目標。選後者，沿用現有同步核對、寫入排序、selection ticket 及 revision；不為手機和桌面各加讀取例外。建立／移除白板的成功、回復與明確取消同時維護這個目標。

CUA 操作 `127.0.0.1:5100`、真實隔離 PostgreSQL `onden_import_audit_test`。使用者明確授權將既有測試帳號 A 暫時 viewer → editor；只改該測試角色。正常 API 完成新建與核對；測完已恢復 viewer，bootstrap 再確認 role=viewer。正式帳號未變更。

## 自動回歸與限制

- 新增 writer 8 案：保留較新布局／分組、同時追加、重複等待與拒絕、已有擺放、不改目前白板、慢快取重查、白板移除及 durable queued 確認。
- 新增讀取 4 案：本機缺副本後上線補讀、補讀失敗重試、取消不復活、快速選取只補最新目標。
- 完整前端 **193 檔／1,440 項通過，0 跳過**。讀取意圖加入後，原同步整合測試有 3 案失敗，因 setup 只直接設定 activeCanvas；已改為經正式 `selectCanvas()` 開啟舊快照後再測同步，保留原拒絕／gate／晚到核對斷言。不是略過失敗案例。
- TypeScript、lint、正式 build 與 `git diff --check` 均通過；未重跑全後端。測試日誌在 `/tmp/onden-storage-live/canvas-create-*.log`，最終 API 結果為 `canvas-create-final-data.json` 與 `canvas-create-golden-check.log`。
- CAN-02 仍為「部分」：跨分頁／跨裝置整份布局競爭、不同操作一拒一允的相依快照、筆記建立加擺放的離線重播／跨重載冪等、全部快速建立與右鍵入口的瀏覽器回歸仍缺。writer 新增操作只組合本機追加，沒有新增後端原子建立、CAS 或跨分頁合併協定。
- 建立成功而擺放拒絕仍顯示共用保存錯誤；本批核對資料有保留，尚未提供完整「部分完成／重新擺放」導引，不宣稱這個使用者回饋已完整驗收。
- CAN-04 的群組建立、折疊、搬移及 undo 仍未盤；本批只核對其他操作不破壞已有分組。
