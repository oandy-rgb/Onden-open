## 已確認的缺陷與修復

| 缺口 | 修前證據 | 修正 |
| --- | --- | --- |
| GAP-39 | 分組根節點含 `nodrag`，實際拖標題旁及背景均不移動；幾何 helper 預設 240×120 與布局 260×200 不同，重疊分組計數也只算首次歸屬 | 背景可拖，文字輸入保留 nodrag；`sectionCarry` 共用儲存幾何，計數、搬移與復原成員使用同一集合 |
| GAP-40 | 搬分組同時把成員各自壓入 undo stack；兩次移動後第二次 Ctrl+Z 沒有回到起點。舊 undo 在保存結果之前移除紀錄 | 一個分組或批次位置手勢只記一筆；完整等待接受，拒絕保留重試，進行中停用重複操作；手機有固定大小的復原入口 |
| GAP-41 | 分組左上角縮放從 (365,147) 拉向左上，API 只由 400×280 變 420×300，原點仍 (365,147)，放開後跳回；卡片有相同 callback 缺漏 | 兩個縮放入口都傳完整 CanvasBounds，保存 x／y／width／height；縮放分組不搬動卡片 |
| GAP-42 | 框選兩張卡片後拖多選框，只有回呼的主卡片保存位置；另一張回原處 | 讀取拖曳事件的全部卡片，以既有 applyCanvasPositions 一次保存；多選、對齊與排版的復原同樣走批次保存 |

GAP-39 的拖動為實際 UI 重現；預設尺寸與重疊計數另有程式及回歸證據。
群組是幾何框，不是 parent-child 容器；重疊框可共享卡片，搬其中一框不搬另一框本身。

## 方案與責任

復原比較逐卡呼叫保存，以及「原分組位置＋原成員位置」的一次操作。選後者：
`restoreSectionPosition(sectionId, x, y, members)` 只復原該手勢的原成員座標，
保留後來新增的卡片、不重建已移除的卡片，保留標題、尺寸、顏色與其他分組。
UI 不在 undo 時重新推算幾何成員，也不逐卡拼接保存。

`useCanvasUndo` 擁有記憶體歷史、等待與紀錄移除；領域 callback 保留 Promise，
既有 canvas writer 負責樂觀回復、離線落盤與提交。拒絕經共用錯誤邊界只通知一次。
晚到接受只移除原紀錄，不能吃掉後來的操作或另一白板的歷史。
批次拖動直接使用已存在的 `applyCanvasPositions`，沒有建立另一個多卡 writer。

縮放比較在舊介面加可選座標，以及以完整矩形為必要參數。選後者：
`handleNodeResized(id, { x, y, width, height })` 與分組相同。元件傳畫布座標，領域統一取整數、
保存完整矩形；呼叫端不用分辨左邊／右邊把手或拆成移動加尺寸兩次寫入。

## 回歸與限制

本批回歸涵蓋一手勢一紀錄、拒絕後重試、進行中防重複、晚到結果、切板、
原成員新增／移除、完整縮放矩形、折疊卡片幾何與重疊／篩選後的分組成員。
最終完整前端 **193 檔／1,451 項通過，0 跳過**，TypeScript、lint、Astro build、diff check 通過。
新增 11 項回歸；未重跑全後端，未更改後端。日誌位於 `/tmp/onden-group-audit/`。

- 分組顏色可存在資料格式，但沒有前端選色入口；沒有使用者可切換的分組折疊。
  低縮放的摘要顯示是自動 LOD，不能稱為已驗證手動折疊。
- Undo 僅在本頁記憶體內，切板／重載清空；沒有 redo、縮放 undo 或跨裝置持久歷史。
- 原拖動在提交前記錄位置，正向保存遭拒絕仍可能留一筆無位移的 undo；此處不宣稱已完整處理。
- 本批當時尚缺完整對齊／分配、snap、手機多選；後續補驗與修正見 [第三十一批](canvas-alignment-audit-2026-09-16.md)。
  混合拖動後續見 [第三十二批](canvas-mixed-drag-audit-2026-09-16.md)；真實樹狀階層及真機仍待驗。
- 縮小後的分組標題與縮放把手仍可能難以觸控；尚未提供分組的固定大小編輯面板。
- 舊布局保存仍是完整快照；其他分頁／裝置的並行修改與離線相依拒絕不在本批已驗範圍。
