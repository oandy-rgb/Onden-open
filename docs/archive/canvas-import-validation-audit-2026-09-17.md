## 完成條件與設計

無效的已映射內容須在第一筆 API 寫入前拒絕；不能用重複 ID 改變卡片與連線歸屬，
不能把連線保存失敗當作匯入成功；同一錯誤只通知一次，檔案可重新選取。

比較兩個方案：保留逐筆略過並在各處補檢查，或先完整解析已支援的資料再開始建立。
選擇後者：`fromJsonCanvas` 負責格式與支援範圍，匯入操作只使用 cards／sections／links。
UI 區分讀檔、格式及提交失敗；不讓 UI 知道哪些 malformed 節點會被略過、ID 怎麼覆蓋或連線如何漏掉。

[JSON Canvas 1.0 規格](https://jsoncanvas.org/spec/1.0/)將 nodes／edges 設為可選陣列；
節點有唯一 ID、四種型別及整數位置／尺寸，文字、檔案和 URL 各有對應欄位。
因此空物件可解析為空白板，但錯誤陣列型別、缺少必要欄位、重複 ID 和不存在的端點會拒絕。
正尺寸及 JavaScript 安全整數是 Onden 的額外限制，不宣稱是標準對正數的要求。

- 驗證全部卡片與邊後才返回。錯誤包含如 `nodes[1].width` 的輸入位置，不回傳正文。
- 分組端點目前沒有對應的 Onden 關聯操作，改成明確拒絕整次輸入；這是相容行為收緊，原本會默默丟線。
- 筆記標題遵循既有 500 字元限制；長 URL／檔案路徑僅截短顯示標題，正文保留完整引用與 subpath。
  外部檔案引用只是文字，不讀取外部檔案，也不自動下載媒體。
- 連線 API 的失敗不再 `.catch(() => null)`。失敗往上回報，停止後續步驟，不自動重試整批。
- UI 移除 alert，沿用共用通知。讀檔及 JSON 失敗在提交之前回報；格式拒絕指出位置。
  其他錯誤提示可能已有內容建立；writer 已回饋的同一錯誤仍去重，不另發第二則通知。
