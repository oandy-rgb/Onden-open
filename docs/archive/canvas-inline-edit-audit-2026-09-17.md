## 已重現的問題

### GAP-50：剛輸入就匯出仍得到舊正文

1280px 瀏覽器雙擊共用卡片，將原文加上「0917 即刻匯出驗證：這行必須出現在檔案。」後立即點匯出。
真實下載 `(5).canvas` 不含新行，預覽先回舊正文，約一秒後才顯示新字。
修正前元件回歸也確認 blur 後 writer 呼叫次數為 0；不是只憑程式碼推測。

原因是 CodeMirror updateListener 只啟動一秒計時器，blur 立即卸載編輯器，沒有同步交接輸入。
該計時器未隨卸載清理；快速重開會從尚未更新的 props 取舊文，Promise 拒絕也沒有在卡片消化。

比較只為匯出增加草稿讀取與統一卡片交接後，選擇後者。`useCardDraft` 集中輸入、停頓、flush、拒絕與明確重試；
卡片只接編輯器事件和顯示狀態，不重寫網路分類、離線佇列或通知。blur、取消選取、卸載、pagehide 和 Mod-S 共用 flush。
預覽與重開使用最新草稿；writer 接受前保留，晚到接受／拒絕不覆蓋更新的輸入。
task checkbox 也走相同的交接。標題仍是原有獨立保存入口，本批沒有將其算入正文驗收。

### GAP-51：已開始的保存不在退出保護內

首次補上卡片 pagehide 後，實際立即重載仍回到前一版本，正文和復原面板都找不到「0917 立即重載驗證」。
不能以 hook 的 pagehide 測試通過宣稱退出可靠。
進一步以實際 note writer 和延遲 mirror 重現：普通保存已開始、仍在等待 mirror 時觸發 pagehide，沒有復原副本。
此缺口證據與瀏覽器症狀一致，但瀏覽器沒有取得足以唯一判定內部排程的 trace，兩者分開記錄。

`writeLifecycle` 現在於等待 lane／mirror 前登記進行中請求，`writeRecovery` 在 pagehide 才保存未確認副本。
原冪等鍵保留；一般輸入不閃出復原面板。接受後立即解除保護，即使提交後 mirror 尚未完成，也不再新增假未提交副本。
這沿用現有 recovery，沒有第二套傳送、授權或冪等協定。
