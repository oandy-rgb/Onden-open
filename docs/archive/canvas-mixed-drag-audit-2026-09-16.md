## 重現與邊界決定

GAP-46：桌面 1280×800 框選三張卡片與兩個重疊分組，拖動選取框。
修前 API 僅內框和共用卡片移動 (23,19)，外框及另外兩張卡片完全未保存位移。
原因是 drag stop 依 React Flow 回報的主節點種類分支，分組分支只處理其中一組。

比較「依序呼叫每個分組的搬動」與「一手勢的位置集合」，採後者。
前者要多次保存、共享成員可能重複移動，復原也必須知道組間重疊；後者明確保存一次操作的固定集合。

- `captureCanvasPositions(data, cardIds, sectionIds)` 擁有選取卡片與所選分組原成員的聯集。
  幾何依完整儲存布局判定；篩選、聚焦與顯示密度不能漏掉原成員，重疊與明確選取去重。
- KnowledgeWorkspace 擷取手勢起點與該集合，結束時只套用一次位移。
  單卡、單組、混合選取共用 `onApplyPositions(nodes, sections)`；取消、跨白板或零位移不寫入。
- `applyCanvasPositions` 在現有布局合併座標並一次呼叫既有 writer，保留尺寸、顏色、文字等欄位。
  不重建已移除卡片，不移動後來新增的成員；目標分組已不存在時整筆拒絕。
- `useCanvasUndo` 只理解一份卡片／分組位置集合，不再理解拖曳事件及三種復原 callback。
  移除舊 `handleSectionDragged`／`restoreSectionPosition`／`carryCardsWithSection` 和顯示節點的
  `memberPositions`；原成員知識不必同時維護在布局產生器、手勢與復原三處。

沒有新增 writer、權限判定、錯誤分類或持久化協定。全域關係圖沒有 active canvas 的分支仍沿用原節點位置寫入，
不能據此宣稱該分支已具有白板的一次保存契約。
