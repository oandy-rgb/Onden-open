# 白板開啟與筆記切換（2026-09-30）

> 狀態：歷史紀錄（最後確認 2026-11-01）

起點 `32b68bb`。使用者反映白板啟動不直覺、切去其他筆記有異常。
本批完整案例是「明確開啟一張白板，只操作該板；選側欄筆記即可回到正文」。

## 問題與責任

- 白板節點被當成普通筆記，開白板檢視時只查它是否放在另一張板上，導致既有白板被誤判尚未建立。
- 側欄開筆記與板內選卡片混用 lens 記憶和 sticky board，選筆記仍可能留在白板。
- 選 B 時 GET 尚未完成或被拒絕，`activeCanvas` 仍是 A，畫面及保存 callback 仍可能作用於 A。

比較在各個拖曳 callback 補 ID 檢查，與讓 canvas writer 在選取時立即撤下舊的可編輯畫面。
選後者：`select(B)` 立即移除 A，既有 selection ticket 阻擋舊讀取覆蓋新的選擇；
拒絕或離線缺快取時不退回 A。已持久化布局仍從 mirror 讀取，尚未確認的輸入保留在原白板，
離開再回來不被較舊快取覆蓋。沒有改變服務端白板授權或保存事件。

白板 node 的身分優先於它在別張板上的位置。顯式導覽至筆記與板內卡片選取
必須區分意圖，前者回到正文並清除舊白板選擇，後者保留當前畫面。
全域白板入口與沒有現成白板的畫面，提供明確的開啟／新增操作；
檢視本身不建立資料，從子筆記建立仍是獨立操作。
「更多 → 白板」固定回到白板清單，不隨目前選取的節點改變語意；
側欄選 canvas node 仍直接開啟該節點自己的白板。

新增白板完成後，只在該白板仍是目前作用中選擇時收起建立畫面；
等待期間重新開啟白板清單或改選別張板，較舊的建立回應不能改掉後來的導覽。
同次建立尚未完成時停用再次新增，保存仍由原有 canvas writer 確認。
直接新增確認後也保存白板的網址；只有作用中白板仍是該次結果，且選取未被
較晚的卡片選取取代時才更新位置。這與清單選板共用位置更新，不額外讀取白板。

白板清單直接使用白板選取操作，不先要求同 ID 的 node 已出現在筆記投影。
這讓離線新建、或伺服器已保存但同步投影尚未追上的白板也能重新開啟。
從清單選板仍把白板 ID 保存於既有 `node` 網址及 `canvas` lens，
只在顯示清單時清空選取。否則 URL 與 resume 設定會失去白板身分，
重載轉而開啟今日／首頁。顯式選板與 canvas-node effect 共用這次選取意圖，
不因同步稍後補上同 ID 的 node 而重複啟動相同讀取；未新增另一套網址格式。
明確選中 canvas node 才啟動它的筆記內白板；資訊欄的第一筆筆記 fallback
不能在清除選取、開啟白板清單時偷偷重新開板。沒有新增本機節點或繞過後端讀取授權。

實際截圖另抓到同一個 fallback 仍把第一筆筆記放入白板的資訊欄，甚至可編輯其標籤／父層。
白板的資訊欄與版本頁尾現只使用真正選中的節點，未選卡片時顯示原有空態；
其他檢視的預設筆記選擇不變。

## 驗證

環境使用獨立 `onden_test`、隔離 owner／無額外 tag scope、單一 headless Chromium worker。
延遲／403 注入只攔截本輪建立的 B 白板；等待時嘗試操作 A 的原位置，
同時核對沒有 A 的 PATCH／DELETE 請求，且伺服器 A 布局未變。
這驗證選取與畫面歸屬，不代表新增服務端權限政策測試。

修改前新增六個單元回歸均失敗；原 23 案通過。
初輪修正後與標籤相關測試合跑 14 檔 152 案通過。
最終隔離 Chromium 整組 16 案通過、0 失敗／略過（3.0 分鐘），其中白板十案。
包含五項既有板／卡片／子板操作、viewport 恢復，以及本批四項新導覽案例。
新增瀏覽器回歸覆蓋「建立回應延遲時重新開清單」及「離線建立、改名、
從清單重新開啟、重連後確認保存」，全部已執行通過。
選板後的網址與重載回歸涵蓋既有白板，以及離線新板重連後的同板恢復；
離線新增也在尚未重開清單前核對網址，避免只靠後續選板補上位置。
上述網址及重載斷言已通過；1280／390／320px 深色 chooser 無水平溢出，
實際截圖已人工目視確認，資訊欄未選取時沒有不相關筆記的可寫欄位。
證據同置 `.acceptance/tag-operations-2026-09-30/`，只操作隔離 `onden_test`。
