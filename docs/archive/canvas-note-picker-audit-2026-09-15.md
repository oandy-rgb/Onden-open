# 白板加入筆記：選單與保存回饋

> 狀態：歷史紀錄（最後確認 2026-11-01）

日期：2026-09-15。對應 CAN-02、UX-01；本批是加入既有筆記的完整小流程，不代表 CAN-02 全部驗收。

## 範圍與設計

不變條件：已在白板上的卡片不能再次被推薦加入；保存等待、拒絕和接受須有不同呈現；手機可閱讀、可點擊；加入／移除擺放不修改筆記正文。

比較兩種方案：

| 方案 | 呼叫與需要理解的知識 | 相容成本 |
| --- | --- | --- |
| 在 KnowledgeWorkspace 繼續加入搜尋、pending、catch 和重置狀態 | 工作區須同時理解圖表過濾、完整成員、請求生命週期 | 少一個檔案，但卡片布局與表單狀態繼續混在一起 |
| CanvasNotePicker 擁有候選與表單生命週期 | `onAdd(id): Promise` 表達等待保存；`onAdded(id)` 僅在接受後發出 | Builder 傳原有 async 操作，取消此入口的 backgroundWrite 包裝 |

選擇後者。成員來自 activeCanvas 的完整資料，不從 displayGraphNodes 推論。writer、佇列、授權與錯誤分類沿用既有邊界；沒有新增保存協定。

## 已重現與修正（GAP-32）

- 20 張卡片的白板開啟「只看這張卡片與相鄰關係」，只顯示 3 張時，搜尋第 20 張仍把它列成可加入；點擊後原有 addToActiveCanvas 判重直接返回，使用者看不到結果。現在從完整白板成員排除，搜尋回「沒有符合的筆記」。
- 320×740 時，原選單 left 57／right 317，白板可用右界約 304；選單 top 138.5 與工具列 bottom 174.5 重疊。12 筆 flex 結果被壓成約 23.3px 高。現在選單 left 13／right 292、top 184.5；與工具列相隔 10px，列至少 44px、不再收縮，長標題可換行。
- 原加入 callback 回傳 void，選單無法等待。現在送出時顯示「加入中」、停用候選以防重複送出；接受後才關閉、清除白板搜尋並選取新卡片，利用既有置中閱讀機制。
- 拒絕保留搜尋與選單，沿用 reportWriteFailure 避免重複通知。關閉／離開白板後晚到的完成不再導航；Escape 和關閉鈕回到工具列焦點。

自動核准審查拒絕了暫時提升既有測試帳號角色的腳本，以及額外輸出兩筆測試筆記全文的命令；兩者均未執行。改用現有角色、既有 fixture 與擺放 metadata 核對。新建成功及多白板獨立性尚未補驗，不能用單一白板的結果替代。

原 20 筆正文 SHA-256 為 `e687664ef7c003ea7d59420b2293591cdc463dc99f086dc89f3876745abe4776`；布局原始排序可能不同，核對按 nodeId 進行。

## 新發現但本批未修（GAP-33）

一次加入先持久化到離線佇列，重載後 PATCH 被注入 403 拒絕；復原面板增加 1 筆（8→9），伺服器仍是原 20 張卡片。重新開啟白板，本機卻仍顯示遭拒的第 21 張卡片，並因此從加入清單排除。

程式對照：canvas layout 不走一般 node sync；refreshCanvasList 只更新 metadata 並保留本機布局。冷啟動先讀本機，後續上線／重播拒絕沒有為該布局建立完整重新核對契約。舊的不存在筆記擺放也會留在本機布局，雖然伺服器位置同步略過不存在 ID。

下一批應在既有 canvas writer／讀取邊界處理布局調和及待同步保護，避免在 picker 裡猜測並刪除成員。尚未驗證後續整份保存會否重新帶回其他遭拒擺放、跨分頁競態及新筆記建立等待期間的布局覆蓋；不能宣稱只刷新一次就解決。

手機移除目前只有右鍵選單線索，尚未完成真實觸控長按／替代入口驗證。本輪手機 viewport 不等於真機鍵盤、安全區與觸控驗收。
