# 白板編輯可讀性盤點（2026-09-17）

> 狀態：歷史紀錄（最後確認 2026-11-01）

案例 CAN-06，維持部分。沿用隔離 UI 5100、測試白板 B 與 viewer A；沒有升權、管理員驗證或正式部署。
本批驗收：低倍率總覽進入卡片編輯後文字可讀，窄畫面不裁切，視窗尺寸改變仍能閱讀，儲存幾何與正文不受顯示修正影響。

## 問題與設計選擇

GAP-52 的原始症狀在第三十五批實測：手機總覽放大至約 0.558 後雙擊編輯，文字仍跟著整張白板縮小。
全域手機 contenteditable 最小字級為 16px，畫布 transform 後約 8.9px；只看 CardNode 主題的 12.5px 會算錯，前批文件已更正。

比較兩個方案：

- 反向放大編輯字體：不移動畫面，但卡片仍可能在視窗外，需要同步處理高度、工具列與寬度，且閱讀和操作比例不同。
- 開始編輯才置中並放大到至少 1 倍：一般瀏覽保持總覽，只有明確進入編輯時調整鏡頭；既有更大倍率保留。

選擇第二個。`GraphCallbacksContext.onNodeEditStart(nodeId)` 由 KnowledgeWorkspace 處理鏡頭，回傳釋放函式。
CardNode 以編輯生命週期呼叫和釋放，不了解 React Flow 的鏡頭排程；雙擊選字不重新啟動。
CSS 只限制手機編輯內層的可見寬度，包含既有放大倍率，外層儲存尺寸不變；編輯時隱藏縮放與連線把手。
沒有新增 Builder callback、保存選項或另一套文字寫入。

第一次實作仍有缺口：從 320 改成 390px 時，編輯卡片左側變為 x=-12.5，因為鏡頭仍停留舊中心。
實際截圖確認裁切後，將白板容器的 ResizeObserver 納入編輯生命週期；尺寸改變等下一 frame 再置中，結束編輯即解除。
普通內容更新、雙擊選字或不變的容器尺寸不重新置中。

## 回歸與剩餘限制

回歸涵蓋低倍率放大、保留更大倍率、選取 effect 不蓋回舊鏡頭、幾何不變、未知／分組節點忽略、
容器 resize 下一 frame 置中、相同尺寸忽略及退出取消 observer／frame；真實 CodeMirror 元件測試確認退出／卸載釋放追蹤。
