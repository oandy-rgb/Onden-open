## 結果與設計

GAP-01 已重新實測並修正：新匯入與能唯一辨識的舊資料夾，重匯時沿用 ID，
不再每次建立空的同名群組。現存多份同名舊匯入樹仍需整理，程式會拒絕歧義，沒有自動清理。

| 發現 | 修正／目前結果 |
| --- | --- |
| 筆記按 `_import_path` 重用，但資料夾一律新建 | 資料夾來源路徑由領域操作集中解析；結果分成新建、沿用與略過 |
| 父層建立失敗後筆記落到根目錄 | 無可用父層就略過該子樹，不改變檔案歸屬 |
| 同名筆記可能把剛建立的資料夾當成舊筆記，覆寫資料夾正文 | 舊筆記標題 fallback 排除有匯入資料夾建立紀錄的節點 |
| 查找與寫入不在同一把鎖內，並行上傳可能重建相同筆記／資料夾 | 在單筆事件交易內完成查找與寫入；相同路徑並行測試只建立一份 |
| 匯入沒有核對沿用父層目前的 read／write_node 與 scope | 資料夾解析和筆記寫入都核對父層；撤權後略過，不繞過限制 |
| `file.text()`／`arrayBuffer()` 例外在 catch 外，畫面卡在讀取中 | 讀檔失敗進入明確錯誤狀態，可重新選擇同一批檔案；尚未發出上傳 |
| 匯入完成後清單刷新失敗也被當作匯入失敗 | 保留已完成結果，提示重新整理 |
| 結果省略集合資料列略過量，資料夾數不能分辨建立／沿用 | 補上計數並翻譯本段中文回饋；檔案數不再顯示為筆記數 |
| 通用輸入框寬度套到 checkbox，中文標籤被擠成直排 | checkbox 固定 16px，整個 label 提供至少 44px 高操作區；同列可換行 |

比較的兩種草圖：

1. 在 route 的資料夾迴圈加入「同名、同父層就沿用」。改動較少，但仍會誤用使用者自己建立的筆記，
   而路由需要同時理解資料夾來源、舊匯入相容、授權、交易與結果。
2. `importObsidianFolders({ actor, workspaceId, paths, reuse })` 封裝來源辨識、相容查找、授權和交易。
   選擇此方案，沿用 `node_attributes`，沒有新增資料表或通用匯入框架。

呼叫者取得 `ids` 與 `created/reused/skipped`；某路徑沒有 ID 代表必須略過，不能當成根節點。
內部以 `_import_folder_path` 加建立事件 `ui_context=import.obsidian.folder` 辨識來源。
唯一舊資料夾依名稱、父層及建立紀錄補內部索引；原名、正文、父層與權限不被修改。
此索引是內部來源辨識，不是同步游標、授權或可讓客戶端自選的能力。

這次減少的是 **route 對資料夾來源與生命週期的理解負擔**，不是單純搬出長函式。
route 仍擁有 Markdown、媒體與 CSV 的編排；沒有宣稱整個匯入領域已完成深模組重構。

## 尚未處理，不能算重匯安全

| 邊界 | 證據與影響 |
| --- | --- |
| 圖片沒有去重 | 實際 API 連續匯入完全相同 SVG＋Markdown：第一次 `imported=1, images_imported=1`；第二次 `updated=1, unchanged=0, images_imported=1, folders_reused=1`。圖片重新落盤並改寫 URL，未改文字也被視為更新。登錄 GAP-09 |
| 相同檔名的不同圖片 | 來源閱讀確認目前仍按 basename 建表，同名檔案最後一份勝出；不同目錄的圖片可能連錯。本批未做檔案內容比對驗收 |
| 多個 vault／不同來源 | 目前只有去除根資料夾後的相對路徑，沒有獨立來源身分。不同 vault 同路徑可能互相覆蓋 |
| 舊筆記標題 fallback／較新編輯 | 除已排除資料夾外，仍沿用舊 slug fallback，沒有三方合併、來源雜湊或覆蓋預覽；手動同名筆記仍可能成為候選。UI 已說明會取代 Onden 裡的修改 |
| 檔案改名／移動 | 路徑仍是檔案身分，沒有跨路徑追蹤；資料夾已在 Onden 移動則拒絕。無法宣稱同步式的重新命名支援 |
| 舊重複群組 | 不自動刪除或合併，避免移動使用者後續內容；多候選略過並回報 |
| CSV／Notion 重複匯入 | 仍走既有新建集合流程；本批僅跑既有 CSV 回歸，沒有完成 DATA-01 的完整 Notion 案例 |
| 批次失敗／重送 | 每檔獨立提交，媒體先寫入；沒有整批持久化冪等／離線上傳。送出後失敗可能已有部分成功，必須先查看資料再重試 |
| 原生 picker／大檔 | 實際目錄選擇、取消、巢狀大 vault、特殊路徑、不合法 payload、混合壞檔與不同瀏覽器仍待驗 |

下一個匯入批次應先處理來源與媒體身分及覆蓋衝突；不能用繼續新增略過分支，掩蓋誤覆蓋的根因。
DATA-01／DATA-02 仍標「部分」，全功能清單總數與已盤數不因本批局部修正上調。
