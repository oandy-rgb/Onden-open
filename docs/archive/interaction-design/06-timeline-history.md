# Timeline / activity / history surface

> 狀態：歷史紀錄（最後確認 2026-11-01）

## Onden today

Onden surfaces temporal information through **three weakly-integrated frontend surfaces** backed by **two independent storage mechanisms** — a structure that is technically rich but conceptually fragmented.

**Storage (event-sourced spine):**

- `domain_events` — append-only log (enforced by migration 051). Every mutation that passes the spine `mutate()` gate writes a row carrying `actor_type`/`actor_id`, `event_type`, `target_type`/`target_id`, `payload`, `created_at`, `tx_meta` (tool_name/token_id/args for agent calls), an `external` flag (true for git/github side-effects that ran outside Postgres), and `triggered_by_event_id` (cause→effect parentage for dispatcher cascades). Workspace-scoped.
- `content_node_versions` — copy-on-write title/markdown snapshots. These are **not** written by route code; a Postgres trigger `capture_node_version` fires only when title/markdown actually change, linking each version row to the active mutation via `myapp.event_id` (migration 032). Migration 048 throttles capture per-actor. This table is now pure history — the old pending/merge/sandbox review queue was removed.

**Backend routes:** `GET /api/events` (filterable, workspace-scoped, id-cursor `since`, cap 500), `GET /api/events/:id/preview` + `POST /api/events/:id/restore` (event-level inverse-undo, emits a *new* event, cascade-aware; `NODE_PURGED` and `external` events are unrestorable), `GET /api/versions/recent` (workspace-wide changed feed), `GET /api/nodes/:id/versions` (per-node list), and `POST /api/nodes/:id/versions/:versionId/restore` (emits `NODE_RESTORED` — a *second, separate* restore path from event-restore).

**Frontend surfaces:**

1. **Timeline MODE** (`TimelineView.tsx`) — a co-equal 5th topbar peer mode alongside Notes / Tags / Tasks / Website (confirmed `AppTopbar.tsx` lines 49–61, also in `MobileNav`). Internally it splits *again* into a 3-tab strip: **Versions** (`/api/versions/recent`, day-grouped, old→current title diff, per-row restore, plus a Published-snapshots section and a "Snapshot" button that POSTs `/api/publish`) / **Events** (lazy `EventLogPanel`) / **Trash** (lazy `TrashView`).
2. **`EventLogPanel.tsx`** — the rich activity log. `useLiveEventLog` polls `/api/events?since=<lastId>` every 5s, pauses on hidden tab (Page Visibility), backs off to 30s on error, shows a Live/Paused indicator. Day-grouped, color-coded by type-prefix, actor filter (All / User / AI agent / System + an "Agent only" chip), per-event restore with preview modal, a separate cascade "+N" button when `triggered_by` children exist, and an expandable structured agent-call view (tool/token/args/result) for `tx_meta`-bearing events.
3. **`OverviewActivityPane.tsx`** (the inspector for a node selected in Notes mode) renders **two adjacent-but-distinct** per-node sections: a lazy "Recent Events" (`NodeEventHistory.tsx`, same hook scoped to `target_id`, 7s poll, relative time, restore+cascade) and a separate "Version History" section from `/api/nodes/:id/versions` with its own inline preview/restore.

**IA weaknesses:**

- **Timeline is a peer mode, not a lens.** It violates the thesis directly: temporal information should be a *lens on a node's maturity*, not a co-equal destination you navigate *away* to.
- **Three surfaces, two stores, two restore paths.** A node's history is split between "Recent Events" and "Version History" in the inspector, and *again* between the Timeline mode's Versions and Events tabs at the workspace level. The user must hold the events-vs-versions distinction in their head — an implementation leak, not a mental model.
- **No diff beyond title.** The Versions feed shows old→current *title* diffs only; there is no body/markdown diff anywhere, despite versions storing full markdown.
- **Restore semantics are doubled and divergent** (event-restore vs. version-restore), with different un-restorable rules and different emitted events.

## The gap

The field has converged on two principles Onden violates:

1. **History lives on the node and is reached in-context** — a modal (AFFiNE, Notion), an inline icon (Reflect, Obsidian), a per-note revision API/dialog (Trilium, source-verified), a CRDT-snapshot read on the open doc (AppFlowy, source-verified), or a query (Tana). Even SiYuan — which generates the *richest* file-level history of the vendored set — surfaces it as a per-doc history dialog, not a top-level peer destination. *Nobody ships a co-equal top-level "history mode."* Onden's Timeline peer mode is an outlier, and a thesis-violating one.
2. **One history, one renderer.** Anytype's standout move (source-verified) is that a historical diff replays through the *same* event protocol as live editing — there is no separate "history viewer." Joplin (source-verified) reinforces the storage half of this: it persists *deltas* (`diff-match-patch` patches), not full snapshots, which is structurally the same shape as Onden's `domain_events` (an event *is* a delta) — Onden already has the delta store Joplin had to build separately, yet it *also* keeps a parallel full-snapshot store. Onden has the opposite of the ideal: two stores (`domain_events` + `content_node_versions`), two restore paths (event-restore + version-restore), and three UI surfaces that each re-implement grouping and rendering.

Onden's *backend* is actually ahead of the field on the dimensions that matter most for its thesis: full actor attribution (user *and* agent), `tx_meta` agent-call provenance, cause→effect `triggered_by` cascades, and an `external` flag for un-undoable side-effects. No competitor models a human+agent collaboration this richly. The gap is **not capability — it is IA.** That capability is buried inside a fragmented, mode-switched, diff-less surface.

What is genuinely *missing*: a **body/markdown diff** (AFFiNE/Notion/Obsidian render full body diffs; Onden stores the markdown but never diffs it — note that SiYuan/Trilium, source-verified, store full historical *content* but their primary affordance is whole-snapshot restore, not an inline body diff, so the diff gap is narrower than "everyone has it") and a **unification of the two restore semantics**. Trilium's source-verified restore is instructive here: it is non-destructive (`saveRevision({source:"restore"})` *before* overwrite, `revisions.ts:136`), which is exactly Onden's `{as_new_node}` posture done as the default.

## Recommendation for Onden

**1. Kill the Timeline peer mode. Make history a lens on the node.** Per the thesis (node = home; canvas/graph/table/inbox/timeline are *lenses on a node's maturity*), there is no "Timeline mode" — there is a **timeline lens** you can point at any node, *and* at the workspace node. Reaching it should be an inline gesture on the node (à la Reflect's clock icon / AFFiNE's modal), not a destination in the topbar. Removing Timeline from `AppTopbar` lines 49–61 also advances the broader thesis goal of dissolving co-equal mode-switching.

**2. Collapse the two per-node sections into one in-context timeline lens.** In the inspector, "Recent Events" and "Version History" should be a single time-ordered stream. Events are the spine of truth; a version is just an event whose payload happened to change title/markdown — render it as an *expandable diff inline on its event*, not as a parallel list. This mirrors Anytype: one stream, one renderer, the diff expressed in the same vocabulary as the live edit.

**3. Add a body diff — it is the single biggest missing capability.** The markdown is already stored in `content_node_versions`. Surface an old→new markdown diff inline on the version-bearing event (CodeMirror 6 is already the editor per the editor decision; a read-only diff view fits the markdown-as-truth model). This closes the one real feature gap versus AFFiNE/Notion/Obsidian.

**4. The workspace-level timeline lens is just the node lens pointed at the workspace.** What is today the Timeline mode's Events tab becomes "the timeline lens on the workspace root" — a single `EventLogPanel`-style live feed with the existing actor/type filters. No separate Versions tab: a version is an event. Trash stays reachable but as a filter/state on the same stream (deleted nodes), not a third tab. This is also the natural surface for **tag=node** governance review — because a `class_tag` is itself a content node, its policy/schema changes appear in *its own* timeline lens, and an agent's tag-gated mutations are auditable in the same feed via `tx_meta`. The timeline lens becomes the human-readable face of the audit/governance story.

**5. Unify the two restore paths.** Event-restore (`POST /api/events/:id/restore`, cascade-aware, inverse-undo) is the more principled mechanism — it is itself logged, it handles cascades, and it honors `external`/`NODE_PURGED` un-restorability. Version-restore (`NODE_RESTORED`) should become a *thin specialization* of it (restore the event that produced this version), so there is one restore semantic and one set of rules. Preserve the `{as_new_node}` option — it matches Reflect's restore-as-copy *and*, source-verified, Trilium's non-destructive restore (`restoreRevision` snapshots the current state before overwriting, `revisions.ts:129-159`), and it fits the maturity loop (a restored past state can re-enter capture without clobbering convergence).

**6. Lean into the provenance edge.** Onden already has what no competitor has: actor-attributed, agent-aware, cause-tracing history. Make that the *headline* of the timeline lens — agent-call expansion (tool/token/args/result) and the `triggered_by` cascade "+N" affordance are differentiators. Keep and elevate them; they are the governance precondition for unconstrained human+agent co-inhabitation that the product thesis rests on.
