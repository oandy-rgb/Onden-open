# Frictionless capture / inbox / daily note

> 狀態：歷史紀錄（最後確認 2026-11-01）

## Onden today

Onden's "frictionless capture" concern is split across **three loosely-coupled mechanisms that never converge on a single triage surface**. Each has its own notion of what an inbox or a daily note is, and they do not see each other's output.

**1. Capture (`QuickCapture.tsx`).** A mobile-first FAB (PenLine icon, bottom-right) plus a global keyboard path. `useKeyboardShortcuts.ts` binds `Cmd/Ctrl+Shift+N`, but rather than lifting state it dispatches a `window` `CustomEvent` (`"onden-open-quick-capture"`); `QuickCapture` mounts a listener that flips its local `open` flag and focuses the textarea after a 50 ms timeout. An optional Web Speech mic toggle (runtime feature-check via `SpeechRecognition` / `webkitSpeechRecognition`) appends interim results live against a `baselineRef` snapshot and commits on `isFinal`. `save()` is an **append-to-daily**: it finds today's daily note in the in-memory `nodes` prop by exact title/slug match against the local-time ISO date (`YYYY-MM-DD`); if missing it `POST /api/nodes {title: dateStr, markdown:"# dateStr\n\n"}`, then `GET /api/nodes/:id` for the full body, then `PATCH /api/nodes/:id` with `${existing}\n\n## HH:MM\n${text}\n`. That is **up to three sequential round-trips** per capture. It then calls `onAfterCapture → refresh()`, selects the node, and `setMode("notes")`. Critically, capture **hard-blocks when offline** ("Offline — reconnect to save.", save disabled) — there is **no local/offline queue** despite the explicit mobile / bus-stop framing in the file's own header comment.

**2. Daily note (`useNodeCreation.openDailyNote`).** `Cmd/Ctrl+Shift+D`, the palette action "Open today's note" (⌘D), and the AppTopbar "Today" button (CalendarDays) all call `openDailyNote()`, which recomputes today's ISO date, searches `data.nodes` for a non-hidden node whose title or slug equals it, and either selects it + `setMode("notes")` or `POST`s a new one (same shape as capture). **`QuickCapture` re-implements this find-or-create logic independently** rather than sharing it — two code paths, two chances to drift. Daily notes are created with `hidden` defaulting to `false`, so they are normal graph nodes and **never enter the Inbox**.

**3. Inbox (`useOverviewMode.ts` + `OverviewSidebar.tsx`).** The Inbox is a **tab inside the notes sidebar** (`overviewPane: "nodes" | "inbox"`), not a top-level surface. `inboxNodes` is derived purely client-side as `data.nodes.filter(n => n.hidden && (n.class_tag_ids?.length ?? 0) === 0)` — i.e. **hidden + untyped** nodes. The tab badge counts `inboxNodes.length + visibleConflicts.length`, because the Inbox **also doubles as a sync-conflict feed** (subscribed via `useLiveEventLog`, dismissable, persisted in `sessionStorage`). Each row has a promote (↑) button (`POST /api/nodes/:id/promote`, emits `NODE_PROMOTED`, clears `hidden`) and a delete. **Nothing in the capture path writes `hidden=true`**, so captures and daily notes can never appear here; hidden nodes arrive only from explicit "Hide" actions and bookmark/RSS imports.

**And a fourth, ghost notion.** `homeBaseTemplate.ts` defines an "Inbox" view via the predicate `note.status == "inbox"` and a "Today" view via `file.eventsSince("2026-06-06")` — a query-based inbox/daily that is **disjoint from both** the sidebar Inbox (hidden+untyped) and the date-titled daily notes. There is no `note.status="inbox"` writer anywhere in the capture path, so this view is permanently empty.

**IA weaknesses.** (a) Three+ incompatible definitions of "inbox" and "daily" with no shared writer. (b) Capture appends raw text into a markdown blob — the captured thought is **not a first-class node**, so it cannot be promoted, typed, linked, or queried as a unit. (c) Capture is the one place that *should* tolerate flaky mobile connectivity, and it is the one place that hard-fails offline. (d) The Inbox conflates "things to triage" with "sync conflicts to dismiss" in a single badge. (e) The maturity loop has no on-ramp: a capture lands as a timestamped `## HH:MM` heading in a daily blob and has no path back out to becoming its own node.

## The gap

The field has converged on two patterns Onden has neither of:

1. **Capture produces a first-class, typed object.** Blinko (`NoteType`), Tana (`#supertag` at capture), and Capacities (pick-type-on-capture) all make the captured thing a *node with a type* the instant it lands. Onden's capture appends opaque markdown text into a daily blob — the thought is not a node, cannot be promoted, typed, linked, or queried, and so has **no on-ramp into the maturity loop**. The "promote" affordance that *does* exist (the Inbox ↑ button) operates on a class of nodes (hidden + untyped) that the capture path can never produce.

2. **"Today" / "journal" is identity, not a string.** This is the strongest cross-source convergence: **all four vendored block/outliner PKMs key the day note off an attribute or class, never the title** — AFFiNE a doc property (`journal`), Logseq the built-in class `:logseq.class/Journal`, SiYuan a per-day custom IAL attribute (`custom-dailynote-<date>`), Trilium a `#dateNote=<date>` label. All survive renames and avoid the find-or-create races that Onden invites by matching on `title === "YYYY-MM-DD"` in two independently-maintained code paths. (SiYuan goes further and makes find-or-create-and-append a single server endpoint, eliminating Onden's three client round-trips entirely.) Onden's date-titled daily note is the brittle string version, and its base-template `note.status=="inbox"` view has no writer at all.

Plus two Onden-specific holes the field treats as solved baselines: **offline capture** (Roam users reach for third-party apps *because* fast offline capture is expected; Onden hard-blocks it) and **a single inbox meaning** (Onden has four, one of which doubles as a sync-conflict dismissal feed).

## Recommendation for Onden

Ground every move in the thesis: **a node is the home; canvas/graph/table/inbox/timeline are lenses on a node's maturity; the flow is a loop (capture → diverge-on-board → converge-in-notes); a tag is a node carrying schema/policy.** Capture and inbox are not features to bolt on — they are the **entry point of the maturity loop** and a **lens on low-maturity nodes**.

**1. Make capture mint a first-class node, not append text.** A capture should create a `content_node` with its body as markdown — not a `## HH:MM` heading inside a daily blob. This is the single change that reconnects capture to the maturity loop: a minted node can be promoted, typed, linked, lensed, and queried. The daily note becomes a *lens that aggregates today's captured nodes* (via backlink/transclusion or an `eventsSince(today)` query — Onden already has the predicate in `homeBaseTemplate.ts`), not the storage. This kills the three-round-trip find-or-create-and-PATCH dance and its duplicated logic in `QuickCapture` vs `openDailyNote`.

**2. Collapse the four inbox notions into one: the Inbox is the low-maturity lens.** Per the thesis, inbox is not a peer mode and not a sidebar tab bolted onto notes — it is **the lens you apply to nodes that have not yet earned a type or a connection**. Define the inbox as *"nodes with no `class_tag_id` and no edges"* (maturity = untyped + unconnected), which is a clean generalization of today's `hidden + untyped` filter and unifies it with the dead `note.status=="inbox"` view. Freshly captured nodes land here **by definition** (they start untyped/unconnected), giving the maturity loop its missing on-ramp. **Move sync-conflict dismissal out of the Inbox** — conflicts are an actor-attribution concern of the event-sourced spine, not a triage pile; surface them in their own affordance so the Inbox badge means one thing.

**3. Borrow Tana/Capacities: let capture be born typed — optionally.** Keep the zero-friction default (capture → untyped node → lands in the inbox lens), but offer an inline "as #tag" affordance in the capture sheet. **Because a tag is a node carrying schema/policy**, choosing a type at capture *is* opening that node's schema lens and instantiating against it — the same mechanism as everywhere else, not a special-case capture feature. A typed capture skips the inbox (it has earned a type), exactly the Tana "no inbox" outcome, while an untyped capture flows through it. This is the thesis's "freedom-high but one unified mental model" in its sharpest form.

**4. Make "today" identity, not a title string.** Follow the unanimous vendored pattern (AFFiNE doc property, Logseq class, SiYuan custom attr, Trilium `#dateNote` label): mark the daily node with a `journal`/`day` attribute (or, more nodely, instantiate it against a `Daily` *class node* — tag = node = class). Find-or-create resolves against that attribute, not `title === dateStr`, so renaming the day node never breaks the lookup and the two code paths can finally share one resolver. The "Today" button and `eventsSince` view then key off the same identity. Borrow SiYuan's other lesson too: make find-or-create-and-append a **single spine command**, not the client's three round-trips.

**5. Add an offline capture queue.** Capture is the one surface where mobile connectivity is most likely to be flaky and most costly to lose. Mint the node locally and enqueue the create event; the event-sourced spine + outbox already model every mutation as a replayable, actor-attributed event, so a client-side capture queue is the natural client mirror of that — not a new subsystem. Stop hard-blocking offline; the bus-stop thought is exactly the use case the file's own comment promises and the code currently drops.

Net: capture becomes *"mint a node (optionally typed via a tag-node's schema lens), enqueue it offline-safe, and let the daily/inbox lenses aggregate it by maturity"* — one mental model, the maturity loop closed at its entry point, and every capture an actor-attributed event on the spine.
