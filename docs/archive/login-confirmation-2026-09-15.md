# 登入後 session 確認補驗（2026-09-15）

> 狀態：歷史紀錄（最後確認 2026-11-01）

案例：ACC-01。隔離測試庫 `onden_import_audit_test`、API 18788／Astro 5100，使用既有測試帳號 A。
不是正式部署或實體手機的 Tailscale 登入驗證。

## 現象及修改

進入測試環境時再次觀察到帳密請求 200 且設定 cookie，但畫面仍在登入表單；重載才能進入。
已安裝 auth client 的成功通知透過延遲 signal 觸發 session 讀取，但本次沒有證明停留的唯一原因
是瀏覽器節流、HMR 或套件缺陷，不能據此把真機登入問題全部歸因於它。

LoginGate 在 signIn／signUp 成功後明確等待既有 `useSession().refetch()`；工作區仍必須取得
驗證後的 session 才掛載，不另存登入旗標，也不自行寫入 session。錯誤密碼不做此後續步驟。
這是既有 auth client 的使用修正，沒有改變來源檢查、後端授權或帳號分區。
