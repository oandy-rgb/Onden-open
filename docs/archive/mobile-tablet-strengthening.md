# Onden Mobile + Tablet Strengthening Roadmap

## 1. Top success factors (cross-cutting lessons)

These recurred across all six themes and the ~80-app corpus:

- **Capture from outside the app.** The dominant pattern. Lock-screen / widget / share-sheet / Siri / floating-badge entry that lands a thought in one gesture without launching the full app. In-app QuickCapture cannot match it.
- **Zero-decision landing = daily/today note.** No folder/title/type gate before the cursor. Onden's day-node sink already wins here.
- **Never block on network, never silently overwrite.** Local-store-as-truth + invisible background reconcile is the #1 trust factor *and* the #1 churn driver. But the local copy must itself be durable (native SQLite / persisted storage), not evictable browser storage.
- **Fast cold start (~1-3s to cursor).** Loading the whole vault first kills "quick" — the exact sql.js full-DB-boot risk Onden carries.
- **Inline-rendered markdown-as-truth + above-keyboard thumb-zone toolbar + list auto-continuation.** The three "feels native" editor primitives. And inputs ≥16px so iOS doesn't zoom-on-focus.
- **Ink/handwriting must become searchable, editable, publishable content** — not a write-only blob. OCR-to-derived-text, lasso-select, and rendering ink on published sites.
- **Real tablet two-pane regime** (persistent sidebar + detail), not the phone drill, across the 768-1024px band — plus touch gestures (edge-swipe-back, swipe-row).

## 2. Where Onden is already strong (honest)

Onden is **architecturally ahead of almost the entire corpus on the hard correctness problems**, and it's real code: an in-Worker sql.js mirror with FTS5, a replay-safe outbox with client-minted idempotency keys + cross-tab Web-Lock single-flighting, two-cursor sync (event delta + fail-closed membership epoch), lossy-by-design SSE that re-handshakes on reconnect, day-node-as-default-sink (the zero-decision landing winners are praised for), and a best-in-class ink **engine** (rAF + getCoalescedEvents + wet/committed split + pen-preempts-palm). The capture *core* is lossless-by-construction — exactly what Bear/Logseq/Notesnook/Evernote users churn over not having. **The gaps are all at the edges**: capture reach, durability eviction, background drain, the editor polish layer, ink-after-the-stroke, and the missing tablet layout.

# Appendix: Per-theme syntheses

## Theme: Frictionless mobile capture — one-tap / always-available capture, quick entry, share-sheet, voice, widgets, getting thoughts in fast

**Onden gap:** Onden's in-app capture is genuinely best-in-class on the dimension competitors most often fail: durability. QuickCapture.tsx mints a real graph node through the single sendOrQueue write chokepoint (offline.ts) with a client-minted UUID idempotency key, mirrors locally, replays on reconnect, and surfaces a live pending-count. That is exactly the offline-safe, never-silently-overwrite property Bear/Logseq/Notesnook/Evernote users churn over not having. The day-node-as-default-sink also already matches the zero-decision landing pattern that Logseq/Reflect/Capacities win on. The shortfalls are at the EDGES of capture, not its core:\n\n1) Capture REACH is in-app-only. The single biggest recurring success factor — capture from OUTSIDE the app via OS-level surfaces — is mostly absent. There is a Web Share Target hand-off (?capture=1 → prefilled QuickCapture) per the index.astro / QuickCapture wiring, but there is no home-screen widget, no lock-screen / Control Center entry, no Siri Shortcut, no floating badge. On the Capacitor Android shell (android/) this is the gap that most separates Onden from Tana/Things/OneNote/Notesnook. Capture still requires launching the app, and the offline-first work flagged in MEMORY notes a real cold-start cost remains (sql.js full-DB load).\n\n2) Cold-start tax undercuts 'one-tap'. Per the offline baseline, the sql.js mirror loads the whole DB into memory in a Web Worker on boot, and the Capacitor shell still runs the browser sql.js path (no native SQLite plugin). This is the exact Obsidian/Tana failure (5–15s cold start kills 'quick' capture). Capture from a widget/share-target must reach the write queue via a LIGHTWEIGHT path that does NOT boot the full projection/mirror first.\n\n3) Voice is raw-transcript only. QuickCapture.tsx uses Web Speech API to text with interim buffering — good, but it is text-only with no Whisper-grade fallback and, critically, no voice-to-STRUCTURED-note (Tana/Mem bar). It also has no photo/camera/scan/audio-clip capture; the learning-loop baseline explicitly notes capture has no image/photo/audio attachment.\n\n4) The #tag leg of capture is online-only best-effort. captureSyntax.ts parses #tag/@date, but the learning-loop baseline states the #tag application is silently DROPPED offline (only the node create + due_date PUT are queued). So an offline capture with #tag loses its tag — a quiet correctness gap in the one flow that is otherwise lossless.\n\n5) iOS input-zoom-on-focus is unmitigated (mobile baseline): the QuickCapture textarea inherits the global ~14px input rule and the viewport meta has no programmatic restore, so iOS Safari zooms in on focus and stays zoomed — a literal friction tax on every capture on the user's own dogfood device.\n\n6) The central + and More sheet are static (mobile baseline): tap = open capture only; no long-press command/route surface (Things/Supernotes overload), and a learning-student who lives in Review/Today can't promote it to a primary slot.

**Recommendations:**

- **Add OS-level capture surfaces on the Capacitor shell: home-screen + lock-screen widget and a share-target/Quick-Add deep link that bypasses the full app boot** (L/high) — packages/frontend/android/ (Capacitor widget + intent), packages/frontend/src/pages/index.astro (capture-only mount path), packages/frontend/src/components/QuickCapture.tsx, packages/frontend/src/lib/data/offline.ts. This is the single highest-leverage gap — capture-from-outside-the-app is THE recurring success factor (Tana/Things/OneNote/Notesnook/Keep) and Onden has none beyond a web share target. A widget/deep-link (onden://capture or ?capture=1) that lands a draft in QuickCapture is the right shape; the hard part is it must reach the sendOrQueue queue WITHOUT first booting the sql.js mirror. Implement a minimal capture entry route in index.astro that mounts only QuickCapture + offline.ts (queue) and defers useAppData/localDbWorker hydration until after the write is queued.
- **Make the offline #tag leg lossless — queue tag membership through sendOrQueue instead of dropping it offline** (S/high) — packages/frontend/src/components/QuickCapture.tsx (tag-apply branch ~lines 200-261), packages/frontend/src/util/captureSyntax.ts, packages/frontend/src/lib/data/offline.ts. Onden's whole capture trust story is 'lossless by construction', but the learning-loop baseline reveals the #tag application is silently dropped when offline (only node create + due_date are queued). captureSyntax.ts already parses tags; route the resolve-path + membership PUT through the same sendOrQueue chokepoint with a client-minted idempotency key so the tag replays on reconnect. Small change, removes a quiet correctness hole in the flagship flow.
- **Kill iOS input-zoom-on-focus across capture + editor** (S/high) — packages/frontend/src/components/QuickCapture.css, packages/frontend/src/styles/global.css (input/textarea + .cm-scroller font-size at <=900px), packages/frontend/src/pages/index.astro (viewport meta). On the user's own dogfood phone, the QuickCapture textarea and .cm-scroller are below 16px so iOS Safari auto-zooms on focus and never restores (mobile baseline), taxing literally every capture. Cheapest robust fix: bump the editable font-size to 16px on coarse-pointer/mobile (textarea, .cm-content), or set the viewport meta to allow programmatic restore. Apple Notes/Bear/UpNote all avoid this. Pure CSS/meta change, felt on every single capture.
- **Make voice capture produce a structured note + add an outbox-async transcription/AI-reformat path** (L/medium) — packages/frontend/src/components/QuickCapture.tsx (audio capture + reformat action), packages/backend outbox effect (transcribe/reformat), packages/frontend/src/components/AskPanel.tsx (reuse RAG reformat). Web Speech voice-to-text is good but raw; the bar (Tana/Mem) is voice → clean, tagged, structured note. Fit to Onden's architecture: capture the raw audio blob instantly (content=hash-pointer), enqueue an outbox effect that runs Whisper-grade transcription + the existing ask/RAG reformat, and write the cleaned body back as a node-attribute event — exactly the server-side-OCR latency trade-off Evernote lives with, done on Onden's effects rail. Even without audio, add a one-tap 'reformat this capture' that pipes the draft through /api/ai/ask.
- **Add photo/camera/scan capture as a first-class modality in QuickCapture** (M/medium) — packages/frontend/src/components/QuickCapture.tsx, packages/frontend/src/components/OverviewEditor.tsx (reuse insertImageFile / pdf_url path), backend nodes.ts (blob/content-addressed store). Multi-modal capture (camera/scan) is a top recurring on-ramp (Keep/Evernote/OneNote) and the learning-loop baseline notes capture has no image/photo/audio attachment. OverviewEditor already has capture="environment" image insert and PDF-drop → pdf_url node minting; reuse that to let QuickCapture attach a photo/scan to the captured day-node child, queued offline via the blob path. Camera-first matches how phone capture actually happens.
- **Overload the central + into a tap-capture / long-press-command control and let primary nav slots be promotable** (M/medium) — packages/frontend/src/components/MobileNav.tsx (long-press handler + promotable slots), packages/frontend/src/components/MobileNav.css, packages/frontend/src/components/QuickCapture.tsx (per-capture destination). Things' Magic Plus and Supernotes' long-press command bar show one thumb-zone control should both capture AND route (to Today/Tomorrow/Inbox, or jump-by-search). Onden's raised oxblood + disc (MobileNav.tsx:108-116) is the natural anchor: keep tap = QuickCapture, add long-press → a small command sheet (capture to today / to a chosen tag / new task / search-jump). Also let the learning-student promote Review/Today into a primary slot instead of the hard-coded Notes/Tasks/+/Read/More (the baseline flags the 5 slots are hard-coded and More is unorderable).
- **Add a lightweight capture-only boot path so widget/share captures don't pay the sql.js full-DB cold-start** (M/high) — packages/frontend/src/pages/index.astro (?capture=1 fast path), packages/frontend/src/lib/useAppData.ts (defer hydration when capture-only), packages/frontend/src/lib/data/offline.ts, packages/frontend/src/components/QuickCapture.tsx. Cold start is the documented killer of 'quick' capture (Obsidian/Tana). The offline baseline confirms the Capacitor shell still runs browser sql.js loading the whole DB on boot. Recommendation #1 depends on this: a capture entry that mounts QuickCapture + offline.ts queue and writes to pending_writes BEFORE (or instead of) hydrating useAppData/localDbWorker, then lazily syncs. This is the structural enabler that makes one-tap capture actually feel instant on the heaviest-use target.
- **Add natural-language date + richer in-field micro-syntax parity to capture quick-entry** (S/low) — packages/frontend/src/util/captureSyntax.ts, packages/frontend/src/components/QuickCapture.tsx. Things' NL date parsing ('Wed 8pm', 'in four days') is a repeatedly-loved friction-killer vs date pickers. captureSyntax.ts already parses @today; extend it to phrase-based dates and surface a tiny inline confirmation chip, keeping the markdown-as-truth/in-field-not-modal discipline. Low effort, compounds the zero-menu structuring Onden already does.

## Theme: Mobile typing/editing surface — above-keyboard toolbars, markdown vs rich text, selection, one-handed formatting, list continuation

**Onden gap:** Onden's mobile editor is architecturally strong but has concrete, code-level gaps against the bar set by Bear/UpNote/Joplin/Notesnook. (1) iOS zoom-on-focus is UNMITIGATED and verified in code: the viewport meta is `width=device-width, initial-scale=1.0` (index.astro:10) with no programmatic restore, and inputs/textarea inherit `font: inherit` (global.css:72-74) while the CM scroller is ~14px — every editable surface is below the 16px iOS threshold, so Safari zooms on focus and stays zoomed, which also pushes the above-keyboard bar partly off-screen. (2) The above-keyboard toolbar (MarkdownEditor.tsx:1204-1214) is a HARDCODED 9-tool set (H1/H2/Bold/Italic/Code/bullet/number/task/quote + dismiss) — it is NOT customizable/reorderable, and is missing the actions users reach for most on mobile: undo/redo, link insertion, and indent/outdent. Link insertion exists in the desktop bubble flow but never made it into the mobile bar. There's also no visible scroll cue and no overflow affordance. (3) The bar's keyboard tracking via VisualViewport (MarkdownEditor.tsx:1084-1092) has NO fallback when `window.visualViewport` is null — `kbInset` stays 0 and the bar pins to `bottom:0`, sitting UNDER the keyboard on those contexts. (4) The editor is a PURE raw-markdown source view with zero CodeMirror Decoration/ViewPlugin/WidgetType extensions — you always see `**`, `#`, `[[ ]]`, `![]()`; formatting and inline images only appear in a separate non-editable Preview tab, a regression vs Bear/Joplin/Apple Notes inline rendering on the exact tablet read/annotate surface Onden wants to win. The genuinely-good parts (pointerdown+preventDefault focus retention, list auto-continuation in handleEnter, idempotent wrapAtSel toggles, thorough IME/composition guards) match best-in-class — the gaps are the polish layer on top.

**Recommendations:**

- **Kill iOS zoom-on-focus: raise editable font-size to 16px (or add accept-and-restore viewport handling)** (S/high) — packages/frontend/src/styles/global.css (add ≤900px rule setting .cm-scroller / .cm-content and QuickCapture textarea to font-size:16px); packages/frontend/src/components/MarkdownEditor.tsx editorTheme (line ~194-206) for the in-editor font size. Verified gap: inputs inherit `font: inherit` (global.css:72-74), the CM scroller is ~14px, and the viewport meta (index.astro:10) has no zoom restore — so iOS Safari auto-zooms on every editor/capture focus and stays zoomed, simultaneously shoving the above-keyboard toolbar off-screen. This is the most jarring 'feels broken' mobile bug and the cheapest to fix. Set the CM content and the QuickCapture textarea to 16px at the ≤900px breakpoint (Apple Notes/Bear/UpNote all sit at native input size); keep desktop density unchanged. This is a pure-CSS, markdown-as-truth-safe change with no data-model impact.
- **Add a VisualViewport-null fallback so the toolbar never hides under the keyboard** (S/medium) — packages/frontend/src/components/MarkdownEditor.tsx (the kbInset useEffect ~1083-1092 and the md-mobile-toolbar render ~1220-1250); global.css:1117-1130 toolbar positioning. MarkdownEditor.tsx:1084-1092 bails to kbInset=0 when window.visualViewport is null, pinning the bar to bottom:0 — under the software keyboard on any context lacking VV (some Android WebViews / Capacitor shell). Since Onden ships a Capacitor Android shell, this is a real target. Fallback path: when VV is absent, either keep the bar docked to the editor bottom inside a flex column (not viewport-fixed) or use a focus/resize heuristic, so the bar is always visible above the keyboard.
- **Add undo/redo, link, and indent/outdent to the above-keyboard bar; make it pin/hide-customizable** (M/high) — packages/frontend/src/components/MarkdownEditor.tsx (mobileTools array 1204-1214; wire startLink + history.undo/redo + indent helpers); a settings/local-mirror key for persisted tool order. The bar (MarkdownEditor.tsx:1204-1214) is a fixed 9-tool set missing exactly the actions mobile users reach for most — undo/redo (Notion users complain it's hidden at the far end on desktop, absent here), link insertion (already implemented in the desktop bubble via startLink ~1100+ but not surfaced on mobile), and indent/outdent (the Logseq mobile pain point was REMOVING these). ## Theme: Offline-first reliability, instant local feel, sync trust, no-data-loss, fast cold start, cross-device continuity

**Onden gap:** Onden is architecturally ahead of almost every app in the corpus on the HARD correctness problems, and the baseline confirms this is real code, not aspiration: a real in-Worker sql.js mirror with FTS5 (localDbWorker.ts), a replay-safe outbox with client-minted idempotency keys + cross-tab Web Lock single-flighting (offline.ts, useAppData.ts:176-212), two-cursor sync (event delta + fail-closed membership epoch, useAppData.ts:236-401), lossy-by-design SSE that re-handshakes on reconnect (useLiveEvents.ts), and forced durability flushes on queue-add/delete/unload (localDb.ts:170-207).
