## 工程健康

- 前端：`tsc`、eslint、建置都通過。單元測試 1977 個中 1 個失敗，270 個檔案中 2 個失敗：
  - `nodeEventHistoryInk.test.tsx`：mock 缺 `fallbackData`，整個檔案無法載入（既有）。
  - `MarkdownEditorSlashInsert.test.tsx`：不穩定，3 次失敗 2 次（F7 帶入）。
- 乾淨 clone 上 `tsc` 會有 13 個錯誤，要先執行 `astro sync`；preflight 沒有先做這一步。
- 後端：`tsc`、eslint、單元測試都通過，1075 個測試通過、6 個略過。157 個需要 Postgres 的整合測試沒跑。
- `npm audit --omit=dev`：
  - 前端 3 critical、23 high；後端 3 critical、10 high。
  - 優先處理：`better-auth`（帳號接管）、`pdfjs-dist`（惡意 PDF 執行 JS）、`simple-git`（critical，大版本升級）、`@modelcontextprotocol/sdk`、`astro`（critical XSS，大版本升級）。
- 熱點：
  - `localDbWorker.ts` 有 26 個 `as any`、27 個 any 停用註解。
  - 37 個 exhaustive-deps 停用。
  - 62 個單行 `.catch(() => null)`，其中 `useAppData.ts` 的啟動流程是靜默吞掉錯誤。
  - 超過 1000 行的檔案：MarkdownEditor、BuilderApp、`routes/tags.ts`、`routes/nodes.ts`、OverviewSidebar。

## 共同根因

- **非同步結果沒有核對目標**（#2、#3、#4、#5、#35、#38）：操作開始時沒記下「為哪篇筆記／哪塊白板」，完成時寫進當下的狀態。
  比較兩種方向：讓媒體檢視依筆記 id 重新掛載（簡單，涵蓋 #3、#5），或讓這些操作自己帶目標並在完成時核對（涵蓋 #2、#4、#35）。兩者不互斥。
- **旁路少做主路徑的檢查**（#9–#17）：同一件事有新舊兩條路或 HTTP／agent 兩個入口，只有一邊做了授權或後續效果。
- **「已提交」的定義不一致**（#6、#7）：巢狀交易內呼叫的 hook 以為已提交。
- **連線狀態只有單向開關**（#19、#20）：失敗會關，恢復只靠少數事件。
