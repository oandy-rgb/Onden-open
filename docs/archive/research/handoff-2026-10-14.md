## 三、部署要注意

- 部署步驟與每次的紀錄在 [vps-tailscale-http-2026-09-28.md](../vps-tailscale-http-2026-09-28.md)。
- **build 之前先 `docker tag onden-vps-<svc>:latest onden-vps-<svc>:before-<sha>`**，並確認執行中的映像就是 latest。曾經有一次回退映像做不出來。
- **建置快取持續變大**（約 30 GB，每次部署多約 2.7 GB），磁碟在 84% 上下。不要直接跑 `docker builder prune`：之前清快取時，執行中映像的內容被刪掉了（containerd 映像庫）。安全的做法：
  1. build 之前才清；
  2. 清完對 latest 和每個 before-* 映像跑 `docker create`，確認都還能建立容器；
  3. 壞掉的就從 `/srv/onden/releases/<sha>` 重建。
- #76 帶 migration 101（outbox 重試期限），後端啟動時會自動套用。
- CI 停用中，以本機測試為準。
- **背景 worker 檢查已進 build**（2026-10-18）：`npm run build`／`build:published` 最後跑 `scripts/check-worker-bundle.mjs`，`localDbWorker-*.js` 混進 pdfjs、micromark、`createElement`、katex、hljs、React 等，或超過體積上限（93,200 B），映像 build 就失敗；build 紀錄裡看 `worker ...: 大小, budget ...` 那行即可，不必再手動 grep worker。切換後仍要用瀏覽器確認 `new Worker(...)` 正常。
