> 狀態：歷史紀錄（最後確認 2026-11-01）

使用者要求：「完整查看全部程式／看看切分乾不乾淨／沒有整合的部份數量」。分兩輪：

- **第 1 輪**：空間改版前的 main `1474dc5`，約 8.5 萬行非測試程式，5 個只讀檢查並行，關鍵結論逐項抽查。
- **第 2 輪**：空間改版（PR #10）合併後，`fix/audit-bugs` `7c1fef8`（main `4800a4f` ＋ PR #11），重算權限相關的數字並檢查空間程式碼本身，3 個只讀檢查並行，最嚴重的幾項逐一抽查屬實。

## 摘要

- **接縫是乾淨的**：模組與核心之間沒有越界 import，outbox 與主要的寫入工具（writers）都有統一入口。
  問題在接縫之上：建立筆記、套用標籤、設定屬性等領域操作，以及 slug、wikilink、hashtag 等文字規則，在很多地方各自重寫，已經開始不一致。
  根本原因是缺少共用的後端服務（建立筆記／套標籤／設屬性）和前後端共用的純邏輯套件。
- **第 1 輪找到的 8 個錯誤已全部修正並上線**（PR #11，見下方）。
- **空間改版後，筆記本身的讀寫都集中在一處**（`services/spaceScope.ts`，經 `assertAuthority`／`mutate`）。仍有三類地方繞過它：
  1. 從筆記衍生出來的資料：事件紀錄、附件、slug 唯一性、對外的備份與發布；
  2. 全域標籤：任何成員都能寫；
  3. 舊的角色檢查：`{role}` 的意思已經變了。
- **正式站目前只有一位成員，以上都不會讓別人看到東西**；但**邀請第二個人之前必須先完成第四節的清單**。

## 三、空間改版後的發現（三份檢查合併、去重，依嚴重度）

**高**
- **事件紀錄給每個成員看所有「不是筆記」的事件**（`routes/events.ts`、bootstrap）。內容包括：
  - AI 代理每次呼叫工具的**完整參數**（`AGENT_TOOL_CALLED`／`FAILED` 的 `tx_meta.args`，含它寫進筆記的內文和搜尋字）；
  - 空間名稱、成員與角色；
  - 權杖範圍；
  - 白板標題、連結兩端的 id。
  （抽查屬實）
- **全域標籤任何成員都能改**（`spaceScope.ts` 的 class_tag 條款）。透過一般的筆記路由可以改名、刪除；刪除會連帶把標籤底下、別人空間裡的筆記丟進垃圾桶。
  設計上標籤定義只限擁有者。（抽查屬實）
- **`{role: editor}` 的意思變成「在任何空間是編輯者」**（`spine/authority.ts`），每個人都是自己個人空間的管理者，所以一律通過。
  例如**只能檢視的成員可以用 `DELETE /api/collections/:id` 刪掉保留的 workspace-config 標籤**：之後整個工作區的 `/api/bootstrap` 與 `/api/site` 會回 500，只有管理者能救回。
  同樣的寬鬆也發生在指標（新增／刪除）和標籤檢視。（抽查屬實）
- **既有筆記全在「共用」，而新成員會自動加入「共用」**（093／094）。第二個人一加入就看得到擁有者全部的舊筆記（日記、舊每日筆記）。這不在已記錄的上線條件裡。

**中**
- **附件**：
  - 匯出 markdown zip 時，附件直接從磁碟複製，沒有檢查附件權限；
  - 附件能不能讀，由「最早建立的引用筆記」決定，而不是由附件掛上去的時間決定。
  所以曾經看得到某個附件的人，把網址貼進自己的舊筆記，就能一直讀下去。
- **slug 全工作區唯一**：
  - `createNode` 的 dry-run 會回傳算出來的 slug，等於可以安靜地探測某個標題的筆記是否存在。
  - slug 也是備份檔名、去重和網址的鍵，改成「每個空間各自唯一」會牽動很多地方（已知缺口 2 的範圍比記錄的大）。
- **移動預覽**（`GET /api/spaces/move-preview`）沒有檢查呼叫者是否屬於目標空間，會回傳那個空間的名稱和全部成員。
- **「擁有者」實作成「任何管理者」**：被升為管理者的人可以把自己加進任何共用空間（包括 094 建的「受限」）、改發布與外部 AI 開關。設計是單一擁有者。
- **AI 代理把筆記建在標籤底下時會跑到「共用」**，不受權杖的寫入範圍限制。
- **`_published`、`_status` 可以經由筆記內文設定**（`key:: value`）。代理可以藉此不經審核就讓筆記上公開網站。這在改版前就存在。
- **標籤合併**會在合併者無權進入的空間裡建立子筆記（範本展開）並寫入欄位預設值。
- **移出空間或關閉「可發布」後不會重新部署** GitHub Pages 與靜態匯出：要等下一次手動發布才會撤下。
- **備份檢查在找不到筆記時放行**：筆記改名或刪除後，排隊中的備份仍會推出去。
- **權杖範圍**：
  - 介面無法表達「沒有任何空間」：清空就送 `null`，意思是全部；重新設定時還會把 094 刻意設成「無空間」的權杖放寬。
  - 任何空間管理者都能把代理加進自己的空間，從而擴大權杖可及範圍。
- **代理的權杖讀不到任何個人空間**，但新筆記預設放在個人空間。上線後新筆記代理看不到，要移到「共用」才行；設定頁的說明也寫錯。
- **刪除成員後，他的個人空間沒有擁有者、也沒有成員**，裡面的筆記從任何 API 都碰不到。
- **Site Config 節點**（含分享權杖、學習者存取權杖）留在「共用」，每個成員都能從 bootstrap 讀到。設計中的「系統空間」沒有做。
- **兩套角色不一致**：工作區的檢視者能在「只有我」建筆記、匯入圖片，卻不能上傳圖片、不能用 AI 轉換。

**低**
- 圖譜位置包含其他空間筆記的 id。
- 同步的刪除清單沒有依讀者過濾。
- 公開網站列出私人 `#page` 筆記的 id。
- 掛在全域標籤上的任務會被單日檢視顯示給所有人，錯過一次後由排程器重建到「共用」。
- 還原舊的改父層操作時，若父層已在別的空間，回傳的是一般性的 500，而不是設計的 409。
- 介面會提供伺服器一定會拒絕的「移到…」。
- 唯讀模式只蓋住標題與內文：標籤、屬性、任務、刪除、發布開關仍可按，按了才收到 403。
- `parent_in_other_space` 等錯誤沒有中文。

## 四、邀請第二個人之前必須完成（依優先順序）

1. **事件紀錄**：
   - 只給讀得到的筆記的事件，非筆記事件依空間或角色過濾，或替事件加上 `space_id`；
   - 不再把工具參數存進 `tx_meta`；
   - 一併處理 cascade preview 與同步的刪除清單。
2. **標籤定義只限擁有者**：
   - 一般筆記路由對標籤的改名、刪除、搬移、屬性；
   - 標籤檢視、集合、指標；
   - 把 `{role}` 改回明確的意思（工作區角色，或「這個空間的角色」）；
   - 刪除保留的 workspace-config 標籤要擋下。
3. **決定舊筆記哪些留在「共用」、新成員是否自動加入「共用」**。
4. **擁有者是單一一個人**，不是任何管理者；權杖範圍的介面要能表達「無空間」，並實作 min(發行者角色, 授權)。
5. **完成已知缺口 1～5**。slug 依空間唯一要和備份檔名、去重、網址一起規劃。
6. **附件**：匯出也要檢查；附件要有真正的所屬空間（或依掛上的時間決定）。
7. **移動預覽**要檢查目標空間的成員資格。
8. **對外的動作要「找不到就不做」**：備份檢查失敗時擋下；移出空間或關閉發布時重新部署。
9. **代理**：
   - 禁止把筆記建在標籤底下的退路；
   - 筆記內文不能設定 `_` 開頭的屬性；
   - 決定代理能否讀個人空間。
10. **成員離開**時處理他的個人空間；把 Site Config 移出「共用」。
11. **一致性**：兩套角色、唯讀模式、介面不提供伺服器會拒絕的操作。
