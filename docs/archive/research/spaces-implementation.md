## 後續待辦（實作中發現）

- 前端還沒有「檢視者唯讀」的介面：0.2 之後檢視者的寫入會被伺服器拒絕（顯示寫入失敗），1b 做空間角色時一併讓介面唯讀。
- 標籤合併仍以直接 `INSERT INTO node_tags` 改掛成員；標籤已不帶權限，不影響可見範圍。
- 集合項目（`POST /api/collections/:id/items`）不能指定空間，一律進建立者的個人空間；要公開或給別人看得先移動。
- 改成員的工作區角色（`PATCH /api/actors/:id`）不再改他在預設空間的角色（094 起觸發器只在新增成員時同步）；要降權請在「設定 › 空間」改。
- 個人空間預設不能公開：分享面板在筆記所在空間不允許公開時會說明（2026-10-13 e2e 發現開關沒有作用也沒有提示）。
- MCP `queryView` 對不存在的 view 回 500（main 上就是如此，非本分支造成）。

migration 094 的轉換（每項都以 RAISE NOTICE 記錄）：
- 帶存取規則（policy）的標籤所標的筆記，連同子樹，移到只有擁有者的共享空間「受限」；若父筆記沒有這種標籤，就脫離父筆記。
- 有標籤範圍（`scoped_tag_ids`）的成員離開預設空間，只剩個人空間，等擁有者把他加進空間。
- 有標籤範圍（`allowed_tag_ids`）的權杖改為不能到任何空間（`'{}'`），等重新設定範圍。
- 標籤定義裡的 policy 刪除；`actors.scoped_tag_ids`、`agent_tokens.allowed_tag_ids` 欄位與 `node_tags` 的 epoch trigger 刪除。
  **因此回滾只能還原資料庫備份。**

### 與草案的差異

- **媒體沒有另建 `media` 表**：沿用第 0 階段「最早引用它的筆記決定」，該筆記的讀取由空間決定，效果相同、少一張要同步的表。
- **第 2 階段改為一次性 migration**：草案要擁有者逐項決定；改為 fail-closed 自動轉換（全部受限筆記放進同一個只有擁有者的「受限」空間），擁有者事後改名或加人。
- **權杖**：`read_space_ids`／`write_space_ids` 為 NULL 時＝代理人所屬的全部空間；再與 external_ai 開關取交集。權杖管理介面可勾選空間（讀寫同一組；不勾＝代理人所屬的全部空間）。
  **注意：把代理人加進一個新空間，會讓它所有範圍為 NULL 的權杖都能到那個空間。**
- **改標籤定義**：設計表原寫「成員皆可」，實作與「功能」標籤頁一致是擁有者；設計表已改。
- **沒有開關、不能切回**：使用者決定直接轉換；切回只能還原資料庫備份。
