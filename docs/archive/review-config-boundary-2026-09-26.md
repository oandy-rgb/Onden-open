# 複習設定的整數邊界（2026-09-26）

> 狀態：歷史紀錄（最後確認 2026-11-01）

起點提交 `3b54929`。範圍是 `#review` TagPack 行為讀取後的每日新卡數與
最長排程天數；未修改 FSRS 權重、既有卡片狀態或評分 API 格式。
修正與測試與本文件同一提交，可由此檔的 Git 歷史追溯。

重現：`behaviour.review` 若給 `new_per_day: 1.9`、
`maximum_interval_days: 2.9`，原 `reviewBehaviourFromSchema` 會回傳
1.9 張／2.9 天。單元測試在修正前以「預期 1、得到 1.9」失敗。
每日張數不是可分割單位；FSRS 原本給整數天的間隔，也不該被小數上限截成
不足整日。現在先沿用原有合法範圍與非法值預設，再將這兩個量向下取整；
例如 1.9 張、2.9 天分別成為 1 張、2 天。回想目標 `request_retention`
仍是原本允許的 0.7～0.97 小數。`review: null`、陣列及字串原本已安全
回到預設，本輪測試確認而未為它們加另一套處理。

驗證使用固定隔離 `onden_test`，只啟動 PostgreSQL 並暫時綁定
`127.0.0.1:55439`，不連正式 DB。單元／FSRS **18 項通過**；
真 PostgreSQL 複習模組 **13 項通過**，其中在資料庫儲存小數設定後，
`/stats` 回傳整數每日上限，`/grade` 的 Good 首次排程為整數 2 天；
原有新卡預算、評分事件、撤回與讀取政策案例亦通過。測畢已停止該測試容器。
輸出與 SHA-256 校驗保存在 gitignored
`.acceptance/2026-09-26/review-config/`；兩端 TypeScript、前端 build
及兩端 lint 的本批 preflight 也通過。

本批只關閉這個數值邊界缺陷。TagPack 從正式 UI／API 匯入後的完整
評分循環、修改設定後既有卡片的再次評分、不同角色與 scope、重載和
手機呈現尚未完成，故 REV-06 仍為「待盤」。
