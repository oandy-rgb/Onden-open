# 登入檢查失聯與恢復驗證

> 狀態：歷史紀錄（最後確認 2026-11-01）

日期：2026-09-13。基線：`0e93619` 加目前未提交的審核變更。案例：ACC-01、ACC-08、NOTE-03；GAP-20 部分修復。

本批修好 API 暫時失聯被顯示成登入表單，以及恢復後缺少明確重試入口的問題。沒有實作完全離線登入，
也沒有完成 A 帳號登出後 B 帳號的本機隔離驗收。

## 原因與設計

原本 `LoginGate` 只看 `isPending` 與 `session`，忽略驗證錯誤；沒有 session 的 503、網路錯誤
和成功確認未登入，都會進入同一張密碼表單。回歸測試先得到 9 項失敗、3 項通過，重現此差異。

比較兩種做法：

| 方案 | 呼叫與隱藏知識 | 相容成本 |
| --- | --- | --- |
| 保存上次身分，失聯時解鎖快取 | 入口需要判斷身分有效期、儲存與佇列的帳號擁有者、登出及離線政策 | 現有本機格式未分帳號，必須先建立歸屬／遷移契約，不能只新增登入旗標 |
| 依驗證結果顯示可重試入口 | 入口使用 `useSession()` 與 `refetch()`；cookie、刷新、跨分頁通知仍由 auth client 擁有 | 不改後端授權、不改本機格式；失聯時尚不能從冷啟動進入編輯器 |

選第二種。本次減少的是畫面對登入協定與失敗種類的錯誤推論，沒有建立新的通用錯誤服務。
所有使用 `LoginGate` 的入口共用同一行為，呼叫者仍只提供 `children`；桌面與手機不另寫判斷。

已檢查本機安裝的 better-auth 實作：`session-atom.mjs` 在一般失敗時保留先前 session，401 清除資料，
成功的空回應代表未登入。重試沿用它的請求和儲存狀態。登入邊界沒有把暫時錯誤當成保存成功，
也沒有清除 SQLite、佇列或復原副本。簽入、註冊、社群登入及後端權限語意不變。

## 已實作

- 沒有 session 且檢查失敗：顯示「暫時無法確認登入狀態」及「重試連線」，不顯示密碼表單或私人工作區。
- 初次檢查中：顯示具 `status` 語意的載入提示。
- 手動重試：保留提示畫面及原 URL，顯示進度、阻止重複送出；意外的 promise rejection 仍可再次重試。
- 已有 session 的暫時檢查失敗：保持已掛載的編輯器；401 或成功的空 session 阻止私人內容。
- 重試按鈕使用 `aria-disabled` 搭配事件守衛，讓鍵盤焦點在請求期間及失敗後保留；原生 disabled 在實測中會失焦。
- 提示沿用主題與繁中翻譯，按鈕至少 44px；登入外框使用最小視窗高度與兩側留白，窄屏卡片限制在可用寬度。

## 實際瀏覽器驗證

Codex 內建瀏覽器，Astro 前端 `127.0.0.1:5100`、真實 API `127.0.0.1:18788`，
隔離資料庫 `onden_import_audit_test`，沿用測試帳號的既有 cookie。沒有使用正式資料庫。
專用 harness 只控制 `/api/auth/get-session`，其他 API 仍走正式應用程式碼。

目標是既有筆記 `1c4e2cc0-7211-4f4e-87ee-8a272b979f23`「0913 待同步正文載入實測」，
保留 `view=notes`、`node`、`lens=editor` 深層連結。本批沒有修改筆記內容。

| 情境 | 實際結果 |
| --- | --- |
| 真實 session、桌面初次進入 | 原筆記正文及既有兩筆拒絕修改復原副本可見 |
| 桌面 1440×900，session 回 503 後重載 | 顯示重試提示；沒有登入表單、沒有私人筆記；失敗後仍可重試 |
| 1.2 秒延遲、鍵盤 Enter 重試 | 顯示「正在確認連線…」；焦點留在按鈕，失敗後仍留在同一按鈕 |
| 手機 390×844、窄屏 320×720 | 文字正常換行，document scrollWidth 分別為 390／320，無橫向溢出；按鈕 44px 高；320px 卡片為 288px 寬 |
| 手機恢復真實 session 回應，再按重試 | 不重新輸入密碼，直接回到原筆記、完整原正文及兩筆復原副本，URL 不變 |
| 手機 harness 回 401 | 顯示登入表單，沒有私人工作區；這是明確拒絕的故障注入，不是實際等待 cookie 過期 |
| 桌面 harness 回 200 null | 正常顯示登入表單；不誤判為連線錯誤 |
| 停止整個 API 程序、桌面重載及重試 | 前端仍由 Astro 提供，API proxy 連線被拒絕；顯示可重試提示，不是密碼表單 |
| 重啟 API、桌面按重試 | 原 cookie 再度通過真實驗證，回到同一筆記與正文，既有復原副本仍可見 |

完成後已關閉本次分頁、還原 viewport 並停止本次啟動的前後端程序。上述是 viewport 與故障注入測試，
不是真機、瀏覽器飛航模式或整個前端伺服器不可達的驗證。已掛載編輯器保留新輸入由元件測試驗證，
未將其說成真實跨分頁登出或撤權實測。

## 剩餘邊界

- 完全離線冷啟動仍停在驗證提示；GAP-20 的離線進入筆記部分尚未解決。
- `indexedDbStorage.ts` 使用共用名稱，SQLite／待送請求沒有 account owner 契約，
  `writeRecovery.ts` 使用同 origin 的 `onden.lostWrites`。這是程式審查發現的歸屬缺口，尚未重現 A→B 資料洩漏。
- ACC-06 必須另驗：登出成功／失敗、A 的 pending 與草稿、登入 B、跨分頁與重播歸屬；
  決定隔離方式後才能規畫持久化離線身分。不能用「快取存在」自動放行。
- 原生平台的登入旁路、換伺服器、OAuth callback 與離線 app shell 不在本次驗證範圍。
