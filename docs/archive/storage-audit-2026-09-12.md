案例：DATA-04、DATA-05；補充 DATA-06／07、ACC-05、UX-01。基線為 `719ce80` 加既有歷史／復原未提交變更。
本批修改前確認工作樹，保留先前工作；不修改後端、發布設定或日常使用者資料庫。

## 範圍與完成結果

本批完成「本機快照的下載、驗證、提交與失敗保留」及「複製成功後才切換位置」的局部修正。
設定頁不再組合選目錄、匯出、寫檔和啟用的順序；`localBackup.ts` 擁有位置切換，
`localDbWorker.ts` 擁有資料庫替換與落盤。仍未完成兩列的全部平台／權限情境，因此清單保留「部分」。

## 發現、證據與修正

| 發現 | 證據類型 | 本批結果 |
| --- | --- | --- |
| `importDatabase` 替換記憶體資料庫後只排程保存，UI 隨即 reload | 真實 sql.js、worker RPC 與可延遲儲存的測試；舊實作失敗 | 候選先驗證、完成 IndexedDB 交易後才安裝；儲存失敗保留舊記憶體與舊磁碟副本 |
| 一般 SQLite 檔會被 migration 補成空 Onden 庫；其他 workspace 也可直接替換 | 真實 sql.js 測試；舊實作接受，修正後拒絕 | migration 前檢查基本表、完整性及單一工作區；已有本機 workspace 時要求 ID 相同 |
| 替換期間其他 RPC／背景保存可交錯，讀到尚未落盤的候選 | 舊實作的延遲提交測試失敗 | RPC 與背景快照共用 worker 內的執行順序；晚來的操作在替換完成後執行，失敗不堵住後續操作 |
| 切資料夾先修改設定，再忽略匯出／寫檔失敗 | 靜態追蹤 `StorageLocationWidget`；新增領域與 adapter 故障測試，未完成原生資料夾瀏覽器實測 | 選目錄→拒絕已有資料庫→複製→提交目錄設定→啟用；失敗保留原位置並顯示錯誤，不 reload |
| 目錄 IDB `put` 成功被當成整個交易成功 | adapter 測試在 request 成功後 abort | 等 `transaction.oncomplete`，abort／error 拒絕 |
| 每次啟動都匯入資料夾，可能蓋掉更新的本機快照或剛還原的資料 | 靜態資料流＋啟動入口回歸；未聲稱以真實資料夾重現 | 已有本機工作區時保留瀏覽器快照；僅無本機工作區時從資料夾初始化 |
| 下載失敗沒有回饋；匯入失敗後同檔不易再次選取 | 元件測試；瀏覽器實際壞檔拒絕後按鈕恢復 | 共用錯誤呈現語意，錯誤留在表單；重設檔案輸入，處理中阻止重複操作 |
| 文案宣稱完整工作區還原、OPFS，超過實際能力 | 程式儲存路徑、下載檔 SQLite 檢查、桌／手畫面 | 說明為本機快照，明列不包含的資料；移除本批畫面的 OPFS 名稱；備份說明／錯誤文字 14px |

最初五個 worker 案例在舊實作 **5／5 失敗**，修正後通過。這不是五個獨立瀏覽器 bug 的計數；
其中包含同一保存契約的不同失敗情境。資料夾項目的程式／adapter 證據不能當成已完成作業系統選擇器驗證。

## 設計取捨與可觀察契約

| 選擇 | 呼叫範例／需要理解的知識 | 決定 |
| --- | --- | --- |
| 每個 UI 在 `importDatabase` 後再 flush | `await importDatabase(bytes); await flushLocalDbSync()`；每個入口要知道原結果只在記憶體，且失敗前已替換 | 不採用；也保護不了啟動時的資料夾入口 |
| 替換操作自身提供落盤保證 | `await importDatabase(bytes)`；成功代表候選已通過驗證及本機交易提交 | 採用；候選失敗不安裝，背景保存與 RPC 在同一個 worker 順序內 |
| 每個設定頁自行排列切換步驟 | UI 理解目錄 handle、檔案、IDB、偏好提交順序 | 不採用 |
| 依操作意圖封裝位置切換 | `await chooseLocalBackupFolder()` 回 changed／取消的 boolean；`await switchToBrowserStorage()` | 採用；先保留完整副本再啟用，不刪原資料夾 |
| 每次啟動以資料夾覆蓋，或猜測哪個時間較新 | 兩份可各自失敗的快照，加上版本／時鐘判斷 | 不採用；目前沒有可靠的雙向檔案同步協定 |
| 瀏覽器內已確認保存的快照優先 | 有本機工作區就使用它；資料夾作初始化來源／副本，其他替換走明確的還原操作 | 採用；不把背景延遲副本當成最新資料 |

- `importDatabase` 不更換伺服器資料，不復原完整事件歷史，也不代表伺服器接受新變更。
- SQLite 檔包含本機已有的快取與待同步佇列；媒體檔、完整伺服器歷史、瀏覽器偏好、尚未保存的編輯不在其中。
  「匯出全部」仍是另一個伺服器 Markdown ZIP 操作，不能混為同一份備份。
- 有本機 workspace 時拒絕不同 workspace 的匯入。這是防誤用檢查，**不是授權機制**；
  尚無本機 workspace 時沒有可信 ID 可比較，不能因此宣稱跨帳號隔離已驗收。
- 已有 `onden.sqlite3` 的目錄拒絕覆蓋。複製完成但保存目錄設定失敗時，目標可能留有一份副本，
  原位置仍在使用；重試可另選空目錄，不自動刪除目標檔案。
- 既有 `fs-access` 切另一目錄，以 handle 交易作啟用點；從瀏覽器切目錄則以最後的偏好寫入啟用。
  切回瀏覽器先確認本機快照落盤，原目錄與檔案保留。舊的 `opfs` 偏好值僅保留格式相容，實作仍是 IndexedDB。

桌面採 1365×900 與工具恢復後的 1280×720；沒有驗證所有主題或全站無障礙。

工具限制：下載事件等待逾時，但實際檔案存在且已用 SQLite 驗證。
