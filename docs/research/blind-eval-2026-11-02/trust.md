# 盲測評價：懷疑論者（資料安全與可靠度）

> 狀態：歷史紀錄（最後確認 2026-11-02）

- 評測方式：第一次見到這個 App。`npm ci` → `npm run build:browser`，用靜態伺服器提供 `packages/frontend/dist-browser`，以 Playwright + Chromium（雲端預裝版）操作。**WebKit／Firefox 沒試**（雲端下不到）。
- 桌面 1280×800；手機 390×844 為 **Chromium 模擬（isMobile + touch），不是真機**。
- 這是「瀏覽器內建後端」的試用版（資料在瀏覽器裡）。**完整版（有伺服器）沒試**，下列結論只適用於這個版本。
- 介面語言是英文（無頭瀏覽器的語系），範例筆記是中文；少數訊息（第二分頁的阻擋訊息）是中文。這件事本身列在問題清單。
- 每個情境都有「做了什麼／預期／實際／有沒有掉資料」。自動化的「寫完再重新整理」是比人更快的極端情境，我標出等待秒數，請自行判斷真人會不會撞到。
- 我一開始的幾個測試判定成了「通過」，後來發現是我比對到了恢復面板裡的文字（假陽性），已全部用「側欄列表＋筆記本體」重做；本文只列重做後的結果。

## 1. 第一印象（前 5 分鐘）

打開約 12 秒（含載入內建資料庫）後出現三欄畫面：左側筆記清單與標籤、中間是空白的今天日記「2026-11-01」、右側一個「Functions／Tags／Relations」面板。左下有一顆常駐的「Trial: your notes are kept only in this browser」膠囊，中間偏下浮著一張「What's new」更新卡（內容是 List／Table 切換、強調條等開發者視角的更新說明，對第一次開的人毫無意義，而且蓋在畫面上要手動關）。

懂不懂：看得出是筆記＋任務＋圖譜的工具；膠囊與「資料存在哪裡」範例筆記很誠實地說「資料只在這個瀏覽器、清除網站資料會消失、請下載備份」。這一點做得比多數產品好。

第一件事（寫一則筆記）做得到，但要先理解「＋」不是直接新增，而是開一個「Create」對話框（Note／Handwriting／Upload a file／Bookmark／Canvas＋位置），再按一次 Create 才建立；對話框裡還列了「Upload a file」，而試用版明明不支援上傳。

## 4. 問題清單（依嚴重度；下文以 P編號 引用）

### 擋路

1. **還原備份在這個版本做不到，卻擺著按鈕並說「Could not reach the server」。** 重現：設定 › Data and backup › Restore from a backup › Choose file…（選任何有效備份 zip）。預期：不能還原就別顯示，或直接說「試用版無法還原，請到完整版」。截圖：`trust-24-restore-preview.png`。程式位置：`packages/backend/src/browser/unavailable.ts`（`/api/backup/restore` 被拒），前端 `packages/frontend/src/lib/data/backupRestore.ts` 的錯誤被統一翻成「無法連線至伺服器」（`lib/data/writeErrors.ts:90`）。一個只存在瀏覽器、唯一的逃生路線是備份的版本，備份卻拿不回來，信任等於打折。
2. **新建／剛輸入完就離開，整則新筆記會消失（0.3 秒～2 秒內重新整理）。** 重現：＋→Create→填標題內文→立刻重新整理。預期：筆記在；或離開前有確認。實際見 S1。截圖：`trust-13-A-after.png`。我沒看到離開前確認（`beforeunload`）。
3. **關分頁、手機重新整理這類「沒給時間」的離開，會無聲掉資料。** 重現：S3、S4。預期：至少像桌面一樣有恢復面板。截圖：`trust-31-m-reload-immediate.png`。
4. **恢復面板的「Try again」沒救回文字，還多建一則空白「Untitled」。** 重現：S5。預期：文字回到新筆記或原筆記；或按鈕名稱改成實際行為。截圖：`trust-16-try-again.png`。

### 煩人

5. **資料被清掉後無聲重置成範例。** 重現：S12／S16。預期：偵測到「上次有資料、這次是空的」時提示「看起來這個瀏覽器的資料被清掉了」，並指向還原。目前使用者會以為自己做了什麼。截圖：`trust-21-after-clear-all.png`、`trust-28-after-fs-clear.png`。
6. **「資料存在哪」說法互相矛盾。** 設定 › Data and backup 的「Where your notes are kept」寫「On the server. … Clearing site data removes only that copy; your notes stay on the server.」，但試用版說「沒有伺服器，清掉網站資料筆記就沒了」（我驗證過是後者）。程式：`packages/frontend/src/settings/registry.tsx:134-136`（用 `ctx.online` 決定文案，試用版也被當成 online）。截圖：`trust-23-data-backup.png`。這是最危險的一句話：它讓人誤以為清除資料很安全。
7. **帳號與同步字樣在沒有帳號的試用版裡出現。** 帳號對話框寫「Connected」、有「Sign out」「Spaces and members」，設定首頁寫「Saving：Synced」（桌面，用紅點表示）。實際上沒有伺服器、沒有同步。預期：顯示「只存在這個瀏覽器」。截圖：`trust-19-account-clean.png`、`trust-22-settings.png`。「Synced」會讓人以為有雲端副本。
8. **「What's new」更新卡蓋在對話框與畫面上。** 重現：第一次開啟，或清資料後再開；開 Settings／帳號對話框時卡片疊在對話框上並攔截點擊（我的腳本因此點不到「Settings」）。預期：先關卡片再開對話框，或不在對話框上方。內容是開發者視角的 UI 微調，對新使用者沒意義。截圖：`trust-03-trial-pill.png`、`trust-08-usermenu.png`。手機也蓋住 1/3 畫面與試用膠囊（`trust-30-m-first.png`）。程式：`packages/frontend/src/components/DeviceNotices.tsx`（`ui-layer device-notices`）。
9. **下載備份後沒有任何回饋。** 按下 Download a backup，對話框原樣沒變。預期：「已下載 onden-backup-….zip」＋提醒存放位置。截圖：`trust-20-after-backup.png`。
10. **沒有看到「上次備份時間」或備份提醒。** 只靠一顆常駐膠囊。對只靠瀏覽器儲存的 App，應該有「已 N 天沒備份」。本次沒找到這個資訊（可能有、我沒找到）。
11. **「Create」對話框列出「Upload a file」，但試用版不支援上傳。** 重現：點＋。預期：灰掉並註明。截圖：`trust-12-create-click.png`。
12. **自動建立的今天日記不斷累積空白筆記。** 隔天開啟就多一則空的 `2026-11-02`；進入備份後變成空的 `2026-11-02.md`。預期：空日記不寫入，或寫入備份時略過。
13. **刪除沒有確認，且 Undo 提示只出現數秒。** 重現：側欄筆記 hover → Delete。預期：可復原的前提是使用者知道去哪找；我沒找到垃圾桶入口，只在備份的 `.trash/` 裡看到。截圖：`trust-17-delete-click.png`。
14. **備份／匯出的 Markdown 夾帶系統標籤頁。** `tag-page.md`、`tag-workspace-config.md`、`tag-admin-only.md` 等 11 個空白檔，對 Obsidian 使用者是雜訊。

### 小瑕疵

15. **手機快速擷取面板被試用膠囊蓋住部分按鈕，且顯示「Ctrl+Enter／esc」鍵盤提示。** 重現：手機尺寸點中央＋（Capture）。截圖：`trust-33-m-capture.png`。
16. **冷啟動約 10–12 秒才看得到畫面。** 載入內建資料庫期間沒有明確進度（本次以固定等待 12 秒，沒量到精確首畫面時間）。
17. **介面語言混用。** 英文 UI 裡，第二分頁阻擋訊息是中文，範例筆記也是中文。
18. **「資料存在哪裡」範例筆記寫「設定 › 下載備份」，實際路徑是設定 › Data and backup › Download，或膠囊對話框。** 截圖：`trust-02-where-data.png`。
19. **「＋」的首次行為不直覺**：要按兩次（＋→Create），連按時容易以為沒反應（我自己的腳本就誤判過）。截圖：`trust-09-after-plus.png`。

沒試：離線、長文（數萬字）效能、圖片／附件、匯入 Obsidian 資料夾（見 S14）、標籤與復原歷史的細節、完整版（有伺服器）、多人。

## 5. 截長補短

### 比它們好、應該保留

- **誠實的資料位置說明**：左下膠囊＋「資料存在哪裡」範例筆記＋對話框，直接講「清除網站資料會消失」。Notion／Google Keep 都不會告訴你雲端以外的事；Obsidian 也沒有這種貼心。保留，並把設定頁的矛盾說法（P6）修掉。
- **第二分頁保護**：直接擋掉並說明原因（S17）。Obsidian Sync／Logseq 都曾因兩處同時開而衝突；這裡用「不載入」換安全，值得保留。
- **完整備份的 README 與內容**：zip 是人看得懂的 Markdown 資料夾，附 `.trash/`，README 清楚列出「包含／不包含」，匯出 Markdown 也附「未匯出的內容」說明。這比 Notion 匯出（HTML 一堆 uuid）、Apple 備忘錄（幾乎不能匯出）好很多。
- **恢復面板的概念**：寫入失敗時把文字攤出來給你複製，而不是假裝成功。Google Docs 離線失敗也只會小字提示。保留概念，把功能補完（P4）。
- **刪除附 Undo toast**，簡單直接，與 Gmail 的「復原」同類。

### 它們做得好、這個 App 該學

- **Obsidian／Bear：檔案就是真相、離開不丟字。** 學「不論何時關頁，輸入都已落地」。做法：輸入時以 `visibilitychange`／`pagehide` 同步寫入（或每次輸入都先寫本機佇列再批次入庫，把防抖視窗縮到近 0），並在桌面與手機都套同一條。這是 P2、P3 的根治。
- **Apple 備忘錄／Google Keep：沒有「儲存」的概念，但有「最近刪除」的明確入口。** 學：在側欄放一個看得見的「垃圾桶（保留 30 天）」，目前只在備份裡看得到被刪的筆記。
- **Standard Notes／Obsidian Sync：顯示「上次備份／上次同步時間」並提醒。** 學：試用版設定頁與膠囊旁顯示「上次備份：N 天前」，超過 7 天輕提醒，用在 P9、P10。
- **Notion／Apple Notes 的新增：一鍵新增空白頁。** 學：「＋」直接建立筆記，進階種類（手寫、白板、書籤）放長按或選單，減少第一次的卡住（P19）。
- **Tana／Logseq 的「資料夾／檔案可選存位置」**：本專案已有「Keep a copy in a folder…」，但試用版的說明被誤導文案蓋過；學 Obsidian 把「我的資料在這個資料夾」放在首次啟動畫面，並讓使用者在第一天就選。
- **Excalidraw／Figma 的資料清除偵測**：「看起來資料被清掉了」顯示一次性橫幅並引導還原（P5）。

## 6. 前 5 個最該先修的
