# 改寫過時與新舊混雜的文件：給雲端工作的指示

> 狀態：歷史紀錄（寫於 2026-11-17）。一次性的工作指示；規則本身在 [docs-freshness.md](../agents/docs-freshness.md)。

擁有者 2026-11-17：「改寫」。上一輪整理（PR #1813）把「現行卻沒有 `> 涵蓋：`」的文件從 125 份減到 45 份；
剩下的多半是內容已經不對，或新舊決定疊在同一份裡。這一輪把它們改對。你的份是任務訊息裡列的那幾份，其他文件不要動。

## 每一份怎麼做

1. **整份讀完，逐段對照程式。** 一句話說某個檔案、函式、畫面、資料表、行為，就去查它現在是不是那樣（`ls`、`grep`、讀程式）。
   不要從標題或檔名猜。上一輪每份文件的一句診斷在 PR #1813 的說明裡，可以當起點，但它只是線索，不是結論。
2. **把文件分成兩部分：**
   - **現在的規則／現況**：只留今天成立、而且之後的人要照著做或要知道的內容。句子改成現在式，過時的句子照程式改正。
     檔頭寫 `> 狀態：現行`，下一行寫 `> 涵蓋：<glob>, …`——寫這份文件真正描述的程式（幾個檔或一個資料夾，不要半個套件），
     每個 glob 都要對得到檔案。之後有人改到這些程式，守門會要求他回頭看這份文件。
   - **歷史**：當時的討論、被取代的做法、分批進度、已經移除的功能。**原文搬過去，不改寫、不刪減。**
     放在同一個資料夾的新檔 `<原檔名>-history.md`，檔頭 `> 狀態：歷史紀錄（寫於 <原文最早的日期>；現行規則見 [<原檔名>.md](<原檔名>.md)）`；
     原檔在檔頭下面加一行連到它。原檔很短、歷史只有幾行時，不必另開檔：留在原檔最後一節，節標題以日期開頭
     （`### 2026-10-31　…`，這種小節不查程式碼引用）。
3. **路徑不變。** 原檔名繼續是「現行」的那一份（別的文件、`AGENTS.md` 的索引都連到它）。搬走內容後，
   用 `grep -rn "<原檔名>" --include=*.md .` 找出連到被搬走段落（`#錨點`）的連結並改掉。
4. **整份都是過去的事**（功能已移除、設計已被另一份取代）：不要硬擠出「現行」內容。狀態改 `已被取代`（同一行連到取代它的文件）
   或 `歷史紀錄`，並在說明裡寫依據。
5. **不要動的情況，列在 PR 說明給擁有者：**
   - 改正一句話等於替擁有者做決定（文件說的是一個**決定**，程式做的是另一回事，而你分不出是程式錯還是決定改了）；
   - 你查不出現況；
   - 分散式同步那條線的內容（來源標記、快照、修改包、節點同步、工作階段、錨點）：標 `note-cf`，不改文字。
6. 不刪文件，不改產品程式，不動圖片。不要為了讓檢查器通過而把內容搬去歷史——搬過去的必須真的是過去的事。

## 清單與檢查

- 文件有了涵蓋、或不再是現行，就從 `scripts/docs-freshness-baseline.json` 的 `noCoverage` 刪掉那一項（只准減少）。
- 交件前貼出最後幾行：`node scripts/check-md-links.mjs`、`node scripts/check-md-links.mjs --report`、`npm run -s ratchet:check`。
