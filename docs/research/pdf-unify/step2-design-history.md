## 兩種鏡頭設計的比較（AGENTS.md：新公共介面至少比較兩種）

| | A. 原生捲動（PDF 現在的做法） | B. 自己的鏡頭（手寫頁現在的做法） |
| --- | --- | --- |
| 捲動與縮放 | 瀏覽器捲動容器；縮放＝改頁面的 CSS 寬度；兩指縮放靠 `touchSplit` 的預覽 | `InkPageCamera`：自己算捲動與縮放，畫布只有視窗大小，自己甩動 |
| 筆跡畫布 | 每頁一個引擎，兩張頁面大小的畫布（只在畫面附近的頁面存在） | 單一引擎，視窗大小的分塊畫布，筆跡用 transform 畫進去 |
| 多頁 | 天然（頁面本來就是由上往下排） | 要把多頁排進同一個 sizer，且一個引擎只有一份文件，要一頁一個引擎並把指標分給正確的那個 |
| 很長的一頁 | 畫布大小跟頁面，過大就降解析度（`cappedPixelRatio`） | 畫布不隨頁長，任何縮放都清楚 |
| 手指長按選文字 | 要把繪圖面做成「只收筆」才能與文字層共存 | 沒有文字層，不遇到 |

**建議：A 為唯一鏡頭**，因為多頁與 PDF 文字層都已在這條路上；代價是現有「往下無限長」的手寫頁要改成固定高度的頁＋
「＋ 新增一頁」（已存的高頁保留自己的高度，不切開筆跡），高頁在高倍放大時解析度會比現在低。
B 的優點（任何長度都清楚）要靠「每頁也只畫視窗範圍」才能保住，那等於把 B 的分塊畫布搬進每一頁，複雜度回來，所以不建議。
**這是需要擁有者確認的取捨**（見最後一節）。

## 頁面本子的契約（提案）

```ts
// src/pagebook/PageBook.tsx — 只認得頁面信封，不認得 PDF
<PageBook
  pages={pageList}                     // InkPages 由上往下；每頁 { key, background, size, doc }
  background={renderBackground}        // (page) => 空白 | PDF 第 n 頁（pdf.js，只畫畫面附近）| 之後的 slide
  layers={{ text, images }}            // 各頁的文字框、圖片層（由外殼傳 controller）
  tool={tool} penDraws stylusOnly      // 裝置設定由外殼傳入，本資料夾不讀偏好
  onPagesChange={(pages, opts) => …}   // 存檔由外殼負責
  onAddPage={() => …}                  // 「＋ 新增一頁」
  t={translate}                        // 翻譯函式由外殼傳入
/>
```

- 鏡頭：一個 `camera.ts`（捲動、兩指縮放、甩動 `glide`、放大鈕、全螢幕、每篇記住放大狀態），合併現在的 `scrollCamera`／`pageCamera`／`pageZoom`。
- 背景是頁面的屬性（`InkBackground`：blank／pdf／slide）。資料結構已經預留 `slide`，這次不畫。
- PDF 專用（選文字、劃重點）是背景為 pdf 的頁面才有的「插槽」，工具列上只在有 PDF 頁時才出現，其他頁不作用。
- 外殼：`PdfNodeView`（讀檔網址、highlights、→ 卡片）與 `InkNodeView`（單頁手寫）變成薄殼，各自接存檔。

## 為什麼畫面這次沒動

1. **多頁手寫筆記的儲存沒有決定。** 手寫筆記的 `ink_data` 就是它唯一一頁的文件（`noteDoc`／`notePages`），整條存檔、離線差異、同步都以「一份文件」為單位；
   第 2 步又規定「存法不改」。要有第二頁，就得決定 `ink_data` 變成 `InkPages` 信封（讀舊格式照 `units` 優先），這會動到寫入、差異（#1055 正在整併）與舊版 App 讀取。
2. **PDF 文字層與繪圖面共存要重做。**（c 已做：`PageBook` 的 `tool` 可為 `null`，選取工具下不掛繪圖面；PDF 頁由外殼的 `PdfPageBackground` 畫。） 筆在「選取」工具下直接畫、手指長按選文字，需要繪圖面只收筆、文字層收手指；
   而 PDF 現在由 pdf.js 的 `PDFViewer` 排版，頁面本子要自己排版，就得自己畫 PDF 頁（畫布＋文字層＋連結），這是整個畫面的重寫。
3. **無法驗證。** 這個環境沒有平板與 S Pen，畫面合一的主要風險（手感、長按選字、解析度、版面）只能在裝置上看；
   6 條進行中的分支正在改同一批檔案（見下），大改會與它們衝突，應該等它們合併後再做。
