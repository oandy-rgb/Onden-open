## 這一步的決定

- **沒有新增 migration。** 「明天再說」與「先不複習」是這個人對這張卡的標記，記在他自己那一列 `review_states.state` 的 JSON 裡（`hold` 欄位），
  所以從沒評過分的新卡也能帶標記；評分會寫一份新的排程，標記就自然結束。每天上限記在帳號偏好（`actor_prefs`）。
- **每天上限是「每人一個數字」。** 存成帳號偏好 `reviewsPerDay`（`actor_prefs`，沒有新增 migration、也不以標籤為鍵），到期卡與新卡合起來只算一次；沒有來源標籤的卡也照算。超過的到期卡只在讀的時候隱藏、順延到隔天，不改任何排程。佇列、統計、狀況頁與牌組數字用同一個算法（先排到期卡，新卡補剩下的名額）。
- **「今天」「逾期」「未來七天」以工作區的日期分界。** 佇列以「到期的那一刻」提供卡片（沿用原本行為），所以狀況頁的「今天」會包含今天稍晚才到期、還沒進佇列的卡。
- **評分按鈕的間隔是後端算的。** `previewIntervals` 用評分路由同一個 `schedule` 函式，前端只顯示。
- **「改這一段」不是新編輯器。** 重用筆記裡「嵌入段落」的編輯面板（`EmbedEditSheet`），存檔走 `drafts.saveBody`（一般的筆記存檔：排隊、離線、三方合併、錯誤分類都在裡面）。
- **「先不複習」可在兩處恢復：** 狀況頁的「已停用」清單，以及筆記自己的複習（功能分頁 › 複習）：打開時才讀一次 `GET /api/review/:noteId/stopped`，列出這則筆記（含段落與子筆記）裡停用的卡片，每張有「重新開始複習」。
