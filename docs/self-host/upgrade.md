# 升級與回退

> 狀態：現行（最後確認 2026-11-21）
> 涵蓋：scripts/upgrade.sh, scripts/rollback.sh, scripts/backup.sh, scripts/restore.sh

這份說明給自己架設 Onden 的人。你只需要會在終端機下指令。

## 基本觀念

- 升級＝換成新版本的程式，重啟後新版會**自動更新資料庫**。這個更新只能往前，不能自己退回去。
- 所以升級腳本會在動手**之前**先備份一次；萬一升級後出問題，可以用這份備份退回去。
- 退回去會把資料還原成「升級前」的樣子：**升級之後寫的筆記、修改、上傳都會消失**。腳本會要你輸入 `yes` 才動手。

## 升級

```sh
scripts/upgrade.sh v1.2.0     # 換成你要的版本名稱
```

腳本會依序做：

1. 看目前版本（`.env` 裡的 `ONDEN_VERSION`）和目標版本。
2. **立刻備份**資料庫與上傳檔案。備份失敗就停在這裡，什麼都沒改。
3. 下載新版本映像（下載失敗會還原版本設定，服務不受影響）。
4. 重新啟動，等後端回應（最多 3 分鐘）。
5. 印出結果。失敗時會直接告訴你怎麼退回。

升級前建議先看這個版本的 release notes：有「需注意」的項目（例如會刪除資料的更新）要先讀。

## 退回

```sh
scripts/rollback.sh
```

它會列出可用的升級前備份（新→舊），你選一份（只有一份就直接用），然後顯示提醒並問你：

> 確定要回退嗎？輸入 yes 繼續

輸入 `yes` 才會繼續，其他任何輸入都取消、什麼都不動。之後腳本會：

1. 先另存一份「回退前」的現況備份（讓你反悔時還找得回升級後寫的資料）；
2. 停止服務；
3. 下載升級前的版本（`.env` 先不動）；
4. 在還原前一刻把 `.env` 的版本改回升級前的版本，然後還原資料庫（並換一個新的節點編號，見下面「備份放在哪裡」最後一點）。
   **還原完成之前，不論失敗、被拒絕，或你按了 Ctrl-C，資料庫都完全沒動**：腳本會把版本改回來、重新啟動服務，告訴你原因；
5. 還原上傳檔案，啟動，等後端回應。上傳檔案沒有還原成功時，服務會停著、腳本印出要再跑的那一行指令：**不要再跑一次回退**（那會再還原一次資料庫），照那一行做完再 `docker compose up -d`。
   中斷時腳本若問不到資料庫是否已經還原，它不會猜：`.env` 與服務都不動，並印出怎麼確認、確認後怎麼做。

還原會把被換下來的資料庫改名留著（`onden_before_restore_<時間>`），確認一切正常後可以刪掉它省空間（腳本會印出指令）。這些複本不會被自動刪，每次還原開始時會列出還在的與大小。

### 如果你只換回舊版本、沒有還原資料

舊版本的後端發現資料庫比自己新，會**拒絕啟動**，紀錄裡寫：
「資料庫比這個版本新……請升級回去，或用 scripts/restore.sh 還原升級前的備份」。
這是保護：舊程式不會去寫它看不懂的新資料。照提示做：重新升級到新版本，或執行 `scripts/rollback.sh`。

## 備份在哪裡

- 預設在專案資料夾的 `backups/`（可用 `.env` 的 `ONDEN_BACKUP_DIR` 改位置）。
- 每個備份是一組檔案，檔名帶 UTC 時間：
  - `onden-<時間>.sql.gz`：資料庫
  - `onden-content-<時間>.tar.gz`：上傳的圖片與檔案
  - `onden-<時間>.note.txt`：只有「升級前備份」才有，寫著從哪個版本升到哪個版本；回退就是看這個檔
- 排程備份（`backup` 服務）每 24 小時做一次，保留最新 14 份；升級前備份用同一個資料夾，
  超過保留數量後也會被清掉，所以升級後確認一切正常，若想長期保存請另外複製出去。
- 自己手動備份：`scripts/backup.sh`；手動還原：`scripts/restore.sh backups/onden-<時間>.sql.gz --yes`（先 `docker compose stop backend`）。
  腳本先把整份備份檢查過，載入到一個新的資料庫，全部成功才換上去；原本的資料庫改名留著當安全複本（需要大約一份資料庫大小的空閒空間）。
  失敗或中途中斷，現有資料完全不動。還原完會多印一行「the restored database is a new node」：
  還原回來的資料庫換了一個新的節點編號，之後的修改不會和備份之後原本那台寫過的修改撞號；備份裡已有的資料一筆都不改。
  較舊版本做的備份也一樣換號（腳本會先補上換號需要的函式）。只有 2026-11-12 到 11-16 之間的版本（migration 190–205）做的備份換不了號：
  腳本預設拒絕、資料庫不動，請改用更新一點的備份；真的只剩那一份時，加 `--keep-node-id` 照樣還原（腳本會說明後果：之後和其他裝置同步前，它們要重新加入）。

## 把備份複製到別台機器

備份目前只在同一顆硬碟上：硬碟壞掉或主機不見，備份也跟著沒了。定期複製一份到別處：

```sh
# 在你的另一台電腦上執行（把 user@host 和路徑換成你的）
rsync -av user@your-server:/path/to/onden/backups/ ~/onden-backups/
```

沒有 rsync 也可以用 `scp -r user@your-server:/path/to/onden/backups ~/onden-backups`。
複製後在那台機器上用 `gzip -t onden-<時間>.sql.gz` 檢查檔案沒壞。備份**不含** `.env`（密碼與密鑰），請另外妥善保管。

## 常見問題

- **升級停在「備份失敗」**：多半是磁碟滿了或資料庫沒在跑。先 `docker compose ps` 看服務，`df -h` 看空間。
- **升級後網站打不開**：看腳本最後印出的後端紀錄；不確定就 `scripts/rollback.sh`。
- **版本名稱**：就是 release 的名稱（例如 `v1.2.0`）。打錯時下載會失敗，版本設定會還原。
- 腳本只改 `.env` 裡的 `ONDEN_VERSION` 一行；compose 用它當映像標籤。
