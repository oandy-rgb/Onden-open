# 版面規則檢查（layout-audit）

用程式量元素位置，檢查通用的版面規則；**不存基準截圖**（截圖比對之後再說）。對象是瀏覽器版（`npm run build:browser` 產生的
`packages/frontend/dist-browser`，由 `e2e/browser-app/serve.mjs` 起靜態伺服器），因為雲端沒有 Postgres／Docker；
瀏覽器版的後端跑在頁面的 Worker 裡，畫面與正式版是同一套。背景與結果見 [docs/research/layout-audit-2026-11-02.md](../../../../docs/research/layout-audit-2026-11-02.md)。

```sh
npm run build:browser                      # 根目錄
cd packages/frontend
npm run layout:audit                       # 全部寬度 × 全部畫面 × 全部規則，約 10 分鐘
npm run layout:audit -- --widths 1280,pixel5 --screens note-long,daily --rules R1,R4   # 只跑一部分
npm run layout:audit -- --shots /tmp/shots # 違規的裁切截圖（紅框），每條規則每個畫面最多 3 張
npm run layout:audit -- --update-baseline  # 把目前的結果寫進 baseline.json（只在審核過、確定要記下時用）
npm run layout:audit:selftest              # 規則自己的測試（假頁面，不用建置）
```

結束碼：0 通過；1 有基準外的新違規，或審核本身出問題（畫面打不開、規則丟例外、頁面有腳本錯誤）。
基準裡已經修好的違規只提示（請從 `baseline.json` 刪掉那筆），不讓檢查失敗；**基準只准變少**。

## 檔案

| 檔案 | 責任 |
| --- | --- |
| `run.mjs` | 進入點：每個寬度開一個新的瀏覽器環境（自己的資料庫），逐畫面跑規則，與基準比對 |
| `env.mjs` | 寬度清單、開 app、等「已保存」、載入頁內輔助 |
| `seed.mjs` | 固定資料（固定 id 與字串；長內文、標籤、子筆記、長標題、任務） |
| `screens.mjs` | 畫面清單；`go(h)` 把 app 帶到該畫面，這個寬度沒有就丟 `Skip` |
| `inpage.mjs` | 在頁面裡跑的共用輔助：什麼算「可見」「可點」、元素怎麼命名、目前看哪一層（對話框／選單／整頁） |
| `rules/rN-*.mjs` | 一條規則一個檔，輸出 `{ selector, text, detail, box }` |
| `selftest.mjs` | 每條規則一個該報的壞例子與一個不該報的好例子 |
| `baseline.json` | 已知違規：規則、畫面、寬度、元素、原因 |
| `reasons.mjs` | 新違規寫進基準時預設的原因 |

## 規則

每筆輸出：哪個畫面、哪個寬度、哪個元素（可讀的選擇器＋文字）、量到的數字。嚴重度 1＝使用者看得到的壞掉、2＝不好點／會跳動、3＝差 1–2px。

| 規則 | 定義 | 誤報處理 |
| --- | --- | --- |
| R1 可點的東西被蓋住（1） | 每個可見的 button／a／role=button 等，取中心與四角內縮 2px 的點做 `elementFromPoint`，回傳的必須是它自己、子孫或它的 label | 圓角按鈕的角落可以點到父層：只有「中心被蓋」或「至少兩個點被同一個非祖先元素蓋」才報；圓形／膠囊形改測內縮 30% 的點；折行的行內連結只看第一行 |
| R2 可點的東西互相重疊（2） | 兩個互不包含的可點元素，可見外框重疊面積 > 0（兩邊都 > 0.5px，避免小數誤差） | label 與它的 input、輸入框內的清除鈕、完全透明的元素不算 |
| R3 文字被截斷（1） | overflow 是 hidden／clip，內容比框大超過 1px，且有文字 | 刻意的 `text-overflow: ellipsis`、`line-clamp`、可捲（auto／scroll）、尺寸為 0（收合）、CodeMirror 與白板畫布（react-flow）不算 |
| R4 捲動容器最後一項到不了／子項被壓縮（1） | 每個可捲的容器與 `.ui-menu--sheet`、對話框、選單：捲到底後最後一個子項要完整在框內；子項的內容比自己的框高（被 flex 壓縮）也報 | 絕對／固定定位的子項不算最後一項；子項自己可捲不算 |
| R5 滑鼠移過去版面位移（2） | 桌面寬度（1280、1100、1920）對最多 30 個可點元素 hover，比較前後所有可見元素的外框，移動或改大小 > 0.5px 就報 | 只報最外層位移的元素（子孫跟著動不重複報）；hover 時才出現的元素原本不在畫面上，不算；變色不改外框，不算 |
| R6 橫向捲軸（1） | `document` 的 scrollWidth 大於視窗寬度 | 被祖先裁掉的元素不算（它們不增加捲動寬度） |
| R7 手機點擊目標小於 44×44（2） | 只在手機：沿元素中心的橫線與直線用 `elementFromPoint` 掃描，量實際可點的長度（`::after` 擴大的範圍也算） | 編輯器與 Markdown 內文裡的行內連結、有 label 的 checkbox／radio（label 才是目標）不算 |
| R8 同層項目沒有對齊（3） | role=tree／list／listbox／menu 與 ul／ol：同一層級（`aria-level` 或 DOM 深度）項目的文字起點 x 與多數相差 > 1px；role=grid：同一欄的格子左緣、同一列的格子上緣相差 > 1px | 少於 3 個項目、或「不一致的」超過一半（沒有「多數」）不報；編輯器與內文裡的清單不算 |
| R9 手機點過之後殘留 hover 色（2） | 只在手機：點列表項、等 450ms、再點空白處；兩個時間點的背景色都要和點之前一樣 | 用 `aria-selected`／`aria-current`／`.active` 等判斷「真的被選取」不算；點下去就離開畫面（元素不在了）略過；名稱含刪除／移除／登出／新增等的按鈕不點（審核不能改動資料） |
| R10 打開的清單與頁面文字疊在一起（1） | 每個可見的 listbox（連同包著它的 `.ui-popover`）與筆記標題、灰字那一行、內文第一行比外框；重疊處最上面的必須是浮層、且浮層底色不透明 | 浮層不透明地蓋住文字不算（只有直接畫在頁面裡、或透明的浮層才報）；清單與那段文字是祖孫關係不算 |

規則的好壞靠 `selftest.mjs`：每條規則至少有一個重現業主回報過那類問題的壞例子（箭頭被直條蓋住、⋯ 面板最後一項被壓縮、hover 時標題下一行換行把內文推下去、
手機 hover 色殘留……）與一個正常例子。調規則時先在 selftest 加案例。

## 已知的盲點

- 只看「點得到」與「量得到」的盒子：用邊框、陰影、偽元素（`::before`）畫出來、不吃點擊的裝飾若蓋住一個可點元素，R1 看不到
  （#1179 的「選取直條蓋住展開箭頭」就是這種：在修正前的版本上 R1 沒有報；R4 與 R5 在修正前的版本上抓得到 #1178 與 #1182，見報告）。
- 內容的對錯、顏色對比、字級、視覺好不好看不在範圍；只量位置。
- 只有 Chromium（桌面與 Pixel 5 模擬）；WebKit 與真機沒跑。

## 畫面與寬度

- 畫面見 `screens.mjs`；每個寬度各開一個全新的資料庫，放同一份固定資料。畫面是「打開網址／點幾下」到達的，對話框與選單開著，規則只看最上層那一個。
- 寬度：桌面 1280×800、1440×900、1920×1080，窄桌面 1100×800（資訊欄預設收起），平板 900×1200（這個寬度 app 用手機版面），手機 Pixel 5（觸控、DPR 2.75），1440 深色（`colorScheme: dark`）。
- 時區固定 UTC、`reducedMotion: reduce`。app 的時間來自 Worker 的系統時鐘，無法從外面凍結；日期相關畫面的內容會隨執行日變，所以基準的比對鍵只用「規則｜畫面｜寬度｜元素選擇器」，不含文字。

## 為了讓結果穩定，測試掛鉤與刻意排除

- 沒有改任何產品程式。
- 注入一段 CSS 隱藏瀏覽器版自己的「試用版」小標籤（正式版沒有它，它會「蓋住」側欄底部的標籤列）與浮動的「這次更新」卡片層（只有比建置更早建立的帳號才看得到它）。
  只有畫面 `whats-new-card` 把它顯示出來量：它是固定在畫面底部的浮層，R1（可點的東西被蓋住）就是量它蓋住了什麼。
  新帳號本來就看不到卡片，所以那個畫面要用「未來的建置」才有東西可看：
  `ONDEN_BUILT_AT_MS=4102444800000 npm run build:browser`（根目錄；2100 年），再 `npm run layout:audit -- --screens whats-new-card`。
  一般的建置跑這個畫面會顯示「略過」，不是失敗。
- 這個檢查只看瀏覽器版的 Chromium；WebKit 的版面沒有跑。

## 基準

`baseline.json` 的每一筆：`rule`、`screen`、`viewport`、`element`（選擇器，不含文字）、`reason`。同一個選擇器在同一畫面出現多次只記一筆。
新違規一律先修；真的要記下（例如已知、排進批次）才用 `--update-baseline`，並補上 `reason`。CI 目前只在擁有者指定時才跑，沒有加進自動流程。
